3. 가입 플로우

구글 가입
FO-LGN-01 로그인 메인 → 구글 동의 화면 → FO-LGN-04 약관 + 이름 → FO-LGN-06 완료

이메일 가입
FO-LGN-01 → FO-LGN-02 이메일 입력 → FO-LGN-02-1 인증 코드 → FO-LGN-02-2 비밀번호 설정 → FO-LGN-04 → FO-LGN-06

이메일 중복
구글 동의 후 → FO-LGN-05 본인확인 모달 → 기존 계정에 구글 연결

인앱 브라우저
FO-LGN-01에서 구글 버튼 → FO-LGN-01-e2 외부 브라우저 유도 → 외부 브라우저에서 재진입

구글이 반환한 이메일은 검증된 것으로 신뢰하므로 인증 코드 단계를 거치지 않습니다. 이메일을 직접 입력한 경로에서만 코드 확인이 붙습니다.

4. 구글 관련 확정 규칙

항목내용
이메일 확보로그인 정보만 요청하는 동안에는 필수로 걸립니다. 캘린더 같은 권한을 하나라도 추가하면 항목별 동의 화면이 떠서 이용자가 이메일만 뺄 수 있게 됩니다
이름이용자가 구글 계정에 이름을 넣지 않았으면 빈 값으로 옵니다. 빈 칸으로 두고 직접 입력받습니다
공개 상태콘솔에서 공개로 바꾸지 않으면 등록한 테스트 계정만 로그인됩니다. 오픈 전 필수
인앱 브라우저구글이 차단합니다. 외부 브라우저 유도 모달이 반드시 필요합니다
연결 해제 감지구글은 해제 알림이 오지 않습니다. 토큰 갱신 실패 시점에 인지해서 처리합니다

5. 선행 과제

구분내용
법무개인정보처리방침에 소셜 로그인 내용이 전혀 없습니다. 구글에서 받은 이용자 정보를 어떻게 쓰고 보관하는지 적혀 있어야 콘솔 등록이 통과합니다
운영구글 콘솔 세팅. 승인 도메인 등록을 리디렉션 주소보다 먼저 해야 합니다. 이후 브랜딩 입력, 클라이언트 발급, 리디렉션 주소 등록, 공개 전환 순서
기획본 안 확정 후 PRD v0.31 개정, 그다음 Figma 시안과 기능정의서 갱신

법무와 운영은 개발과 병렬로 지금 시작해야 합니다. 개발을 끝내고 신청하면 그만큼 오픈이 밀립니다.

6. 결정이 필요한 항목

6-1. 위챗 전제 화면 처리

FO-MYP-07과 FO-RSV-02는 위챗이 있어야 성립하는 화면입니다. 위챗은 아직 미정입니다.

  • 지우면 위챗을 넣을 때 다시 그려야 합니다
  • 남기면 이번 시안에 미확정 요소가 들어갑니다

본 안은 보류로 표시만 하고 삭제하지 않았습니다.

6-2. 이름 확인 화면

FO-LGN-03 이름 확인은 v0.23에서 FO-LGN-04에 흡수하면서 폐기했습니다. 구글은 이름이 빈 값으로 올 수 있어 입력 자리가 필요합니다.

  • FO-LGN-04 안에서 처리
  • FO-LGN-03을 되살려 별도 화면으로 분리

본 안은 FO-LGN-04 안에서 처리하는 쪽으로 잡았습니다.

6-3. SNS 연결 유도 모달

FO-MYP-08은 이메일 가입자에게 로케일별로 채널 하나를 추천하는 화면입니다. 구글만 남으면 추천할 대상이 사실상 하나뿐입니다.

  • 구글 연결 유도로 문구만 바꿔 유지
  • 화면 자체를 보류

본 안은 문구를 바꿔 유지하는 쪽으로 잡았습니다.
