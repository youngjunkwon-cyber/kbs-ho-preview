■ 요구사항

알리페이 이용자가 따로 가입하지 않고 알리페이 계정으로 바로 예약하도록 회원 정보 연동을 만들어 주세요. 진입 동의를 관문으로 두고 프로필을 필수로 받으며, 예약 알림은 우리 문자로 보냅니다. 알리페이 홍콩 월렛 진입도 함께 확인합니다. 규칙 전문은 아래 개발 전달 위키에 있습니다.

 

[무엇을 만드는가]

화면 ID는 9개입니다. 어드민 1, 고객 화면 6, 공통 처리 2입니다. 새 화면은 어드민 알리페이 회원 목록(BO-CH-11), 진입 차단 화면(FO-CH-08), 진입 동의 창(FO-CH-09) 셋이고, 나머지는 기존 화면 수정과 데이터 처리입니다.

- 알리페이 채널에 들어오면 알리페이 계정 식별자를 받아 별도 로그인 없이 회원을 식별합니다. 진입 동의와 알리페이 권한 허용을 통과해야 이용할 수 있습니다

- 알리페이에서 이름, 닉네임, 성별, 생년월일, 국적을 받아 회원 정보에 채우고, 예약 입력과 계정 설정에 씁니다. 휴대폰 번호는 알리페이에서 받지 않고 첫 예약이나 계정 설정에서 직접 입력받아 문자 인증합니다

- 알리페이 회원은 이메일이 없습니다. 예약·상담접수 폼에서 이메일 칸을 빼고, 예약 알림은 우리 문자로 보냅니다

- 어드민 회원 메뉴 아래에 알리페이 회원 목록을 새로 둡니다

- 알리페이 홍콩 연동은 진입 경로(/zh-TW) 확인, 월렛 판별과 홍콩 회원 식별, 권한 해제(revoke), 테스트 계정, 검색 키워드 등재까지입니다

 

[지금 동작이 바뀌는 항목]

- 알리페이 채널은 진입 동의를 통과해야 이용할 수 있습니다. 둘러보기는 없습니다

- 자체 로그인, 회원가입, 소셜 로그인, 비밀번호 찾기로 가는 모든 자리를 숨깁니다

- 예약 입력과 상담접수 폼에 이메일 칸이 없고, 회원 정보로 칸을 채웁니다

- 예약 알림은 이메일 대신 우리 문자로 갑니다. 예약 완료 화면의 이메일 발송 문장은 알리페이 회원에게 문자 발송 문장으로 바뀝니다

- 마이페이지와 계정 설정에 이메일, 비밀번호 변경, 로그아웃, 이름 칸이 없고, 마케팅 정보 수신 토글이 생깁니다

- 진입 관문 스위치를 끄면 지금의 알리페이 도메인 비로그인 동작으로 돌아갑니다(6장)

[핵심 규칙 · 진입 관문]

- 순서: 알리페이에서 계정 식별자를 받습니다(auth_base) → 우리 동의 창(FO-CH-09)에서 필수 셋에 동의하고 "동의하고 시작하기" → 알리페이 권한 요청(getAuthCode)으로 알리페이 권한 창 → 필수 권한 다섯이 모두 허용되면 사용자 정보 조회 → 회원을 만들고 로그인

- 우리 동의 창과 알리페이 권한 창은 합칠 수 없습니다. 알리페이 권한 창은 알리페이가 그리는 화면입니다

- 동의 창 "닫기", 필수 권한 거부, 식별 실패(권한 허용 뒤 우리 쪽 처리 실패 포함)는 진입 차단 화면(FO-CH-08)에 머뭅니다. 화면마다 제목·안내·버튼 문구가 다르고, 문구는 9장 PRD 4장에 있습니다

- 진입 차단 화면은 헤더·메뉴·검색이 없는 전체 화면이고, 버튼은 "다시 동의하기" 또는 "다시 시도" 하나입니다

- 이미 동의를 마친 회원은 다음 진입부터 동의 창을 보지 않습니다. 권한을 해제했거나 권한이 끝났으면 알리페이 권한 창만 다시 띄웁니다

- 창과 화면의 언어는 진입 주소의 언어를 따릅니다

 

[핵심 규칙 · 권한과 프로필]

- 필수 권한은 USER_NAME, USER_NICKNAME, USER_GENDER, USER_BIRTHDAY, USER_NATIONALITY 다섯이고, 하나라도 거부하면 진입 차단 화면입니다

- 아바타, 주소, 연락처(USER_CONTACTINFO), 휴대폰 번호 원본(PLAINTEXT_MOBILE_PHONE), 이메일, 알리페이 로그인 ID 원본은 요청하지 않습니다

- 프로필은 진입 동의 때 한 번 받고 다시 동기화하지 않습니다. 알리페이 계정에 값이 없는 항목은 비워 둡니다

- 예약 입력에서 고친 국적·성별·생년월일과 여권 영문명은 칸을 벗어나는 순간, 계정 설정에서 고친 값은 저장을 누를 때 회원 정보를 덮어씁니다. 휴대폰 번호는 예약에서는 예약 요청을 보낼 때, 계정 설정에서는 문자 인증을 마친 때 덮어씁니다

- 인증한 휴대폰 번호는 회원 정보에 저장되어 두 번째 예약부터 채워지고 인증을 건너뜁니다. 같은 번호를 다른 회원이 인증했어도 막지 않습니다

 

[핵심 규칙 · 식별과 계정]

- 월렛(알리페이 중국/알리페이 홍콩)은 알리페이 응답의 월렛 값으로 정해 진입 때 저장합니다. 값이 없으면 진입 경로로 정합니다(/zh는 알리페이 중국, /zh-TW는 알리페이 홍콩, 그 밖의 경로로 첫 진입하면 알리페이 중국)

- 웹뷰를 새로 열 때마다 알리페이 계정을 다시 식별합니다. 같은 웹뷰 안의 새로고침과 화면 이동, 앱 전환 뒤 복귀는 새로 열기가 아닙니다. 식별한 계정이 직전과 다르면 앞 회원 상태를 끊고 새 회원으로 로그인합니다

- 딥링크로 들어와 식별과 동의를 거치면 원래 가려던 화면으로 돌려보냅니다

- 월렛마다 식별자가 다르면 별도 회원입니다. 웹 회원과 같은 사람이어도 계정을 합치지 않습니다

- 알리페이 회원은 기존 회원 관리 화면에 나오지 않고 알리페이 회원 목록에만 나옵니다. 회원번호는 기존 회원과 겹치지 않고, 회원 수 같은 집계는 두 회원을 합쳐 셉니다

 

[핵심 규칙 · 회원 화면]

- 자체 로그인 경로를 숨기고(FO-CH-10), 로그인 화면 주소로 직접 들어오면 마이페이지로 보냅니다

- 마이페이지 위쪽은 닉네임(비어 있으면 "알리페이 회원")과 가입일이고, 그 아래 한 줄 "알리페이 계정으로 로그인했습니다. K-Beauty Station 계정과는 별개입니다."를 둡니다

- 계정 설정은 여권 영문명, 국적·성별, 생년월일, 휴대폰 번호, 연락 메신저와 저장 버튼입니다. 이메일, 비밀번호 변경, 로그아웃, 이름 칸은 없습니다

- 마케팅 정보 수신 토글(화면 이름 "Marketing messages")은 켜고 끌 때마다 동의 또는 거부를 시각과 함께 남깁니다

- 탈퇴는 기존 탈퇴 경로를 씁니다. 방문 일시가 지나지 않은 예약이 남아 있으면 탈퇴할 수 없습니다. 탈퇴하면 알리페이 식별자와의 연결을 끊고 권한을 해제(revoke)하고, 해제가 실패해도 탈퇴는 진행합니다. 다시 들어오면 새 회원입니다

- 리뷰 작성자명과 채팅에 보이는 이름은 닉네임이고, 닉네임이 비면 "알리페이 회원"입니다. 알리페이 식별자는 고객 화면에 보이지 않습니다

 

[핵심 규칙 · 예약 입력과 상담접수 폼]

- 이메일 칸을 두지 않습니다. 국적·성별·생년월일을 회원 정보에서 채우고 "회원 정보에서 채웠습니다"를 표시하며, 이용자가 고칠 수 있습니다. 이름 칸은 없습니다

- 여권 영문명은 직접 입력받습니다. 메신저 연락처 입력은 현행 그대로 필수이고 매번 빈 칸입니다

- 필수값이 모두 채워지고 휴대폰 번호 인증을 마쳐야 예약 요청 버튼이 켜집니다

- 클리닉 스토어(피부과·성형외과·치과·메디컬체크·안과와 그 스토어의 상품)는 동의 항목에 "[Required] I am 18 or older as of the visit date" 체크 줄을 둡니다. 웹 예약 폼과 같은 규칙이고, 고객이 예약 변경을 신청할 때마다 변경 확인 시트에서 다시 체크합니다. 상담접수·채팅과 매장·운영자가 대신 등록하거나 변경하는 예약에는 없습니다

- 예약 완료 화면은 현행 그대로이고 "We sent the confirmation details to your email"만 알리페이 회원에게 "We sent the confirmation details by text message"로 바꿉니다

- 상담접수 폼의 이름과 휴대폰 번호는 회원 정보 값으로 채우고 이용자가 고칠 수 있습니다. 고친 값은 회원 정보를 덮어쓰지 않습니다

- 예약은 지금의 무결제 예약 그대로이고, 노쇼 등 운영 기준도 같습니다

 

[핵심 규칙 · 어드민 알리페이 회원 목록]

- 화면 제목 "알리페이 회원". 상세 화면과 엑셀 다운로드는 두지 않습니다

- 칼럼은 회원번호, 가입일, 마지막 로그인, 알리페이 식별자, 유입 채널, 닉네임, 이름, 성별, 생년월일, 국적, 언어, 연락처, 여권명, 예약, 노쇼, 프로필 동의 일자, 마케팅 활용 정보(동의 여부, 동의 일자)입니다

- 필터는 가입 기간, 가입 시작일과 종료일, 탈퇴 여부(기본 미탈퇴), 유입 채널, 마케팅 수신 여부, 검색어입니다. 유입 채널 값은 회원이 가입한 월렛(알리페이 중국 / 알리페이 홍콩)입니다

- 알리페이 식별자는 가리지 않고 전부 보여주고, 검색은 완전 일치입니다

 

[핵심 규칙 · 알림 발송]

- 알리페이 회원의 예약 알림은 우리 문자로 보냅니다. 이메일, 알리페이 알림(푸시·문자·메시지함)과 알림 발송 권한(SEND_MESSAGE)은 쓰지 않습니다

- 알림은 예약 확인, 예약 변경, 예약 취소, 예약 거절, 방문 하루 전(전날 한국 시간 오전 10시) 다섯입니다. 변수는 예약번호, 스토어명, 일시, 주소이고, 언어는 회원의 현재 언어입니다

- 받는 번호는 그 예약에 저장된 번호입니다. 발송이 실패하면 5분 뒤 한 번 다시 보내고, 그래도 실패하면 어드민·호스트 예약 상세에 "문자를 보내지 못했습니다."를 보입니다

- 예약번호는 웹과 같은 규칙과 같은 일련 카운터를 씁니다

- 마케팅 문자는 마케팅 정보 수신에 동의한 회원에게만, 한국 시간 오후 9시부터 다음 날 오전 8시 사이를 피해 보냅니다

 

[배포]

- 「알리페이 채널 분리 관리 PRD v1.0」 1단계(채널 기록값 저장 시작) 배포 뒤에 진행합니다

- 알리페이 콘솔 할 일 셋(개발): 기능(Features)에 사용자 인증 기능(App user authorization) 추가, 개발 설정(Development Configuration)에 가맹점 공개 키 등록, 알리페이 중국 API 호출 위임

- 스위치를 끄면 알리페이 채널이 비로그인 상태로 돌아갑니다. 자체 로그인 경로 숨김은 유지하고 로그인·마이페이지 주소는 홈으로 보냅니다. 예약·상담접수는 지금 알리페이 도메인의 비로그인 동작(이메일 칸 포함)입니다. 만든 회원은 그대로 두고 알림도 계속 우리 문자로 보냅니다. 다시 켜면 같은 계정을 그 회원으로 식별합니다

- 롤백은 진입 관문 스위치를 끄는 것입니다. 이미 만들어진 회원은 그대로 둡니다

- STG의 알리페이 채널 주소는 확정 전이고 개발이 지정해 공유합니다

- FO-CH-08 진입 차단 화면. 새 화면. 동의 창 닫기, 필수 권한 거부, 식별 실패일 때 머무는 화면

- FO-CH-09 진입 동의 창. 새 화면. 필수 셋(약관·처리방침·프로필), 선택 하나(마케팅). 항목 넷. 알리페이 권한 창 연계

- FO-CH-10 로그인·회원가입 영역 정리. 알리페이 채널에서 자체 로그인 경로를 숨김

- FO-CH-11 마이페이지·계정 설정. 이메일·비밀번호·로그아웃 없음, 이름 칸 없음, 마케팅 수신 토글

- FO-CH-12 회원 탈퇴. 기존 탈퇴 경로 사용, 알리페이 연결·권한 해제

- FO-CH-13 예약 입력. 이메일 칸 없음, 프로필 자동 채움, 휴대폰 번호는 첫 예약이나 계정 설정에서 직접 입력·문자 인증, 클리닉 스토어는 방문일 기준 만 18세 이상 동의 체크. 상담접수 폼도 이메일 칸 없음
