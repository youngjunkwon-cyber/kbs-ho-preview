웹과 알리페이 앱(alipay-app.kbstations.com)을 별도 채널로 운영하는 작업입니다. 콘텐츠마다 어느 채널에 낼지 정하고, 알리페이 회원은 진입 동의를 통과해야 들어옵니다. 알리페이 예약은 받고 결제만 이번 범위에서 뺍니다.

1. 무엇을 만드는가

화면 ID는 34개입니다. 어드민 13, 호스트 3, 고객 화면 13, 공통 처리 5입니다. 신규 화면은 어드민 알리페이 회원 목록, 고객 진입 차단 화면, 진입 동의 창 셋입니다. 알림 발송 처리가 새로 붙고, 나머지는 기존 화면 수정과 데이터 처리입니다. 상세는 기능정의서에 있습니다.

상품 단위 예약도 이번 범위 안이고, 규칙은 상품 예약 PRD v0.40에서 정합니다. 이 문서의 상품 버튼 규칙은 상품 예약이 들어간 상태를 기준으로 하고, 두 기능이 만나는 곳은 PRD v3.7 부록 C에 있습니다.

알리페이 회원과 알림(FO-CH-08~13, BO-CH-11, SYS-CH-04·05)도 함께 착수합니다. 알리페이 웹뷰에서 getAuthCode를 쓸 수 있다는 알리페이 회신을 2026년 8월 19일에 받았습니다. 유입 채널(BO-CH-12, HOST-CH-03)은 회원 연동 없이 채널 기록값만 써서 1단계에 배포합니다.

2. 지금 동작이 바뀌는 항목

가장 먼저 봐 주세요. 웹 동작이 바뀌는 것과, 알리페이 도메인에서 지금 보이던 동작이 바뀌는 것입니다.

  • 매거진·스토어 칼럼 에디터에 링크 도구로 넣은 우리 도메인 절대 주소는 저장할 때 상대 경로로 바뀝니다.

  • 웹에도 노출 채널 조건이 붙습니다. 알리페이 앱 전용으로 정한 콘텐츠는 웹 목록·검색·상세·사이트맵에서 빠지고 주소로 열면 404입니다. 기존 콘텐츠는 전부 전체로 시작합니다(스토어 칼럼은 저장값 없이 소속 스토어를 따릅니다). 배포 직후 웹에서 빠지는 것은 집계 3 중 배너 자체의 연결 대상이 걸린 배너뿐입니다. 하단 버튼의 대상만 걸린 배너는 버튼만 숨기고 배너는 남습니다

  • 버튼 자리 세는 법. 지금 웹은 상담접수와 문의하기를 한 자리로 세는데 웹과 알리페이 모두 항목별 한 자리로 바뀝니다. 상품 상세의 버튼 조합도 1단계 배포부터 이 세는 법을 따릅니다. 새 세는 법으로 3자리 이상이 되는 기존 데이터(집계 1)는 1단계 배포 전에 운영자가 정리합니다. 정리 완료가 배포 조건이고, 배포 뒤 상한 초과는 잠금 해제·예약 재사용 때만 생깁니다

  • 기획전 구성 항목이 필수가 됩니다. 활성 상태로 저장할 때 담은 항목이 0건이면 저장이 막힙니다. 비활성으로 저장할 때는 막지 않습니다

  • 배너의 연결 대상 선택지가 배너 채널에 맞는 것으로 제한됩니다

  • 스토어 칼럼 에디터는 웹을 포함해 외부 링크와 외부 임베드를 넣을 수 없습니다. 호스트가 옛 칼럼을 다른 항목만 고쳐 저장해도 남은 외부 링크·임베드가 지워집니다(지우기 전 원문을 보관하고, 운영자가 어드민 칼럼 상세의 "원문 복원" 버튼으로 되돌립니다. 어드민 칼럼 상세에서 저장할 때는 본문을 검사하지 않습니다). 매거진은 웹에서 지금처럼 허용합니다

  • 랜딩페이지 배너의 하단 버튼은 연결 대상이 웹에 노출되지 않으면 웹에서도 버튼만 숨깁니다

  • 기획전, 홈 큐레이션 섹션, 인플루언서 기획전, 매거진 본문 카드에서 웹에 노출되지 않는 항목이 빠집니다

  • 알리페이 도메인에서 메신저 버튼을 인앱 채팅으로 바꿔 보여주던 자동 치환을 없앱니다. 배포 4단계이고 2단계(버튼 열 마이그레이션) 뒤여야 합니다

  • FO-CH-13 예약 입력. 이메일 칸 없음, 프로필 자동 채움, 원본 휴대폰이면 인증 생략. 위쪽 요약 카드(상품명 또는 Decide at the store, 스토어명·가격, 고른 시간)는 웹과 같다(상품 예약 PRD 5.11). 클리닉 스토어(피부과·성형외과·치과·메디컬체크)는 방문일 기준 만 18세 이상만 예약(예약 요청 때 판정, 미만이면 알림 창 FO-CH-13-mdl "예약할 수 없습니다". 예약 변경으로 방문일을 바꿀 때도 다시 판정, 매장·운영자 대리 등록·변경은 제외, 진입 관문을 끈 동안의 예약도 같은 기준. 상담접수·채팅은 막지 않고 클리닉이 아닌 스토어는 지금 규칙 그대로). 웹 예약 폼도 같은 규칙(상품 예약 PRD 5.13). 예약 완료 화면은 그대로 쓰되 이메일로 보냈다는 문장만 "We sent the confirmation details by text message"로 바꿈. 알리페이 채널 상담접수 폼도 이메일 칸 없음

5. 핵심 규칙

채널 판별

  • alipay-app.kbstations.com 접속이 알리페이 채널이고, 그 외는 웹 채널이다. 이미 도메인으로 분리 운영 중이라 새 로직이 아니다

  • 필터·폴백·결과 분리·버튼 노출·참조 정리·진입 관문이 모두 같은 판별 결과를 따른다

  • 알리페이 중국과 홍콩은 한 채널(알리페이 앱)이다. 월렛(알리페이 중국/알리페이 홍콩)은 알리페이 응답의 월렛 값으로 진입 때 저장하고, 없으면 진입 경로로 정한다(중국 /zh, 홍콩 /zh-TW, 그 밖의 경로로 첫 진입하면 알리페이 중국). 언어는 진입 주소로 시작한다

노출 채널

  • 콘텐츠 건마다 값이 하나이고, 값은 전체 / 웹 / 알리페이 앱이다. 대상은 상품, 스토어, 배너, 기획전, 매거진이다. 스토어 칼럼은 값을 두지 않고 스토어를 따른다. 인플루언서 기획전은 URL 랜딩이라 대상이 아니다

  • 저장값은 운영자가 고른 값, 유효값은 스토어 종속·대상 외 언어·지원언어·외부링크 배너를 반영해 실제로 적용되는 값이다. 새 상품의 저장값은 전체로 시작한다(칼럼은 저장값이 없다)

  • 공개여부·활성화·히든 같은 기존 노출 조건은 그대로 별개다. 노출 채널은 어디에 낼지만 정한다

  • 상품과 칼럼은 스토어를 따른다. 스토어가 전체면 상품은 셋 중 자유롭게 고르고 칼럼은 전체, 웹이면 웹 고정, 알리페이 앱이면 알리페이 앱 고정이다. 상품은 저장값을 두고(칼럼은 저장값 없음), 화면·목록·노출 판정은 스토어를 반영한 유효값을 쓴다

  • 일본어·인도네시아어·몽골어 상품이나 그 언어를 켠 칼럼이 있는 스토어, 지원언어에 그 언어가 있는 스토어는 알리페이 앱 전용으로 바꿀 수 없다. 저장값이 알리페이 앱인 스토어가 지원언어에 그 언어를 켜면 유효값은 전체가 되고 저장값은 알리페이 앱으로 남는다. 알리페이 앱 전용 스토어에는 그 언어 상품을 새로 등록할 수 없고 칼럼에서 그 언어를 켤 수 없다

  • 지원언어에 간체·번체·영어가 없는 스토어는 웹으로 고정된다. 스토어 라디오에 사유 안내는 없고 버튼 표 알리페이 열에만 잠금 안내가 붙는다. 알리페이 앱 전용 스토어도 지원언어에서 셋을 모두 빼는 저장은 막지 않는다(현행 그대로). 지원언어 저장은 확인 창 없이 바로 저장된다. 노출 채널을 바꾸면서 같은 저장에서 대상 언어를 모두 빼도 창이 없다. 지원언어에서 뺀 언어의 상품은 현행대로 노출되지 않는다

  • 일본어·인도네시아어·몽골어 건은 웹으로 고정된다. 외부링크 배너는 링크종류만 보고 웹으로 고정된다. 스토어 칼럼 에디터가 내부로 보는 도메인은 k-beautystation.com, www.k-beautystation.com, alipay-app.kbstations.com 셋이고 어드민·호스트 도메인은 외부다

  • 언어별 건은 별개다. 상품·배너·기획전·매거진 상세에서 언어를 바꾸면 그 언어의 같은 종류 목록으로 이동하고, 대응 건을 찾지 않고 404로 보내지 않는다(지금 웹과 같은 동작). 스토어 페이지·스토어 칼럼 상세는 지금 웹 동작 그대로다. 알리페이 채널에서 /ja /id /mn으로 들어오면 저장된 언어(없으면 월렛의 진입 언어. 알리페이 중국은 간체, 알리페이 홍콩은 번체) 홈으로 보낸다. 저장된 언어가 일본어·인도네시아어·몽골어면 월렛의 진입 언어로 바꿔 저장하고 그 홈으로 보낸다

  • 호스트 화면에는 설정이 없다. 호스트 상품·칼럼은 스토어 값을 따르고, 한쪽 채널에 나가지 않는 상품·칼럼에는 안내만 보인다. 일본어·인도네시아어·몽골어 상품과 그 언어만 켜진 칼럼에는 안내가 없다

노출 판정. 웹과 알리페이가 같은 규칙이다. 조건 번호 ①~④는 배포 단계(1단계~5단계)와 별개다

  • ① 노출 채널 유효값이 전체이거나 지금 채널과 같다

  • ② 기존 노출 조건은 지금 웹이 쓰는 그대로다. 상품·칼럼은 소속 스토어가 그 채널에 노출되어야 한다. 공통 필터 스위치를 끄면 스토어 노출 채널에서 오는 종속만 풀린다. 스토어 비공개 등 스토어의 ②에서 오는 조건은 그대로다

  • ③ 배너에만 적용한다. 배너 자체의 연결 대상이 그 채널에 노출되어야 한다. 랜딩페이지 배너 본체와 우리 경로 패턴에 맞지 않는 직접입력(목록 페이지)은 대상이 없어 ③을 통과로 본다. 등록 시 채널에 맞지 않는 대상은 고를 수 없고, 신규 등록이거나 이번 수정에서 대상·노출 채널·언어를 바꿔 어긋나면 저장을 막는다. 연결 뒤 대상이 바뀐 경우만 자동으로 숨긴다

  • 랜딩페이지 하단 버튼의 대상은 배너 노출과 무관하다. 대상이 그 채널에 없으면 그 채널에서 버튼만 숨기고 저장은 막지 않는다

  • ④ 기획전에만 적용한다. 담은 항목 중 그 채널에 노출되는 것이 1건 이상이어야 한다. 채널마다 따로 센다

  • 새로 등록했거나 배포 직후라 연결 대상·담은 항목의 노출 여부가 아직 반영되지 않은 배너·기획전은 ③④를 통과로 보고 숨기지 않는다

  • 버튼은 판정 조건이 아니다. 버튼이 없어도 노출된다

  • 인플루언서 기획전은 그 채널에 노출되는 담은 상품이 0건이면 그 채널에서 404다

  • 배너 내부링크 직접입력에는 우리 사이트 경로(/로 시작하는 주소)만 쓰고, /로 시작하지 않는 주소와 //로 시작하는 주소는 칸 옆 안내와 함께 저장을 막고, 외부 사이트는 외부링크로 연결한다. 칸 옆 표시는 대상의 노출 채널 값이다. 우리 경로 패턴에 맞지 않는 주소(목록 페이지)면 "직접입력 (목록 페이지)"로 보인다

목록 표시

  • 노출 채널 칼럼은 하나이고 값은 유효값이다. 세 값 모두 같은 회색 표시다. 상품·스토어 목록에는 사유 칼럼이 없다

  • 사유 칼럼은 배너·기획전 목록에만 있다. "연결 대상이 웹에 없음" / "연결 대상이 알리페이 앱에 없음", 둘 다면 "연결 대상이 웹과 알리페이 앱에 없음" 한 줄로 적는다

버튼 구성

  • 종류는 상담접수 / 채팅(신설) / 상담접수·채팅 통합 표시 / 외부링크 설정 / 메신저 설정 / 예약, 여섯이다. 예약은 스토어와 상품 모두에 있다. 채팅은 웹 열·알리페이 열 모두 OFF로 시작한다

  • 여섯은 각각 독립이다. 켜져 있으면 항목마다 한 자리를 쓴다

  • 자리는 웹 열과 알리페이 열에 각각 둘까지다. 셋째를 켜려 하면 토스트 안내(화면 위쪽에 잠깐 뜨는 안내) "버튼은 최대 2개까지 설정 가능합니다."로 막고 누른 라디오는 원래 값으로 돌아간다. 표 아래 자리 수와 알림 창에 버튼 이름을 적을 때는 표의 행 순서대로 " / "로 잇는다

  • 알리페이 열에서 외부링크와 메신저는 잠겨 있어 켤 수 없다

  • 노출 채널이 웹이면 알리페이 열을, 알리페이 앱이면 웹 열을 잠그고 값은 유지한다. 노출 채널·대상 외 언어·지원언어로 잠긴 열과 예약 설정 때문에 잠긴 예약 줄은 상한 검사에서 빼고 표 아래 자리 수에 넣지 않으며, 잠긴 열은 0개로 적고 이름을 붙이지 않는다. 잠금이 풀리거나 예약을 다시 사용으로 바꿔 상한을 넘으면 빨간 안내가 뜨고 저장이 막힌다

  • 상품의 예약 줄은 웹 열과 알리페이 열을 따로 두고, 자리 세는 법과 잠금 규칙은 다른 버튼과 같다. 기본 설정 상품도 예약 줄은 스토어 예약 버튼 값을 따르지 않고 상품마다 따로 정한다. 기본 설정이면 예약 줄까지 버튼 표 전체가 잠기고 예약 줄에는 상품의 예약 값(처음 OFF)이 흐리게 보이며, 예약 줄을 켜거나 끄려면 개별 설정으로 바꾼다

  • 기본 설정에서 개별 설정으로 바꾸면 다른 버튼은 그 순간의 스토어 값을 두 열 모두 복사하고, 예약 줄은 복사하지 않고 원래 상품 값이 그대로다. 스토어의 버튼 설정을 바꾸면 기본 설정인 상품 전부에 바로 적용된다(예약 줄 제외)

  • 예약설정에서 예약을 미사용으로 바꾸면 스토어 예약 버튼과 상품의 예약 버튼은 값을 그대로 둔 채 잠기고 고객 화면에는 나가지 않는다. 다시 사용으로 바꾸면 둘 다 꺼지기 전 값으로 돌아온다

  • 예약 줄을 켠 기본 설정 상품이 스토어 버튼 변경으로 채널마다 2자리를 넘게 되면 스토어 저장을 알림 창으로 막는다. 예약 설정을 다시 사용으로 바꾸는 저장은 이 검사에서 상품의 예약 버튼을 세지 않는다(넘친 상품은 그 상품 화면에서 빨간 안내와 저장 차단). 상품을 개별 설정에서 기본 설정으로 바꿔 자리가 넘치면 그 상품 화면에 빨간 안내가 뜨고 저장이 막힌다

  • 콘텐츠 설정 저장을 막는 것은 다섯이다. 버튼 자리 상한 초과(예약 줄을 켠 기본 설정 상품이 넘치게 되는 스토어 저장, 상품을 개별 설정에서 기본 설정으로 바꿔 넘치는 상품 저장 포함), 활성 상태로 저장하는 기획전의 담은 항목 0건(비활성으로 저장할 때는 막지 않는다), 배너 연결 대상이 배너 채널에 없음(신규·이번 수정), 직접입력 주소 오류(배너 본체는 /로 시작하는 경로가 아니거나 //로 시작하거나 대상을 못 찾을 때, 하단 버튼은 /로 시작하는 경로가 아니거나 //로 시작할 때만 막고 대상을 못 찾으면 그 채널에서 버튼만 숨긴다. 신규·주소 변경 시), 기획전 유형 레코드 중복이다

  • 서버는 위 다섯과 스토어·칼럼 언어 규칙 셋(대상 외 언어 건이 있거나 지원언어에 대상 외 언어가 있는 스토어의 알리페이 앱 전용 전환, 알리페이 앱 전용 스토어의 대상 외 언어 상품 등록, 알리페이 앱 칼럼의 대상 외 언어 켜기)을 저장 시점에 다시 검사한다

  • 버튼 설정에서 저장을 막는 것은 자리 상한 초과뿐이다. 버튼이 비었다는 안내나 확인은 없다

고객 화면 처리

  • 숨김은 웹과 알리페이 양쪽의 모든 노출면에 같은 판정으로 적용한다. 숨긴 콘텐츠는 화면에서 가리기만 하는 것이 아니라 어떤 경로로도 볼 수 없어야 한다. 노출면마다 결과가 달라서는 안 된다

  • 판정 조건 ①③④ 때문에 노출되지 않는 주소는 404, ② 때문이면 지금 정책(비공개 스토어는 200과 noindex)을 따른다

  • 저장하면 60초 안에 목록과 고객 화면에 반영된다

  • 사이트맵에는 웹 채널 판정을 통과한 건만 넣는다. 사이트맵은 기존 생성 주기대로 갱신하고 60초 반영 기준의 대상이 아니며, 알리페이 도메인은 지금처럼 색인하지 않는다

  • 알리페이 채널에서 버튼이 0개면 하단 버튼 영역을 접는다

  • 상품 상세 [예약]과 예약 화면 상품 선택에는 예약 설정이 켜진 스토어의 상품 중 노출 판정을 통과하고 고객이 보고 있는 채널 열의 상품 예약 버튼이 켜진 상품만 나온다. 스토어 예약 버튼(스토어 페이지 [예약])은 상품 예약과 무관하다

  • 메신저 카드, SNS 임베드, SNS 채널 아이콘, 상품 인스타그램 임베드는 알리페이 채널에서 늘 영역째 숨긴다. 허용 목록은 매거진·스토어 칼럼 본문 안의 임베드에만 적용하고, 목록에 없는 본문 임베드는 숨긴다(허용 목록은 운영자가 확정, 확정 전에는 비어 있다). 구글 리뷰 위젯은 대상이 아니다

  • 매거진·스토어 칼럼 본문의 외부 링크는 알리페이 채널에서 글자로 바꾸고, 외부 임베드는 숨긴다. 저장된 본문은 그대로다

  • 스토어 대표번호·사업자 이메일 같은 전화·메일 링크(tel·mailto)는 알리페이 채널에서 글자로 바꾼다

  • 리뷰는 채널을 나누지 않는다. 작성자 표시명은 회원 정보의 닉네임(진입 동의 때 받은 알리페이 닉네임, 고치는 자리 없음)이다. 닉네임이 비어 있으면 "알리페이 회원"으로 표시하고 난수형 식별자는 쓰지 않는다

회원

  • 진입 동의가 관문이다. 둘러보기는 없다. 우리 모달 하나(이용 약관·개인정보 처리방침·알리페이 프로필 제공 필수, 마케팅 정보 수신 선택. 프로필 제공 설명에 닉네임이 리뷰와 채팅에 작성자 이름으로 표시된다는 안내) 뒤에 알리페이 권한 창이 한 번 뜬다. 순서는 알리페이 계정 식별자 받기(auth_base) → 우리 동의 창 → 알리페이 권한 창(getAuthCode) → 필수 권한이 모두 허용되면 사용자 정보 조회 → 회원 생성·로그인이다. 이미 동의를 마친 회원은 다음 진입부터 동의 창을 다시 보지 않는다. 회원이 알리페이에서 권한을 해제했거나 권한이 끝났으면 다음 진입 때 진입 관문 전체가 아니라 알리페이 권한 창만 다시 띄우고, 거기서 필수 권한을 거부하면 진입 차단 화면(필수 권한 거부)에 머문다

  • 동의 창 닫기, 필수 권한 거부, 식별 실패(권한 허용 뒤 우리 쪽 처리 실패 포함)는 진입 차단 화면으로 간다. 원본 휴대폰 권한은 알리페이가 승인해 요청하는 동안 필수라 거부하면 진입 차단 화면으로 간다

  • 필수 권한은 이름, 닉네임, 아바타, 성별, 생년월일, 국적, 주소, 연락처(USER_CONTACTINFO) 여덟이고, 알리페이가 승인한 뒤에는 휴대폰 번호 원본 권한(PLAINTEXT_MOBILE_PHONE)이 아홉째 필수다. 휴대폰 번호는 원본 권한으로 원본이 왔을 때만 쓰고 가려진 값은 쓰지 않는다. 이메일은 받지 않는다

  • 동의 창 문구에는 실제로 요청하는 권한만 적는다. 휴대폰 번호는 필수인 연락처 권한으로 늘 요청하므로 빠지지 않는다

  • 알리페이 회원은 어드민에서 기존 회원과 따로 보이고(BO-CH-11) 회원번호가 기존 회원과 겹치지 않는다. 계정을 합치지 않는다

  • 웹뷰를 새로 열 때마다 다시 식별하고, 로그인은 웹뷰가 열려 있는 동안 유지한다. 새로 열기는 알리페이 앱에서 우리 진입 주소나 딥링크로 웹뷰가 처음 뜨는 것이고, 같은 웹뷰 안의 새로고침과 화면 이동, 앱 전환 뒤 복귀는 새로 열기가 아니다. 새로 식별한 알리페이 계정이 직전과 다르면 앞 회원 상태를 끊고 새 회원으로 로그인한다

  • 원본 휴대폰이 오면 예약 폼 문자 인증을 생략하고, 고치면 다시 인증한다. 원본 권한이 없으면 직접 입력하고 인증한다. 두 갈래를 모두 만든다. 인증한 번호는 회원 정보에 저장되어 두 번째 예약부터 채워지고 인증을 건너뛴다

  • 예약 폼 필수값은 지금 웹과 같고 이메일만 뺀다. 국적·성별·생년월일은 회원 정보에서 채운다. 이름·주소 칸은 마이페이지·계정 설정과 예약 입력에 두지 않는다. 알리페이 채널 상담접수 폼도 이메일 칸을 빼고 프로필을 채운다

  • 알리페이 채널 예약 폼·상담접수 폼의 메신저 앱 열기 버튼은 숨기고 아이디는 고객이 직접 입력한다(왓츠앱, 라인, 위챗, 카카오 네 메신저 모두 같다). 예약 폼의 메신저 칸은 회원 정보에서 채우지 않고 매번 빈 칸이며, 예약에서 입력한 메신저는 회원 정보에 저장하지 않는다

  • 예약 입력의 위쪽 요약 카드, 예약 완료 화면의 Product 줄, 마이페이지 예약 카드의 상품 줄은 웹과 같다(상품 예약 PRD 5.11)

  • 예약 입력에서 고친 국적·성별·생년월일은 칸을 벗어나는 순간, 계정 설정에서 고친 값은 저장을 누를 때 회원 정보를 덮어쓴다. 휴대폰 번호는 예약 요청 때(계정 설정은 인증을 마친 때) 덮어쓴다. 상담접수 폼에서 고친 값은 현행 상담접수 폼 로직 그대로이고 회원 정보를 덮어쓰지 않는다

  • 마케팅 수신은 계정 설정의 마케팅 정보 수신 토글에서 바꾼다. 마케팅 문자는 동의한 회원에게만 보낸다

  • 탈퇴 때 권한 해제가 실패해도 탈퇴는 진행한다

  • 예약의 확인·변경·취소는 알리페이 앱에서 우리 채널을 다시 여는 것이 정규 경로다. 그 밖의 경우는 고객센터가 예약번호와 휴대폰 번호로 대신 처리한다

알림

  • 예약 알림은 우리 문자로 보낸다. 알림 종류는 예약 확인·변경·취소·거절·방문 하루 전, 다섯이다. 상품 예약이면 상품명 줄을 더한다(상품 예약 PRD 7장. 상품명은 예약한 언어, 항목 이름은 회원의 지금 언어)

  • 링크 대신 예약번호를 넣는다(스토어명·일시·주소는 그대로)

  • 방문 하루 전 알림은 전날 오전 10시에 확정 상태인 예약에만 보낸다. 그 뒤 확정되거나 바뀐 예약과 당일 예약은 확정·변경 알림으로 대신한다

  • 알리페이 회원에게 이메일은 보내지 않는다. 진입 관문을 끈 동안 알리페이 도메인에서 비로그인으로 예약한 고객은 웹 고객처럼 이메일을 받는다

6. 마이그레이션과 배포 순서

  • 기존 콘텐츠의 노출 채널을 전부 전체로 일괄 설정한다. 기존 버튼 ON/OFF는 웹 열 값으로 그대로 둔다

  • 알리페이 열은 스토어가 예약설정 사용이면 예약과 상담접수, 미사용이면 상담접수를 켠다. 개별 설정 상품은 상담접수를 켠다. 기본 설정 상품은 배치 대상이 아니고 늘 스토어 값(예약 줄 제외)으로 보인다. 웹 열 값을 알리페이로 옮기지 않는다

  • 배너의 하단 버튼은 버튼 링크 종류가 외부링크면 알리페이 비활성화, 내부링크와 링크없음이면 웹 값을 그대로 둔다

  • 상품의 예약 줄은 기본 설정·개별 설정 상품 모두 웹 열·알리페이 열을 OFF로 두고, 이후 새로 등록하는 상품도 OFF로 시작한다. 운영자가 상품마다 켜므로 배포 때 상품 예약은 꺼져 있다

  • 배치는 여러 번 실행해도 결과가 같다. 다시 돌려도 운영자가 저장한 알리페이 열은 바뀌지 않는다

배포는 다섯 단계입니다.

  • 1단계. 노출 채널 값 설정(전부 전체)과 어드민·호스트 화면(스토어 칼럼 에디터 차단·원문 복원, 매거진 저장 결과 창(띄우는 것은 5단계부터), 유입 채널 표시 포함). 채널 기록값 저장도 이때 시작한다

  • 2단계. 버튼 열 마이그레이션(알리페이 열 채우기)

  • 3단계. 판정 결과와 목록 사유가 어드민 목록에 보이기 시작합니다. 고객 화면에는 아직 적용하지 않습니다

  • 4단계. 고객 화면 알리페이 열 렌더(웹 열의 채팅과 배너 하단 버튼 내부링크 렌더 포함), 자동 치환 제거, 외부 요소 숨김, 본문 외부 링크·임베드 변환, 알리페이 채널 언어 목록·경로 정리

  • 5단계. 공통 필터(양방향)를 적용합니다

단계 사이 동작: 1단계~4단계 동안 저장 완료 안내는 "저장했습니다"만 띄웁니다("1분 안에 반영됩니다" 줄은 5단계부터). 1단계~2단계에서 배너 대상 셀렉트는 기존 노출 조건(②)만으로 거릅니다. 사유 칼럼은 3단계부터 값이 보입니다. 1단계~4단계에는 호스트 화면의 채널 안내(상품·칼럼의 "알리페이 앱에서는 보이지 않아요"·"웹에서는 보이지 않아요")와 매거진 알리페이 앱 표시 안내 창을 띄우지 않고, 스토어 저장 확인 창의 배너·기획전 문장은 3단계부터 씁니다. 1단계~2단계에는 판정이 없어 배너 직접입력 칸 옆 표시와 연결 대상의 채널 불일치 저장 차단도 3단계부터 동작합니다. /로 시작하지 않는 주소와 대상을 찾을 수 없는 주소의 저장 차단은 1단계부터입니다. 2단계 배치는 1단계 배포 직후 같은 날 실행합니다.

4단계는 반드시 2단계 뒤입니다. 알리페이 열이 채워지기 전에 알리페이 열로 렌더하면 알리페이 앱에서 하단 버튼이 전부 사라집니다. 치환으로 보이던 채팅 버튼이 사라지는 것은 의도한 결과입니다.

진입 관문 스위치가 켜는 화면(FO-CH-08·09·11·12·13. FO-CH-10은 처음 켤 때 함께 켜지고 꺼도 유지됩니다)은 1단계~5단계와 별개입니다. FO-CH-13의 클리닉 만 18세 판정은 스위치와 별개로 늘 동작합니다. 어드민 알리페이 회원 목록(BO-CH-11)은 진입 관문을 처음 켜기 전에 배포합니다. 어드민 유입 채널(BO-CH-12)과 호스트 유입 채널(HOST-CH-03)은 1단계에 배포합니다. 회원정보 조회 권한 개통, PRD 16장 "관문 오픈 차단" 세 항목(진입 동의 구조의 지침 부합 여부와 심사 기간, 월렛별 authClientId, 중국 월렛 getAuthCode·getSiteInfo 호출 권한 개통) 회신, PRD 16장 콘솔 할 일 세 가지와, PRD 15장 선행 작업 중 기한이 "진입 관문 오픈 전"인 다섯 항목(개인정보 처리방침·이용약관 개정 게시, 약관·처리방침 3개 언어 전문 준비, 번역 문구표, 월 문자 비용 추정, 고객센터 대리 처리 절차 공유)이 끝난 뒤 켭니다. 이용약관의 클리닉 나이 조항은 나이 판정을 웹이나 알리페이에 처음 배포하기 전에 게시합니다.

스위치는 둘입니다. 어드민 화면 없이 서버 구성 값으로 두고, 운영자가 요청하면 개발이 배포 없이 바꿉니다. 어느 스위치든 켜고 끈 시각과 요청자를 기록합니다.

  • 공통 필터: 끄면 노출 채널·연결 대상·담은 항목 조건(①③④)과 채널 종속(스토어 노출 채널에서 오는 종속)이 풀리고, ② 기존 노출 조건(스토어 비공개 등으로 빠지는 조건 포함)과 외부 연결 계열 넷은 그대로입니다.

  • 진입 관문: 끄면 알리페이 채널은 비로그인 상태로 돌아가고 회원은 그대로 둡니다. 자체 로그인 경로 숨김은 유지하고, 로그인·마이페이지 주소로 들어오면 홈으로 보냅니다. 예약·상담접수는 지금 알리페이 도메인의 비로그인 동작(이메일 칸 포함)으로 돌아갑니다. 클리닉 스토어 만 18세 판정은 꺼도 그대로 합니다(FO-CH-13). 기존 회원의 알림은 계속 우리 문자로 보냅니다. 다시 켜면 같은 계정을 그 회원으로 식별합니다.

외부 연결 계열 넷은 스위치와 별개로 늘 적용되어 공통 필터 스위치를 꺼도 유지됩니다. 외부링크 배너의 알리페이 앱 숨김, 외부링크·메신저 버튼의 알리페이 앱 비표시, 메신저 카드·SNS 임베드·SNS 채널 아이콘 숨김, 본문 외부 링크·임베드의 알리페이 앱 변환입니다.

7. 개발에 요청하는 것

어드민 필터가 배포 후에 생겨서 배포 전에는 개발이 직접 뽑아 주셔야 합니다. 아래 다섯 건을 건별 ID·이름·언어·해당 조건을 담은 스프레드시트 한 장으로 부탁드립니다. 건수를 받으면 운영 정리 공수를 확정합니다.

  • 집계 1. 웹 열 버튼 자리가 3개 이상인 상품·스토어

  • 집계 2. 활성 상태이면서 구성 항목이 0건이거나 웹에서 노출 가능 항목이 0건인 기획전(알리페이 앱에서만 0건인 기획전은 참고용)

  • 집계 3. 연결 대상이 비활성·기간 종료·언어 불일치·삭제·비공개이거나, 배너 언어의 언어별 노출이 꺼진 스토어이거나, 노출 상품 없는 인플루언서 기획전이라 그 채널에 노출되지 않는 배너. 하단 버튼 대상이면 버튼만 숨긴다. 배너 자체가 이미 기간이 지났으면 세지 않습니다

  • 집계 4. 같은 유형 값과 언어로 둘 이상인 기획전 유형 레코드

  • 집계 5. 지원언어에 간체·번체·영어가 없는 스토어. 배포와 동시에 그 스토어와 상품·칼럼이 알리페이 앱에서 빠진다

집계 1·2·4는 1단계 배포 전에 운영자가 정리를 마칩니다. 집계 3·5는 정리를 기다리지 않고 배포합니다.

STG 알리페이 채널 도메인은 확정 전입니다. 개발에서 지정해 공유해 주세요.

알리페이 담당에게 서면으로 확인받을 항목은 기획에서 진행합니다. 차단 범위가 "두 갈래로 흡수"인 항목은 결과마다 처리를 문서에 정해 두었습니다.

  • 진입 때 필수 항목 동의 후 계정 권한(getAuthCode)을 요청하는 구조가 "미니프로그램을 열 때 권한 허용을 유도하지 말 것" 지침(중국·홍콩 공통)에 어긋나는지, 출시 심사 기간. 관문 오픈 차단

  • 월렛별 authClientId를 받는 방법. 회원 정보 조회(applyToken)에 필요합니다. 관문 오픈 차단

  • 중국 월렛: getAuthCode·getSiteInfo 호출 권한 개통 요청(미니프로그램 ID 2102020206420316). 알리페이 솔루션 아키텍트가 엽니다. 관문 오픈 차단

  • 원본 휴대폰 권한(PLAINTEXT_MOBILE_PHONE) 승인 여부와 월렛별 지원 여부. 두 갈래로 흡수

  • 알리페이에서 받은 휴대폰 번호의 자체 마케팅 사용 가능 여부. 두 갈래로 흡수

  • 홍콩 월렛: 테스트 계정을 받을 수 있는지. 두 갈래로 흡수

  • 홍콩 월렛: 검색 키워드 개수·형식과 의료 관련 단어 가능 여부. 홍콩 검색 노출 차단

알리페이 회신과 별개로 개발에서 콘솔에 해 둘 일입니다. 진입 관문을 켜기 전에 끝내 주세요.

  • 기능(Features)에 사용자 인증 기능(App user authorization) 추가. 지금은 추가된 기능이 없습니다

  • 개발 설정(Development Configuration)에 가맹점 공개 키 등록. 지금은 미등록입니다

  • 중국 월렛 API 호출 위임. 콘솔 상태가 "Authorization Required"입니다. 같은 계정으로 알리페이 중국에 로그인해 승인합니다

이미 답을 받은 항목입니다.

  • 미니프로그램 설정·출시: 우리가 받은 콘솔 계정이 워크스페이스 Owner라 직접 수정·업로드·출시합니다. 유형이 DSL이라 진입 주소는 코드의 web-view 주소로 바꾸고, alipay-app.kbstations.com은 허용 목록에 이미 있습니다(콘솔, 2026-10-13)

  • 출시 상태: 중국은 v1.0.3(2024-10-08), 홍콩은 v1.0.5(2025-07-08)가 정식 출시되어 있습니다(콘솔, 2026-10-13)

  • 권한 해제(revoke): 홍콩은 있고 중국은 지원하지 않습니다(기능 추가 안내). 지원하지 않거나 실패해도 탈퇴는 진행합니다

  • getAuthCode 사용 가능 여부: 웹뷰에서 쓸 수 있습니다(2026-08-19 회신). 월렛마다 주는 사용자 정보가 다를 수 있어 userId로 식별하라고 권했습니다

  • 거부한 권한 목록이 응답에 오는지: 허용된 권한(authSuccessScopes)과 거부된 권한(authErrorScopes)이 따로 옵니다(개발자 문서)

  • 월렛 식별: my.getSystemInfo의 app 값으로 알 수 있습니다. 중국은 alipay, 홍콩은 alipayHK입니다(2026-07-10 회신)

8. 이번 범위가 아닌 것

  • 알리페이 결제(예약은 포함), 월렛 확대, 새 채널별 통계 화면, 목록 일괄 변경, 계정 병합

  • 상품 단위 예약은 이번 범위 안이고 상품 예약 PRD v0.40에서 정합니다. 두 기능이 만나는 곳은 PRD v3.7 부록 C에 있습니다

  • 다만 노출·클릭·조회수·버튼 클릭수·채팅·상담·예약 기록에 어느 채널에서 들어왔는지 값(채널 기록값: 웹 / 알리페이 중국 / 알리페이 홍콩)을 남기는 것은 이번에 넣습니다. 통계용이고 과금 기준은 그대로입니다. 화면은 나중에 만들어도 되지만 값을 남기지 않으면 소급할 수 없습니다

  • 기획전 유형 관리의 중복 차단은 기존 화면에 검증 하나만 추가하는 것이라 동작 시안 범위 밖입니다

  • 건수 칩 줄이 이미 있는 어드민 화면만 칩에 유입 채널 그룹을 더하고, 호스트 목록 화면은 건수 칸을 새로 두지 않고 필터를 고른 뒤 목록 제목의 건수로 보며, 대시보드 통계 영역은 합계만 보여주고 채널별 숫자와 필터는 두지 않습니다. 값이 0인 칸(메신저 문의·채팅 문의·예약 확정·방문 완료)은 숨깁니다. 새 통계 화면은 범위 밖입니다. 메신저 상담(어드민 메신저 상담 관리, 호스트 메신저상담)은 알리페이 채널에 메신저 버튼이 없어 늘 웹이라 유입 채널 대상이 아닙니다
