## 1. 개요·목적

K-Beauty Station 예약은 지금 스토어 예약만 있습니다. 고객은 스토어와 시간만 고르고, 어떤 시술로 오는지는 예약에 남지 않습니다.

이번 작업은 지금의 스토어 예약 구조 위에 **상품을 붙여 예약하는 기능**을 더합니다.
- 고객은 상품 상세에서 바로 그 상품으로 예약할 수 있습니다.
- 스토어 페이지에서 예약할 때도 상품을 고를 수 있습니다. 고르지 않으면 지금과 같은 스토어 예약입니다.
- 스토어와 운영팀은 어떤 상품으로 들어온 예약인지 목록·상세·수치로 보고, 운영팀은 예약 상세에서 유입경로도 봅니다.

## 2. 범위

**포함**
- FO
  - 예약 화면의 상품 영역(상품 상세 진입 시 고정 표시, 스토어 진입 시 날짜·시간 아래 상품 선택, 기본 I'll decide at the store)
  - 상품 상세의 예약 버튼
  - 예약하기 URL 진입(스토어 예약 URL은 스토어 진입, 상품 예약 URL은 상품 고정 진입, 5.2)
  - 예약자 정보 입력 요약 카드의 상품 정보
  - 예약 요청([Book])을 누를 때 클리닉 스토어 나이 판정(5.13)
  - 예약 완료 화면, 마이페이지 메인 Booking History 카드, 마이페이지 예약 목록·상세의 상품 정보
- HOST
  - 대시보드 예약 현황 카드의 상품 정보
  - 대시보드 통계 칸 노출 규칙(스토어 방문·상품 방문 고정, 나머지는 값이 있을 때만)
  - 예약 현황(문의 · 방문 예약 > 예약 현황) 목록의 상품 정보
  - 예약 현황 처리 필요 패널 카드의 상품 정보
  - 예약 상세의 상품 정보 영역(유입경로는 보이지 않음, 5.8)
  - 예약 처리 모달의 상품 정보
  - 수기 예약 등록의 상품 선택
- BO
  - 예약 관리 목록의 상품 정보
  - 예약 상세의 상품 정보 영역과 유입경로
  - 예약 처리 모달의 상품 정보
  - 상품 > 관리자설정 > 버튼 설정에 예약 추가
  - 상품 목록·기획전·인플루언서 기획전의 “예약수” 칼럼과 버튼 클릭수의 “예약하기” 칸
  - 통계 > 스토어 문의 통계의 문의 방식 “플랫폼 예약”
- 발송
  - 상품 예약용 템플릿 추가: 스토어 알림톡, 고객 이메일, 고객 문자
- 데이터
  - 예약에 유입경로(스토어 / 상품) 추가

**제외**
- 시술 시간에 따라 예약표 여러 칸을 차지하는 방식
  - 시술 시간 정보가 클리닉 상품에만 있어 공통 기준을 잡을 수 없습니다.
  - 카테고리·옵션 정비가 끝난 뒤 다룹니다.
- 상품 옵션 선택
  - 지금 상품에 옵션이 없습니다.
  - 옵션 정비가 끝난 뒤 다룹니다.
- 구글 예약 연동(아직 연동 전이며, 연동 작업에서 다룹니다)
- 입점사의 상품 예약 버튼 직접 제어
- 결제는 지금 스토어 예약 구조를 그대로 따릅니다(현재 무결제).
- 예약 목록(HOST 예약 현황·BO 예약 관리) 엑셀 다운로드(지금 실화면에 없고, 이번에 만들지 않습니다)

## 3. 성공 지표

- 예약 버튼을 켠 상품 수
- 상품 예약 건수
- 전체 예약 중 상품 예약 비중
- 유입경로별 예약 건수(스토어 / 상품)

## 4. 사용자·역할

- FO(고객)
  - 상품 상세 [예약], 스토어 [예약], 예약하기 URL(스토어 예약 URL / 상품 예약 URL)로 들어옵니다.
  - 날짜·시간을 고른 뒤, 그 아래에서 상품을 확인(상품 상세 진입, 상품 고정)하거나 선택(스토어 진입, 선택 사항)합니다.
  - 이후 흐름(로그인, 예약자 정보, 완료)은 스토어 예약과 같습니다.
  - 마이페이지에서 예약한 상품을 확인합니다.
- HOST(입점사)
  - 문의 · 방문 예약 > 예약 현황에서 상품 예약과 스토어 예약을 구분해 확인합니다.
  - 수기 예약에 상품을 붙여 등록합니다.
  - 대시보드와 처리 필요 패널에서 어떤 상품 예약인지 바로 확인합니다.
- BO(K-Beauty Station)
  - 상품별 예약 버튼을 켜고 끕니다.
  - 전 스토어 예약을 상품 기준으로 확인하고, 예약 상세에서 유입경로를 봅니다.
  - 상품 목록·기획전·인플루언서 기획전에서 예약수와 예약하기 버튼 클릭수를 확인합니다.
  - 스토어 문의 통계에서 스토어별 플랫폼 예약 건수를 확인합니다.

## 5. 핵심 정책

### 5.1 예약표

- 상품 예약은 스토어 예약과 **같은 예약표**를 씁니다.
  - 상품 예약과 스토어 예약이 같은 시간대의 자리를 나눠 씁니다.
  - 운영시간, 예약 간격, 동시에 받을 예약 수, 예약 마감, 예약 안 받는 날은 전부 스토어 예약 설정 값을 따릅니다.
- 상품 예약 1건은 **예약표 한 칸**을 차지합니다(스토어 예약과 같습니다).
  - 상품의 시술 시간은 예약 가능한 시간 계산에 쓰지 않습니다.

### 5.2 상품 선택

- 상품 상세에서 [예약]으로 들어오면
  - 그 상품으로 고정된 예약 화면이 열립니다.
  - 예약 화면에서 다른 상품으로 바꾸거나 선택을 풀 수 없습니다. 상품 목록과 “I'll decide at the store” 없이 그 상품 카드만 보여줍니다.
  - 다른 상품으로 예약하려면 뒤로 가서 원하는 상품의 [예약]을 누르거나, 스토어 [예약]으로 들어옵니다.
- 스토어 페이지에서 [예약]으로 들어오면
  - 예약 화면에 상품을 고르는 영역이 있습니다.
  - 맨 위 선택지는 “I'll decide at the store”이고, 처음 들어오면 이것이 선택돼 있습니다. 이대로 예약하면 스토어 예약입니다.
  - 그 아래 상품 중 하나를 고르면 상품 예약이 됩니다. I'll decide at the store와 상품은 둘 중 하나만 고릅니다.
  - 고른 상품을 풀면 다시 I'll decide at the store가 선택됩니다.
  - 고르는 영역의 모양과 동작은 5.11을 따릅니다.
- 고를 수 있는 상품
  - 그 스토어의 상품
  - 상품의 예약 버튼이 켜져 있는 상품(기본 설정 상품도 스토어 예약 버튼과 무관하게 상품 값으로 봅니다, 5.3 참조)
    - 예약 버튼은 고객이 보고 있는 채널의 열을 봅니다(웹이면 웹 열, 알리페이 채널이면 알리페이 열).
  - 고객이 보고 있는 언어로 지금 노출 중인 상품
    - 알리페이 채널 분기 PRD 6장의 노출 판정을 통과한 상품입니다. 알리페이 채널이면 노출 채널 유효값이 웹인 상품은 빠지고, 웹이면 알리페이 앱 전용 상품이 빠집니다.
- 고를 수 있는 상품이 하나도 없으면 상품을 고르는 영역을 두지 않습니다. 지금 스토어 예약 화면 그대로입니다(예약 줄을 켠 상품이 없는 스토어 포함).
- 예약 1건에 상품은 1개까지입니다.
- 예약 후에는 상품을 바꿀 수 없습니다.
  - 다른 상품으로 바꾸려면 취소하고 다시 예약합니다.
  - 일시 변경 신청은 스토어 예약과 같이 할 수 있습니다.
- 예약하기 URL로 바로 들어오면, 어디서 딴 URL인지에 따라 나뉩니다.
  - 스토어 예약 URL(스토어에서 딴 URL): 스토어 페이지 [예약]으로 들어온 것과 같습니다. 상품을 고르는 영역이 있고, 유입경로는 “스토어”입니다.
  - 상품 예약 URL(상품에서 딴 URL): 상품 상세 [예약]으로 들어온 것과 같습니다. 상품이 고정되고, 유입경로는 “상품”입니다.
  - 상품 예약 URL로 들어왔는데 그 상품을 지금 예약할 수 없으면
    - 들어오자마자 예약 화면 위쪽에 “This product can't be booked right now.”와 [Go to store page] 버튼을 보여줍니다(5.5와 같은 문구·버튼).
    - 날짜·시간은 고를 수 없습니다. 상품이 고정이라 이 URL로는 다른 예약을 만들 수 없기 때문입니다.
    - 버튼을 누르면 스토어 페이지로 이동합니다.
  - 예약 설정이 꺼진 스토어면 두 URL 모두 스토어 예약 PRD의 예약 중단 화면을 따릅니다.
- 구글 예약
  - 아직 연동 전입니다.
  - 연동하면 스토어 단위로 들어오므로, 상품을 고르는 영역이 있는 스토어 진입 화면을 씁니다.

### 5.3 예약 설정과 예약 버튼

- 스토어 예약은 두 층(예약 설정 > 스토어 예약 버튼), 상품 예약도 두 층(예약 설정 > 상품 예약 버튼)입니다.
  - 상품 예약을 스토어 단위로 켜고 끄는 값은 두지 않습니다. 운영자가 상품마다 예약 버튼을 켭니다.
  - 스토어 예약 버튼(스토어 페이지 [예약])은 상품 예약과 무관합니다.

| 층 | 범위 | 누가 바꾸나 | 규칙 |
|---|---|---|---|
| 예약 설정 | 스토어 하나에 하나, 스토어 예약과 상품 예약 공통 | HOST·BO | 꺼지면 스토어 예약 버튼, 상품 예약 버튼이 모두 잠깁니다. 고객 화면에는 나가지 않고, 저장된 값은 흐리게 보입니다. 값은 지우지 않고, 다시 켜면 꺼지기 전 값으로 돌아옵니다. |
| 스토어 예약 버튼 | 스토어 페이지 | BO만 | 기존 그대로입니다. 웹 열과 알리페이 열을 따로 둡니다(알리페이 채널 분기 PRD 7장). |
| 상품 예약 버튼 | 상품 상세 | BO만 | 이번에 추가합니다. 기본 설정·개별 설정과 상관없이 상품마다 자기 값을 씁니다(스토어 예약 버튼 값을 따르지 않습니다). |

- 상품 예약 버튼이 잠기는 경우는 셋입니다.
  - 예약 설정이 꺼진 경우
    - 값은 지우지 않고 잠그기만 합니다. 고객 화면에는 나가지 않고, 저장된 값은 흐리게 보입니다.
    - 잠금이 풀리면 꺼지기 전 값으로 돌아옵니다. BO가 다시 켜지 않아도 됩니다.
    - 잠긴 예약 줄의 안내: “예약설정에서 예약을 사용하면 켤 수 있습니다.”
  - 노출 채널·대상 외 언어 때문에 열이 잠기는 경우(아래 알리페이 채널, 알리페이 채널 분기 PRD 7장·8장 규칙 그대로)
  - 기본 설정인 경우
    - 다른 버튼과 함께 잠깁니다. 값은 상품의 예약 값(처음 OFF)이 그대로 흐리게 보이고, 켜려면 개별 설정으로 바꿉니다(알리페이 채널 분기 PRD 7장).
- 상품 상세 [예약]과 예약 화면 상품 선택(5.2)에 상품이 나오는 조건
  - 예약 설정이 켜져 있습니다.
  - 상품이 노출 중입니다(알리페이 채널 분기 PRD 6장 노출 판정).
  - 고객이 보고 있는 채널 열의 상품 예약 버튼이 켜져 있습니다(스토어 예약 버튼과 무관).
- 스토어 예약 버튼도 예약 설정이 꺼지면 같은 규칙입니다(알리페이 채널 분기 PRD 8장).
  - 값은 그대로 둡니다.
    - 고객 화면에는 나가지 않고, 저장된 값은 흐리게 보인 채 잠깁니다.
    - 예약 설정을 다시 켜면 꺼지기 전 값으로 돌아옵니다.
- 상품 버튼 설정의 기존 “스토어 설정 적용(기본 설정 / 개별 설정)”을 그대로 씁니다.
  - 기본 설정 상품: 다른 버튼은 스토어 값을 따르지만, 예약 버튼은 스토어 예약 버튼 값을 따르지 않고 그 상품의 값을 씁니다. 스토어 예약 버튼이 꺼지거나 켜져도 바뀌지 않습니다.
  - 개별 설정 상품: 그 상품의 예약 버튼 값을 씁니다.
  - 개별 설정 상품은 스토어 예약 버튼이 꺼져 있어도 예약 버튼을 켤 수 있습니다(상품 페이지에서만 예약을 받는 운영). 기본 설정 상품은 개별 설정으로 바꾼 뒤 켭니다.
  - 상품의 예약 버튼 처음 값은 웹·알리페이 모두 OFF입니다.
    - 배포할 때 이미 있는 상품(기본 설정·개별 설정 모두)
    - 배포 뒤 새로 등록하는 상품
    - 운영자가 상품마다 켭니다. 그래서 배포 때 상품 예약은 꺼져 있습니다.
  - 기본 설정에서 개별 설정으로 바꿀 때 다른 버튼은 알리페이 채널 분기 PRD 7장대로 그 순간의 스토어 값을 복사합니다. 예약 줄은 원래 상품 값이 그대로입니다(따로 정하는 값이라 바뀌지 않습니다).
- HOST 상품 화면에는 예약 버튼 상태를 보여주지 않습니다. 입점사는 상품 예약 버튼을 보거나 바꾸지 않고, K-Beauty Station이 BO에서만 관리합니다.
- 상품 상세의 버튼 노출 조합·순서는 스토어 버튼 규칙과 같습니다. 스토어 규칙이 바뀌면 상품도 같이 따릅니다.
  - 지금(알리페이 1단계 배포 전) 웹 규칙
    - 버튼은 최대 2개입니다.
    - 메신저 버튼은 왼쪽에 둡니다.
    - 나머지 한 자리는 예약 > 외부링크 > 상담접수 순으로 켜져 있는 것 하나를 씁니다.
  - 알리페이 1단계 배포부터
    - 알리페이 채널 분기 PRD 7장·8장의 자리 세는 법을 그대로 따릅니다(켠 항목마다 한 자리, 채널마다 최대 2자리, 셋째는 토스트로 막습니다).
    - 상품 버튼 설정의 예약 줄도 같은 세는 법을 따릅니다.
    - 저장 차단 알림 창(BO-CH-10-mdl)은 잠긴 열이 풀리거나, 예약 설정을 다시 켜 이미 세 자리가 된 상태로 저장할 때, 그리고 상품을 개별 설정에서 기본 설정으로 바꿔 자리가 넘친 채 저장할 때 뜹니다.
    - 예약 줄을 켠 기본 설정 상품이 스토어 버튼 변경으로 넘치게 되면 스토어 저장을 막습니다(알리페이 채널 분기 PRD 7장·8장).
  - 예약 설정을 다시 켜 자리가 넘치는 상품
    - 따로 처리하는 규칙은 두지 않습니다. 기존 규칙(채널마다 2자리를 넘을 수 없음)을 그대로 씁니다.
    - 그 상품을 열면 알리페이 채널 분기 PRD 8장의 빨간 안내와 저장 차단이 같게 동작합니다.
    - 넘친 상품이 여러 건이면 운영팀이 백단에서 일괄로 맞춥니다.
    - 이 경로는 알리페이 채널 분기 PRD 15장의 상한 초과 경로 둘(잠금 해제, 예약 재사용) 가운데 예약 재사용입니다.
- 알리페이 채널
  - 상품 버튼 설정 표에 “예약” 줄을 추가하고 웹 열과 알리페이 열을 둘 다 둡니다.
  - 잠금 규칙은 다른 버튼과 같습니다(알리페이 채널 분기 PRD 7장·8장). 기본 설정이면 예약 줄도 다른 줄과 함께 잠깁니다.
    - 노출 채널 유효값이 웹이면 알리페이 열이 잠깁니다(스토어 종속으로 웹이 된 상품 포함).
    - 노출 채널 유효값이 알리페이 앱이면 웹 열이 잠깁니다.
    - 일본어·인도네시아어·몽골어 상품은 알리페이 열이 잠기고, 표 아래 자리 수에 알리페이 앱 0개로 셉니다.
    - 예약 설정이 꺼지면 두 열 모두 잠깁니다.

### 5.4 예약에 저장하는 상품 정보

- 예약하는 순간의 상품 정보를 예약에 따로 저장합니다.
  - 상품명(고객이 예약한 언어)
  - 영어 상품명(같은 상품의 영어 상품이 있을 때만, 7장 발송의 스토어 알림톡에 씁니다)
  - 가격
  - 썸네일
- FO·HOST·BO 모두 이 저장값을 보여줍니다.
  - 화면에는 예약한 언어 상품명만 보여줍니다.
  - 예약 후 상품이 바뀌어도 예약에 보이는 내용은 바뀌지 않습니다.
- 상품 페이지로 가는 링크는 그 상품이 지금 그 언어로 노출 중일 때만 걸립니다.

### 5.5 상품이 바뀌거나 내려갈 때

- 상품 예약 버튼을 끄거나, 상품이 비활성·히든·반려·삭제되면
  - 새 예약만 막습니다.
  - 이미 잡힌 예약은 그대로 유지합니다.
- 예약 요청([Book])을 누르는 순간 상품이 예약 가능한지 다시 확인합니다(스토어 예약의 제출 시점 재검증에 추가).
  - 예약할 수 없게 됐으면 예약을 막고 안내합니다.
  - 상품 상세로 들어온 예약
    - 상품을 바꿀 수 없으므로 예약을 만들지 않고, 정보 입력 화면 위쪽에 “This product can't be booked right now.”와 [Go to store page] 버튼을 보여줍니다.
    - 버튼을 누르면 스토어 페이지로 이동합니다(자동 이동 아님). 상품이 내려갔으면 상품 상세가 열리지 않기 때문입니다.
  - 스토어 페이지로 들어온 예약
    - 예약 화면으로 돌아가 선택을 I'll decide at the store로 되돌립니다.
    - 고를 수 있는 상품이 남아 있으면 “This product can't be booked right now. Please choose again.”을 상품 선택 위에 보여줍니다.
    - 고를 수 있는 상품이 하나도 남지 않았으면(마지막 남은 상품의 예약 버튼이 꺼진 경우 등) 상품 영역 없이 시간 아래에 아래 안내를 보여줍니다. 그대로 진행하면 상품 없는 예약(Decide at the store)이 됩니다.
      - 영어: “This product can't be booked right now. You can still book and decide at the store.”
      - 한국어 원문: “지금 이 상품은 예약할 수 없어요. 그대로 예약하고 매장에서 정할 수 있어요.”
- 예약 설정이 꺼진 뒤 예약 요청([Book])을 누르면 상품이 있든 없든 예약을 만들지 않습니다(스토어 예약 PRD의 제출 시점 재검증과 같습니다).

### 5.6 상품 예약의 처리 규칙

- 일시 변경 신청, 취소, 방문완료, 미방문, 스토어 직접 변경, BO 대리 처리는 전부 스토어 예약과 같습니다.
- 예약번호 체계도 같습니다.
- 다른 점은 예약 후 상품을 바꿀 수 없다는 것 하나입니다.

### 5.7 수기 예약

- HOST 수기 예약 등록에 상품 선택 칸을 추가합니다.
  - 선택 사항이고, 기본 선택은 “스토어 예약”입니다(FO의 Decide at the store와 같은 뜻). 상품을 고르면 상품 예약이 됩니다.
- 선택 칸에 나오는 상품
  - 그 스토어의 승인된 상품 중 예약자 정보에서 고른 언어의 상품만 나옵니다.
  - 예약 버튼이 꺼진 상품도 고를 수 있습니다(수기 예약은 예약 설정이 꺼져 있어도 허용하는 기존 원칙과 같습니다).
  - 언어를 고르기 전에는 “스토어 예약”만 있습니다.
  - 상품을 고른 뒤 언어를 바꾸면 선택이 “스토어 예약”으로 돌아갑니다.
- 저장하는 순간의 상품 정보를 예약에 저장합니다(5.4와 같습니다).

### 5.8 유입경로

- 지금 예약에는 어디서 들어왔는지 남는 값이 없습니다. 이번에 예약에 “유입경로”를 새로 저장합니다.
  - 스토어 예약 PRD v0.3의 데이터 항목에 “유입경로(외부 지도 / 서비스 직접)”가 적혀 있지만 라이브에는 구현되지 않았습니다(2026-10-12 HOST 실화면 확인, 구글 예약 연동 전). 이 절의 유입경로가 그 자리를 대신합니다.
- 값과 이름은 어드민 상담접수·채팅에 이미 있는 “유입경로(스토어 / 상품)”와 맞춥니다.

| 유입경로 | 뜻 |
|---|---|
| 스토어 | 스토어 페이지 [예약] 또는 스토어 예약 URL로 들어옴 |
| 상품 | 상품 상세 [예약] 또는 상품 예약 URL로 들어옴 |

- 유입경로는 들어온 곳이고, 예약 구분(5.9)은 상품이 붙었는지입니다. 스토어 페이지로 들어와 상품을 고르면 “유입경로 스토어 + 상품 예약”이 됩니다.
- 구글 예약 연동이 붙으면 그때 유입경로 값을 추가합니다.
- 수기 예약은 기존 “등록 방식(고객 / 매장)”으로 구분하고, 유입경로는 남기지 않습니다.
- 알리페이 채널 분기 PRD 11장의 “유입 채널(웹 / 알리페이)”과는 다른 값입니다. 둘 다 따로 저장합니다.
- 표시
  - BO 예약 상세(드로어)
    - 위치: 예약 정보 목록(여권명·국적·언어 … 접수 시각·등록 방식. 취소된 예약은 접수 시각·등록 방식 자리에 취소 시각·취소한 사람·취소 사유) 맨 아래에 “유입경로” 한 줄
  - HOST에는 유입경로 칼럼·필터·줄을 두지 않습니다(예약 현황·예약 상세·대시보드·상담접수). 상담접수에 있던 유입경로 칼럼과 필터도 뺍니다(알리페이 채널 분기 PRD 11장).
  - 값이 없는 예약은 “-”로 표시합니다.
    - 수기 예약
    - 이 기능 배포 전에 잡힌 예약
  - 예약 목록 필터에는 넣지 않습니다.

### 5.9 예약 목록 (HOST 예약 현황·BO 예약 관리)

- 칼럼을 새로 만들지 않고, “고객(여권명)” 칸 둘째 줄에 예약 상품을 표시합니다.
  - 모양: 방문일시 칸의 “접수 …” 둘째 줄과 같은 작은 회색 글자입니다.
  - 이유: 지금 표는 칼럼 수에 맞춰 화면 폭이 꽉 차 있어, 칼럼을 하나 더하면 1440 화면에서 상태 칸이 가로 스크롤 뒤로 밀립니다.
  - 알리페이 1단계 배포부터는 알리페이 채널 분기 PRD 11장에 따라 고객(여권명) 뒤에 “유입 채널” 칼럼이 하나 늘어납니다(1440 화면에서 가로 스크롤이 생겨도 칼럼으로 둡니다). 예약 상품은 그때도 고객 칸 둘째 줄 그대로입니다.
  - 상품명이 길면 한 줄로 줄이고 끝을 “…”로 표시합니다(HOST·BO). 마우스를 올리면 전체 이름이 보입니다.
  - 상품이 없는 예약은 “스토어 예약”으로 표시합니다. 빈칸이나 “-”로 두지 않습니다.
- 필터 “예약 구분”을 추가합니다.
  - 선택지: 전체 / 상품 예약 / 스토어 예약
  - 위치: 언어 → 유입 채널 → 예약 구분 → 등록 주체 순입니다. 유입 채널 필터가 생기기 전에는 언어 바로 뒤(등록 주체 앞)에 둡니다.
  - 기존 “등록 주체” 필터(고객 / 매장)는 예약 구분 바로 뒤에 있습니다.
  - 따르는 것
    - BO 예약 관리 상단 카드(전 매장 예약, 방문 예정, 방문 완료, 노쇼, 노쇼율)
    - HOST 목록 제목의 건수(“예약목록 (N)”)
  - 따르지 않는 것: HOST 처리 필요 패널(알리페이 채널 분기 PRD 11장과 같이 늘 전부 보입니다)
  - 초기화 버튼을 누르면 예약 구분도 전체로 돌아갑니다.
- 검색어 대상에 상품명을 추가합니다.
- 예약 상세(드로어)에 “예약 상품” 섹션을 추가합니다.
  - 유입 채널 배지는 이와 별개로 상단 상태 표시 바로 옆에 둡니다(알리페이 채널 분기 PRD 11장).
  - 위치: 예약 일시(변경 요청이면 요청한 새 시간 상자) 바로 아래입니다.
  - 모양: 드로어의 다른 섹션(고객 요청사항 등)과 같은 부품(작은 제목 + 회색 읽기 상자)입니다.
  - 내용
    - 상품명, 가격, 상품 보기 링크(상품이 지금 노출 중일 때만)
    - 썸네일은 넣지 않습니다(어드민에 없는 UI).
    - 상품이 없는 예약은 “스토어 예약”만 표시합니다.

### 5.10 예약수

- 세는 기준
  - 상품이 붙은 예약의 총 접수 건수(취소 포함)
  - 기존 상담접수 수치처럼 총 건수 한 칸으로 봅니다.
  - 수기 예약도 포함합니다.
  - 기준일은 접수일입니다.
  - 스토어 문의 통계의 “플랫폼 예약”은 세는 기준이 다릅니다(수기 예약 제외, 5.15).
- 넣는 곳
  - BO 상품 목록
    - 기존 지표 칼럼(노출수·내부진입수·직접유입수·채팅수·상담수·버튼 클릭수) 중 “상담수” 바로 다음에 “예약수” 칼럼을 추가합니다.
  - BO 기획전, BO 인플루언서 기획전
    - 기존 지표 칼럼(대상 클릭수·채팅수·상담수·버튼 클릭수) 중 “상담수” 바로 다음에 “예약수” 칼럼을 추가합니다. 인플루언서 기획전도 기획전과 같은 칸·같은 기준입니다.
    - 기획전 총합과 대상 상품별 예약수를 보여줍니다.
    - 고객이 기획전을 거쳐 들어왔는지는 따지지 않고, 기획전에 든 상품의 예약수를 더합니다.
  - 칼럼 순서: 채팅수·상담수·예약수·버튼 클릭수(… 페이스북, 예약하기) 순입니다(5.14).
- 넣지 않는 곳
  - HOST 상품 관리 목록
    - 지금 HOST 상품 관리 목록에는 채팅수·상담수 같은 수치 칼럼이 없어, 예약수도 넣지 않습니다(칼럼설정 항목도 그대로).
    - HOST 상품 통계 화면도 바꾸지 않습니다.
  - HOST 대시보드 통계 칸(스토어 방문, 상품 방문, 메신저 문의, 채팅 문의, 예약 확정, 방문 완료)
    - 예약수 칸은 넣지 않고, 칸이 보이는 규칙만 아래처럼 바꿉니다.
    - 스토어 방문, 상품 방문 2칸은 항상 보입니다.
    - 메신저 문의, 채팅 문의, 예약 확정, 방문 완료는 선택한 기간에 값이 있을 때(1 이상)만 보이고, 0이면 숨깁니다.
    - 보이는 칸들이 한 줄 폭을 나눠 씁니다(빈 칸을 남기지 않습니다).
    - “예약 확정” 칸은 예약이 들어온(접수된) 날짜 기준으로 셉니다(알리페이 채널 분기 PRD 11장과 같은 기준).
      - 취소된 예약(고객 취소·매장 취소)만 뺍니다.
      - 그 밖의 상태(예약·변경요청·변경완료·변경거절·방문완료·미방문)는 모두 들어갑니다.
- 칼럼 이름은 “예약수”로 씁니다. 기존 “채팅수”, “상담수”와 같은 이름 짓기입니다.
  - 상담접수 접수상태에 이미 “상품예약” 값이 있습니다. 상담 결과로 상품 예약까지 이어졌다는 뜻이라 이번 기능과 다릅니다.
  - 상담접수 상태값은 손대지 않습니다. 새 칼럼에는 “상품예약”이라는 말을 쓰지 않습니다.

### 5.11 FO 표시

- 예약 화면
  - 상품 카드는 스토어 상세 페이지의 상품 카드 UI를 그대로 씁니다(상품명, 가격, [View Details], 설명 화살표).
    - [View Details]를 누르면 그 상품 상세로 이동합니다.
    - 설명 화살표를 누르면 카드 안에 설명과 시술 정보(시술 시간, 마취, 회복 기간, 효과가 보이는 시점)가 열리고, 다시 누르면 닫힙니다. 선택은 바뀌지 않습니다.
  - 화면 순서: 스토어명·주소 → 날짜 → 시간 → 상품. 상품 영역은 시간 아래에 둡니다.
  - 상품 상세로 들어온 경우
    - 시간 아래에 “Product” 제목과 그 상품 카드 한 장을 보여줍니다.
    - 다른 상품으로 바꿀 수 없습니다(I'll decide at the store와 상품 목록 없음).
  - 스토어 페이지로 들어온 경우
    - 고를 수 있는 상품이 없으면(예약 줄을 켠 상품이 없는 스토어 포함) 상품 영역 전체를 두지 않습니다. 지금 스토어 예약 화면 그대로입니다.
    - 시간 아래에 “Select a product (optional)” 제목과 선택 목록을 둡니다. 목록은 항상 펼쳐져 있고 여닫는 버튼은 없습니다.
    - 목록 맨 위 칸 = 지금 선택. 처음에는 “I'll decide at the store” 카드(상품 카드와 같은 부품, 이름만 있고 가격·버튼 없음)가 선택된 채 있습니다.
    - 상품을 고르면 맨 위 칸이 그 상품 카드로 바뀝니다(I'll decide at the store 카드는 그동안 보이지 않습니다).
    - 상품을 골랐을 때만 제목 “Select a product (optional)” 오른쪽에 “Reset”이 나옵니다. 누르면 I'll decide at the store로 돌아갑니다.
    - 그 아래: 세부분류 칩(All + 목록에 있는 상품의 세부분류)과 상품 카드.
      - 처음에는 5개까지 보이고, [View More Products]를 누를 때마다 5개씩 더 보입니다.
        - 다 보이면 버튼이 사라집니다.
        - 칩을 바꾸면 다시 5개부터 보입니다.
      - 칩은 상품 카드만 거르고, 맨 위 칸(I'll decide at the store 또는 고른 상품)은 칩과 상관없이 항상 맨 위에 있습니다.
    - 선택된 카드는 강조 테두리로 표시합니다. 한 번에 하나만 선택됩니다.
    - 고르기: 상품 카드(버튼 바깥 부분)를 누르면 그 상품이 선택되고 맨 위 칸이 그 상품으로 바뀝니다. 목록의 그 카드도 강조 테두리로 표시합니다.
    - 바꾸기: 다른 상품 카드를 누르면 그 상품으로 바뀝니다.
    - 풀기: 제목 오른쪽 “Reset”을 누르거나, 목록에서 고른 상품 카드를 다시 누르면 I'll decide at the store로 돌아갑니다.
- 예약자 정보 입력 화면
  - 화면 구성은 지금 그대로입니다(예약자 정보, 연락처, 메신저, 요청사항, 동의).
  - 알리페이 회원의 예약 입력 화면도 요약 카드는 같습니다. 이메일 칸이 없는 것 등 폼의 차이는 알리페이 채널 분기 PRD 11장(FO-CH-13)을 따릅니다.
  - 상품 예약이면 위쪽 검은 요약 카드에서 상품명이 제목이 됩니다.
    - 1줄(제목): 상품명
    - 2줄: “at 스토어명 · 가격”
    - 3줄: “Selected time: …”(지금 그대로)
  - 상품 없는 예약도 같은 구성입니다.
    - 1줄: “Decide at the store”
    - 2줄: “at 스토어명”(가격 없음)
    - 3줄: “Selected time: …”(지금 그대로)
- 상품 없는 예약의 표기
  - 고객 화면(영어)
    - 고르는 칸(예약 화면 상품 선택 맨 위 카드): “I'll decide at the store”
    - 결과 칸(정보 입력 요약 카드 제목, 예약 완료 표의 Product 값, 내 예약 목록 둘째 줄, 예약 상세 Product 카드, 마이페이지 카드): “Decide at the store”
    - 상품을 아직 정하지 못한 고객의 마음을 받아 주는 문구입니다. 고르는 칸은 “~할게요” 의도형, 결과 칸은 짧은 이름표로 나눕니다.
  - HOST·BO: “스토어 예약”
  - “consultation”, “상담”이라는 말은 쓰지 않습니다. 상담접수와 헷갈리지 않게 하고, 예약이라는 뜻이 바로 읽히게 하기 위해서입니다.
  - 예약 구분 필터·통계의 구분 이름도 같은 “스토어 예약”입니다.
- 상품 정보 위계 원칙(FO)
  - 예약 전(예약자 정보 입력 요약 카드): 상품 예약이면 상품명이 제목, 스토어명은 보조 줄입니다.
  - 예약 후(예약 완료, 마이페이지 메인 카드, 마이페이지 예약 목록·상세): 스토어가 먼저, 상품명은 그 아래에 둡니다.
    - 방문할 곳을 먼저 확인하는 화면이기 때문입니다.
    - 예약 완료 화면은 요약 표의 첫 줄이 Store, 그 바로 아래 줄이 Product입니다.
  - 상품이 없는 예약은 상품명 자리에 “Decide at the store”를 씁니다(빈 자리로 두지 않습니다).
- 예약 완료 화면, 마이페이지 예약 목록·상세
  - 예약 완료 화면(STG 실화면 2026-10-14 확인): 화면 구성은 지금 그대로입니다(초록 체크, “Your booking is complete”, “We sent the confirmation details to your email”, 요약 표, [View booking details], 관심사 설문 카드).
    - 요약 표(Store / Visit date / Booking number)의 Store 바로 아래에 “Product” 한 줄을 더합니다. 값은 상품명, 상품 없는 예약은 “Decide at the store”입니다.
    - 같은 표 부품(왼쪽 회색 항목명, 오른쪽 값)을 그대로 쓰고, 상품 카드나 링크는 넣지 않습니다.
    - 알리페이 회원에게는 안내 문구가 “We sent the confirmation details by text message”입니다(알리페이 채널 분기 PRD 11장 FO-CH-13). 나머지 구성과 Product 줄은 웹과 같습니다.
  - 마이페이지 예약 상세
    - 제목: 지금 문구 그대로(“You are scheduled to visit” / “Your visit to” + 스토어명)
    - 제목 아래에 Product 영역을 둡니다.
    - 카드: FO 메인의 상품 카드 UI 그대로(상품 이미지, 상품명, 가격, 스토어명, 별점)
    - 카드를 누르면 그 상품을 예약한 언어로 상품 상세가 열립니다. 상품이 지금 노출 중이 아니면 이동하지 않습니다.
  - 마이페이지 예약 목록 카드: 제목은 “스토어명 (D-n)”, 바로 아래 줄에 상품명을 진한 글자(15px 굵게)로 둡니다.
  - 마이페이지 메인 “Booking History” 카드: 예약 목록 카드와 같은 부품이라 같은 상품 줄을 넣습니다(라이브 캡처 2026-10-14 확인).
  - 저장해 둔 상품 정보를 보여줍니다.
  - 상품 없는 예약의 표시
    - 예약 상세 Product 영역: 같은 카드 모양에 “Decide at the store”(가격 없음, 이미지 자리는 스토어 대표 이미지). 누르는 동작은 없습니다.
    - 예약 완료 표의 Product 줄, 목록 카드·마이페이지 메인 카드의 상품 줄: “Decide at the store”
  - 내 예약 목록은 방문 일시 순으로 보여줍니다(지금 정렬 표시 “Visit date & time”과 같습니다).
- 상태 표시는 스토어 예약과 같습니다(예약 / 방문완료 / 취소).

### 5.12 HOST 카드·모달 표시

- 상품명 한 줄을 더합니다. 상품명은 예약에 저장해 둔 값을 쓰고, 상품이 없는 예약은 “스토어 예약”으로 표시합니다.
- 카드의 상품명 위치·크기: 날짜·시간 줄 바로 아래, 고객 이름보다 큰 굵은 글자로 둡니다. 고객 이름은 그 아래 줄입니다.
- 상품명이 길면 한 줄로 줄이고 끝을 “…”로 표시합니다. 마우스를 올리면 전체 이름이 보입니다(대시보드 카드·처리 필요 패널 카드·모달도 같습니다).
- 카드의 날짜·유입 채널 배지·상태 배지가 한 줄에 다 들어가지 않으면(예: 처리 필요 패널 카드의 “알리페이”와 “변경요청”) 배지 묶음을 날짜 아랫줄 오른쪽으로 내립니다. 날짜는 자르지 않습니다(대시보드 카드·처리 필요 패널 카드 모두).
- 대시보드 예약 현황 카드
  - 기존 필터(전체 / 신규 / 방문결과 / 변경)와 카드 구성은 그대로입니다.
  - 예약 고객 카드에 상품명 한 줄을 추가합니다(위치·크기는 위 규칙).
  - 유입 채널 배지는 카드 오른쪽 위 “예약” 배지 바로 왼쪽에 둡니다(알리페이 채널 분기 PRD 11장). 상품명 줄과 자리가 겹치지 않습니다.
- 예약 현황 처리 필요 패널 카드
  - 대시보드 카드와 같게 상품명 한 줄을 추가합니다.
- 예약 처리 모달(시간 변경, 방문완료, 미방문, 취소, 변경 수락·거절)
  - 예약 요약을 보여주는 모달이면 요약에 상품명 한 줄을 추가합니다.
  - 실화면 확인 결과(스테이징 2026-10-13)
    - 예약 시간 변경 모달(HOST·BO 공통): “기존 예약” 일시 줄이 있어 그 아래에 “예약 상품” 줄을 추가합니다. 상품이 없는 예약은 “스토어 예약”으로 표시합니다.
    - 예약 취소 모달(HOST “예약 취소”, BO “예약 취소 (관리자)”): 요약이 없어 추가하지 않습니다.
  - 방문완료·미방문·변경 수락·거절 모달: 예약 요약이 있으면 같은 규칙으로 상품명 줄을 더하고, 요약이 없으면 더하지 않습니다.
- BO 처리 모달: 위 “예약 처리 모달” 규칙과 같습니다.
- 예약 상세(드로어): HOST·BO 모두 5.9의 “예약 상품” 섹션만 둡니다. 위 카드 규칙(날짜 아래 큰 굵은 상품명)은 드로어에 쓰지 않습니다.

### 5.13 클리닉 스토어 예약 나이

- 규칙은 알리페이 채널 분기 PRD 11장 “예약 입력과 상담접수 폼”(FO-CH-13)의 클리닉 스토어 예약 나이와 같습니다.
  - 웹과 알리페이에 똑같이 적용합니다.
  - 대상, 기준(방문 예정일 기준 만 18세 이상), 판정 시점, 예약 변경 재판정, 막지 않는 것(상담접수·채팅, 매장(HOST)이나 운영자(BO)가 고객 대신 등록하거나 변경하는 예약), 한국어 알림 창 문구, 판정 결과 저장 안 함은 알리페이 채널 분기 PRD 11장을 따릅니다.
- 상품 예약에서 정하는 것
  - 상품마다 따로 정하지 않고 스토어 카테고리(피부과·성형외과·치과·메디컬체크)로 판정합니다. 스토어 예약과 상품 예약 모두 같습니다.
  - 웹에서는 예약자 정보 입력 화면의 예약 요청([Book])을 누를 때 판정합니다.
  - 클리닉이 아닌 스토어는 지금 규칙 그대로 예약할 수 있습니다.
- 알림 창 문구
  - 영어(2026-10-13 확정)
    - 제목: “Booking unavailable”
    - 본문: “This store accepts bookings only from guests aged 18 or older on the visit date.”
    - 버튼: “OK”
  - 중국어(간체)·중국어(번체)는 알리페이 채널 분기 PRD 15장 번역 문구표에서 정합니다.
  - 웹의 일본어·인도네시아어·몽골어 문구는 9장 후속에서 정합니다.

### 5.14 버튼 클릭수의 예약

- BO 상품 목록, 기획전, 인플루언서 기획전의 버튼 클릭수에 “예약하기”를 다른 버튼과 같은 방식으로 셉니다. 칸 이름은 BO 칼럼설정의 버튼 이름(“예약하기”)과 같습니다.
  - 세는 것: 고객이 상품 상세의 예약 버튼을 누른 횟수(웹·알리페이 모두). 예약을 끝까지 마쳤는지는 따지지 않습니다.
  - 칸 위치: 버튼 종류별 칸(상담접수·인앱채팅·외부링크·메신저 6종)의 맨 끝, 페이스북 다음에 “예약하기” 칸을 추가합니다.
  - “버튼 클릭수” 합계 칸에 예약 클릭도 더합니다.
  - 기획전·인플루언서 기획전은 대상 상품의 클릭수를 더합니다(다른 버튼과 같습니다).
- “예약하기”는 버튼을 누른 횟수, “예약수”는 접수된 예약 수입니다. 기존 “상담접수”(버튼)와 “상담수”(건수)의 짝과 같습니다.
- 스토어 페이지의 예약 버튼 클릭은 이번 범위에 넣지 않습니다(상품 단위 화면만 다룹니다).

### 5.15 스토어 문의 통계의 플랫폼 예약

BO 통계 > 스토어 문의 통계에 예약을 “문의 방식” 하나로 넣습니다.

- 이름 기준: 알리페이 채널 분기 PRD 11장이 이 화면의 기존 “채널구분 / 문의 채널”을 “문의 방식”으로 바꿉니다(도넛 카드 제목, 스토어별 집계 그룹 이름, 화면 부제, 차트 제목 “스토어별 문의 방식 분포”). 이 절은 바뀐 이름 기준으로 적습니다. 알리페이 1단계 배포 전에는 지금 이름(“채널구분”)에 같은 칸으로 들어갑니다.

- 이름: “플랫폼 예약”
- 세는 것
  - 플랫폼 안에서 고객이 접수한 예약 전부: 스토어 예약과 상품 예약, 웹·알리페이 어디로 들어왔든 모두 포함합니다.
  - 빼는 것: HOST 수기 예약(고객이 직접 넣은 예약이 아님), 외부 링크 예약(매장 쪽 사이트에서 끝나 플랫폼이 건수를 모름).
  - 기준일은 접수일입니다. 나중에 취소돼도 빼지 않습니다.
  - 플랫폼 예약 건도 예약에 기록된 유입 채널(웹 / 알리페이)을 함께 가집니다. 알리페이 채널 분기 PRD 11장의 유입 채널 필터·도넛·그룹 칼럼에도 같은 값으로 셉니다.
- 넣는 곳
  - 문의 방식 카드와 스토어별 집계 표의 문의 방식 그룹: 채팅문의·상담문의·메신저상담 다음에 “플랫폼 예약” 한 칸. 다른 문의 방식처럼 상품 / 스토어로 나누지 않습니다.
  - 문의구분(스토어 / 상품): 상품이 붙은 예약은 “상품”, 아니면 “스토어”에 더합니다.
  - 언어구분: 고객이 예약한 언어로 더합니다.
  - 총 문의 건수, 전체 문의 건수, 일별 문의 건수 추이, 스토어별 문의 방식 분포, TOP 10 스토어: 플랫폼 예약까지 합산합니다.
  - 상세 보기 탭
    - 플랫폼 예약 건도 일자(접수일)·스토어·문의 구분·언어 줄에 들어갑니다.
    - 문의 구분: 상품이 붙으면 “상품문의”, 아니면 “스토어문의”
    - 언어: 예약한 언어
    - 문의 상세: “플랫폼 예약”, 상세 건수: 그 건수
    - 총건수·구분 총건수·언어 건수에도 더합니다.
  - 엑셀 다운로드(이 화면에 이미 있음): 표와 같은 칸으로 받습니다.
- 바꾸지 않는 곳: 메신저구분, 메신저종류(메신저 문의만 셉니다).
- 기존 필터(일별 / 월별, 언어, 활성, 스토어 선택, 데이터 존재, 기간)는 그대로 적용합니다.

## 6. 예약 플로우 (요약)

- 상품 상세 진입
  - 상품 상세 [예약] → 예약 화면(상품 고정, 유입경로 “상품”) → 날짜·시간 → 로그인 → 예약자 정보 → 예약 요청([Book]) → (클리닉 스토어면 방문일 기준 만 18세 판정, 5.13) → 자리·마감·예약 설정·**상품 예약 가능 여부** 재확인 → 확정 → 상품 예약용 안내 발송
- 스토어 진입
  - 스토어 [예약] → 예약 화면(날짜·시간 아래 상품 선택, 처음엔 I'll decide at the store, 유입경로 “스토어”) → 이후는 같습니다.
  - 상품을 골랐으면 상품 예약용, 안 골랐으면 기존 스토어 예약용 안내 발송
- 예약하기 URL
  - 스토어 예약 URL은 스토어 진입, 상품 예약 URL은 상품 상세 진입과 같습니다(5.2).
- 수기 예약
  - HOST 문의 · 방문 예약 > 예약 현황 [수기등록] → 언어 선택 → 상품 선택(선택 사항, 고른 언어의 상품만) → 이후 기존 수기 예약과 같습니다.

## 7. 발송

- 상품이 붙은 예약은 상품 예약용 템플릿으로 보냅니다. 스토어 예약은 기존 템플릿을 그대로 씁니다.
- 기존 유형마다 상품 예약용을 하나씩 추가합니다. 달라지는 건 상품명이 들어가는 줄 하나입니다.

| 채널 | 받는 사람 | 상품 예약용 추가 유형 |
|---|---|---|
| 알림톡 | 스토어 담당자 | 새 예약 / 미확인 예약 / 예약 취소 / 예약 시간 변경 요청 / 예약 시간 변경 완료 |
| 이메일(6개 언어) | 웹 고객 | 확정 / 리마인더 / 취소 / 변경 / 거절 |
| 문자 | 웹 고객 | 확정 / 리마인더 / 취소 / 변경 / 거절(이메일과 같은 유형) |
| 문자 | 알리페이 회원 | 예약 확인 / 변경 / 취소 / 거절 / 방문 하루 전 |

- 알리페이 진입 관문을 끈 동안 알리페이 도메인에서 비로그인으로 예약한 고객은 웹 고객처럼 이메일을 받습니다(알리페이 채널 분기 PRD 11장·15장).
- 상품명은 예약에 저장해 둔 값(고객이 예약한 언어)을 씁니다.
- 스토어 담당자 알림톡은 영어 상품명을 함께 넣습니다.
  - 예약한 언어가 영어가 아니고, 같은 상품의 영어 상품이 있으면 “예약 언어 상품명 (영어 상품명)”으로 씁니다. 예: “Abijou ボトックス (Abijou Botox)”
  - 영어로 예약했거나 영어 상품이 없으면 예약 언어 상품명만 씁니다.
  - “같은 상품의 영어 상품”은 상품 그룹화(8장)로 묶인 영어 상품입니다. 그룹화 전에는 연결이 없어 예약 언어 상품명만 씁니다.
  - 상품명이 들어가는 자리는 하나이고, 값만 위 규칙으로 만듭니다.
- 고객에게 가는 이메일·문자는 예약한 언어 상품명만 씁니다.
- 새로 번역할 문구는 항목 이름 “상품” 하나입니다.
- 웹 고객 문자는 스토어 예약 PRD에 적힌 유형 기준이고, 지금 스토어 예약 문자가 나가는 유형마다 상품 줄을 더합니다.
  - 문자 언어는 지금 스토어 예약 문자와 같습니다(스토어 예약 PRD 기준).
  - 문자가 다국어로 나오면 이메일과 같은 언어별 항목 이름을 씁니다.
- 알리페이 회원 문자의 나머지 구성(링크 대신 예약번호, 방문 하루 전 발송 기준)은 알리페이 채널 분기 PRD 12장을 따릅니다.
- 알리페이 회원 문자의 상품 줄 항목 이름은 회원의 지금 언어(중국어(간체)·중국어(번체)·영어)를 따르고, 이메일과 같은 이름을 씁니다.

## 8. 상품 그룹화와의 관계

상품 그룹화(언어별 상품을 하나로 묶는 작업)는 다른 담당자가 진행 중입니다. 두 작업은 같이 나가도, 어느 쪽이 먼저 나가도 성립합니다.

- 상품 예약이 상품 정보에 주는 영향은 **언어별 상품의 예약 버튼 설정 하나**입니다. 의존은 상품 예약 → 상품 한 방향입니다.
- 그룹화 전
  - 예약은 언어별 상품을 가리킵니다.
  - 수기 예약 선택 칸에는 고른 언어의 상품만 나옵니다(5.7).
- 그룹화 후
  - 예약 버튼은 언어별 상품에 그대로 남습니다.
  - 수기 예약 선택 칸은 그룹 단위로 합쳐지고, 저장하는 상품 정보(5.4)는 고른 언어의 상품 것입니다. 그룹에 그 언어 상품이 없으면 고를 수 없습니다.
  - 그룹화 때 상품 번호가 바뀌어 끊기는 연결은 그룹화 작업에서 직접 다시 잇습니다.
  - 예약에 저장해 둔 상품 정보는 그룹화와 상관없이 그대로 남습니다.
  - 스토어 알림톡의 영어 상품명(7장)은 그룹화 뒤부터 붙습니다.
