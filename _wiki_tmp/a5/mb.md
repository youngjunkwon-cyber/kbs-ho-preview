# 알리페이 회원정보 연동 및 알리페이 홍콩 연동 개발 전달 (v1.0)

알리페이 이용자가 따로 가입하지 않고 알리페이 계정으로 바로 예약하게 하는 작업입니다. 진입 동의를 관문으로 두고, 프로필을 필수로 받고, 예약 알림은 우리 문자로 보냅니다. 알리페이 홍콩에서도 같은 방식으로 들어와 회원으로 식별되게 합니다. 규칙 전문(PRD v1.0)은 9장에 그대로 있어 이 문서만 읽으면 됩니다.

진입 관문은 알리페이 앱 이용자를 도메인(alipay-app.kbstations.com)으로 구분하므로 「알리페이 채널 분리 관리 PRD v1.0」의 배포 순서와 상관없이 켤 수 있습니다. 유입 채널 표시는 그 문서가 담당합니다.

## 1. 무엇을 만드는가

화면 ID는 9개입니다. 어드민 1, 고객 화면 6, 공통 처리 2입니다. 새 화면은 어드민 알리페이 회원 목록(BO-CH-11), 진입 차단 화면(FO-CH-08), 진입 동의 창(FO-CH-09) 셋이고, 나머지는 기존 화면 수정과 데이터 처리입니다.

- 알리페이 채널에 들어오면 알리페이 계정 식별자를 받아 별도 로그인 없이 회원을 식별합니다. 진입 동의와 알리페이 권한 허용을 통과해야 이용할 수 있습니다
- 알리페이에서 이름, 닉네임, 성별, 생년월일, 국적을 받아 회원 정보에 채우고, 예약 입력과 계정 설정에 씁니다. 휴대폰 번호는 알리페이에서 받지 않고 첫 예약이나 계정 설정에서 직접 입력받아 문자 인증합니다
- 알리페이 회원은 이메일이 없습니다. 예약·상담접수 폼에서 이메일 칸을 빼고, 예약 알림은 우리 문자로 보냅니다
- 어드민 회원 메뉴 아래에 알리페이 회원 목록을 새로 둡니다
- 알리페이 홍콩 연동은 진입 경로(/zh-TW) 확인, 월렛 판별과 홍콩 회원 식별, 권한 해제(revoke), 테스트 계정, 검색 키워드 등재까지입니다

## 2. 지금 동작이 바뀌는 항목

가장 먼저 봐 주세요. 모두 알리페이 도메인(alipay-app.kbstations.com)의 동작이고, 웹 회원의 화면과 알림은 현행 그대로입니다.

- 알리페이 채널은 진입 동의를 통과해야 이용할 수 있습니다. 둘러보기는 없습니다
- 자체 로그인, 회원가입, 소셜 로그인, 비밀번호 찾기로 가는 모든 자리를 숨깁니다
- 예약 입력과 상담접수 폼에 이메일 칸이 없고, 회원 정보로 칸을 채웁니다
- 예약 알림은 이메일 대신 우리 문자로 갑니다. 예약 완료 화면의 이메일 발송 문장은 알리페이 회원에게 문자 발송 문장으로 바뀝니다
- 마이페이지와 계정 설정에 이메일, 비밀번호 변경, 로그아웃, 이름 칸이 없고, 마케팅 정보 수신 토글이 생깁니다
- 진입 관문 스위치를 끄면 다음에 웹뷰를 새로 열 때부터 지금의 알리페이 도메인 비로그인 동작으로 돌아갑니다(6장)

## 3. 읽는 순서

1. 이 문서 1~8장. 무엇을 만드는지, 바뀌는 동작, 핵심 규칙, 배포
2. 9장 PRD 전문. 화면 문구, 권한 표, 알리페이 확인 사항의 전문
3. 9장 PRD의 부록 A. QA 체크리스트

문서끼리 다르게 읽히면 9장 PRD를 따르고 기획에 알려 주세요.

## 5. 핵심 규칙

진입 관문

- 순서: 알리페이에서 계정 식별자를 받습니다(auth_base) → 우리 동의 창(FO-CH-09)에서 필수 셋에 동의하고 "동의하고 시작하기" → 알리페이 권한 요청(getAuthCode)으로 알리페이 권한 창 → 요청한 필수 권한이 모두 허용되면 사용자 정보 조회 → 회원을 만들고 로그인
- 알리페이 호출: 월렛 판별은 getSiteInfo·getSystemInfo, 계정 식별과 권한 요청은 같은 getAuthCode에 요청 범위(auth_base, 프로필 권한)만 다르게 보냅니다. 웹뷰 안의 웹페이지는 이 호출을 직접 부를 수 없어, 미니프로그램이 호출하고 결과를 웹페이지로 전달합니다(postMessage/onMessage). 서버는 applyToken으로 이용 허가 토큰을 받고, inquiryUserInfo로 사용자 정보를 조회합니다(둘을 합친 applyTokenAndInquiryUserInfo도 가능). 서버 호출(applyToken, inquiryUserInfo, revoke)에는 월렛 값을 customerBelongsTo로 함께 보냅니다(필수). 단계별 표는 9장 PRD 4장에 있고, 요청 값과 응답 칸의 세부는 알리페이 미니프로그램 개발자 문서를 따릅니다
- 회원을 만들 때 웹 회원 가입과 같은 처리를 적용합니다(지금은 가입 혜택이 없습니다). 이메일이 없어 환영 메일은 보내지 않습니다
- 우리 동의 창과 알리페이 권한 창은 합칠 수 없습니다. 알리페이 권한 창은 알리페이가 그리는 화면입니다
- 동의 창 "닫기", 필수 권한 거부(권한 요청이 오류 11·1001로 끝난 경우 포함), 식별 실패(권한 허용 뒤 우리 쪽 처리 실패 포함)는 진입 차단 화면(FO-CH-08)에 머뭅니다. 화면마다 제목·안내·버튼 문구가 다르고, 문구는 9장 PRD 4장에 있습니다
- 진입 차단 화면은 헤더·메뉴·검색이 없는 전체 화면이고, 버튼은 "다시 동의하기" 또는 "다시 시도" 하나입니다
- 이미 동의를 마친 회원은 다음 진입부터 동의 창을 보지 않습니다
- 동의와 동의 시각은 회원을 만들기 전까지 접속 상태에 임시로 두고 회원을 만들 때 기록합니다. 그전에 창이나 웹뷰를 닫으면 버립니다
- 창과 화면의 언어는 들어온 주소의 언어를 따릅니다

권한과 프로필

- 알리페이 중국은 권한을 묶음 하나(auth_user)로 요청하고, 허용되면 통과합니다. 알리페이 홍콩은 USER_NAME, USER_NICKNAME, USER_GENDER, USER_BIRTHDAY, USER_NATIONALITY 다섯을 항목별로 요청하고(항목별 권한 지원은 홍콩 테스트 계정으로 확인한 뒤 확정), 하나라도 거부하면 진입 차단 화면입니다. 받는 항목과 동의 창 문구는 두 월렛이 같습니다
- 월렛이 주지 않는 권한은 처음부터 요청하지 않습니다. 진입 차단은 이용자가 직접 거부했을 때만이고, 요청한 항목의 값이 오지 않으면 빈 채로 둡니다. 월렛별로 실제로 오지 않는 항목은 홍콩 테스트 계정으로 확인합니다
- 아바타, 주소, 연락처(USER_CONTACTINFO), 휴대폰 번호 원본(PLAINTEXT_MOBILE_PHONE), 이메일, 알리페이 로그인 ID 원본은 요청하지 않습니다
- 프로필은 진입 동의 때 한 번 받고 다시 동기화하지 않습니다. 알리페이 계정에 값이 없는 항목은 비워 둡니다
- 예약 입력에서 고친 국적·성별·생년월일과 여권 영문명은 칸을 벗어나는 순간(올바른 값만. 비운 칸은 덮어쓰지 않습니다), 계정 설정에서 고친 값은 저장을 누를 때 회원 정보를 덮어씁니다. 휴대폰 번호는 예약에서는 예약 요청을 보낼 때, 계정 설정에서는 문자 인증을 마친 때 덮어씁니다
- 인증한 휴대폰 번호는 회원 정보에 저장되어 두 번째 예약부터 채워지고 인증을 건너뜁니다. 채워진 번호는 계정 설정에 가지 않고 예약 입력에서 바로 고칠 수 있습니다(현행 예약 폼 그대로 "다른 번호 사용" 버튼과 문자 인증). 계정 설정의 "다른 번호 사용" 버튼도 그대로입니다. 같은 번호를 다른 회원이 인증했어도 막지 않습니다

식별과 계정

- 회원은 월렛과 알리페이 식별자의 조합으로 식별합니다. 식별자는 계정 식별(applyToken) 응답의 customerId를 저장하고, 사용자 정보 조회의 userInfo.userId와 같은 값인지 중국·홍콩 테스트로 확인합니다. 이 조합은 탈퇴하지 않은 회원 사이에서만 고유하고, 진입 때 탈퇴 회원은 빼고 찾습니다. 탈퇴 뒤 다시 들어오면 새 회원입니다
- 월렛(알리페이 중국/알리페이 홍콩)은 알리페이 응답의 월렛 값으로 정해 진입 때 저장합니다. getSiteInfo의 customerBelongsTo를 쓰고, 없으면 getSystemInfo의 app 값(alipay는 ALIPAY_CN, alipayHK는 ALIPAY_HK)으로 정합니다. 둘 다 없으면 진입 경로로 정합니다(/zh는 알리페이 중국, /zh-TW는 알리페이 홍콩, 그 밖의 경로로 첫 진입하면 알리페이 중국). 진입 경로로 정한 월렛으로 서버 호출이 실패하면 다른 월렛으로 한 번 더 시도합니다
- 웹뷰를 새로 열 때마다 알리페이 계정을 다시 식별합니다. 같은 웹뷰 안의 새로고침과 화면 이동, 앱 전환 뒤 복귀는 새로 열기가 아닙니다. 식별한 계정이 직전과 다르면 앞 회원 상태를 끊고 새 회원으로 로그인합니다. 진입 때 웹 계정으로 로그인한 상태가 남아 있으면 그 로그인은 끊고 알리페이 회원으로 로그인합니다
- 이미 가입한 회원이 다시 들어오면 알리페이 계정 식별만으로 로그인 상태가 됩니다. 권한 상태를 다시 확인하지 않고 프로필도 다시 받지 않습니다. 이용자가 알리페이에서 권한을 끊어도 받아 둔 회원 정보로 이용합니다
- 화면 언어는 들어온 주소의 언어입니다. 회원 정보에 저장된 언어는 가입 때 진입 주소의 언어로 시작하고 회원이 직접 바꿀 때만 갱신하며, 문자는 저장된 언어로 보냅니다
- 로그인 없이 시작한 채팅방은 새 알리페이 회원에게 넘기지 않고, 매장 쪽 기록은 그대로 둡니다
- 딥링크로 들어와 식별과 동의를 거치면 원래 가려던 화면으로 돌려보냅니다
- 월렛마다 식별자가 다르면 별도 회원입니다. 웹 회원과 같은 사람이어도 계정을 합치지 않습니다
- 알리페이 회원은 기존 회원 관리 화면에 나오지 않고 알리페이 회원 목록에만 나옵니다. 회원번호는 기존 회원과 겹치지 않고, 회원 수 같은 집계는 두 회원을 합쳐 셉니다. 데이터는 기존 회원과 같은 회원 데이터에 두고 알리페이 회원 구분 값을 둡니다

회원 화면

- 자체 로그인 경로를 숨기고(FO-CH-10), 진입 관문이 켜져 있을 때 로그인 화면 주소로 직접 들어오면 마이페이지로 보냅니다
- 마이페이지 위쪽은 닉네임(비어 있으면 "알리페이 회원")과 가입일이고, 그 아래 한 줄 "알리페이 계정으로 로그인했습니다. K-Beauty Station 계정과는 별개입니다."를 둡니다
- 계정 설정은 여권 영문명, 국적·성별, 생년월일, 휴대폰 번호, 연락 메신저와 저장 버튼입니다. 연락 메신저 칸은 현행 웹 계정 설정과 같습니다. 이메일, 비밀번호 변경, 로그아웃, 이름 칸은 없습니다
- 마케팅 정보 수신 토글(화면 이름 "Marketing messages")은 켜고 끌 때마다 동의 또는 거부를 시각과 함께 남깁니다
- 탈퇴는 기존 탈퇴 경로를 씁니다. 방문 일시가 지나지 않은 예약이 남아 있으면 탈퇴할 수 없습니다. 탈퇴하면 알리페이 식별자와의 연결을 끊습니다. 알리페이 홍콩 회원은 권한도 해제(revoke)하고, 알리페이 중국은 권한 해제를 지원하지 않아 우리 쪽 연결만 끊습니다. 해제에는 프로필 권한 때 받은 이용 허가 토큰을 쓰고, 이 토큰과 갱신 토큰은 계정 식별 때 받는 토큰과 따로 저장합니다. 만료되었으면 갱신 토큰으로 새로 받아 한 번 다시 시도하고, 그래도 안 되면 해제를 건너뜁니다. 해제가 실패해도 탈퇴는 진행합니다. 다시 들어오면 새 회원입니다
- 리뷰 작성자명과 채팅에 보이는 이름은 닉네임이고, 닉네임이 비면 "알리페이 회원"입니다. 알리페이 식별자는 고객 화면에 보이지 않습니다

예약 입력과 상담접수 폼

- 이메일 칸을 두지 않습니다. 국적·성별·생년월일을 회원 정보에서 채우고 "회원 정보에서 채웠습니다"를 표시하며, 이용자가 고칠 수 있습니다. 이름 칸은 없습니다
- 여권 영문명은 직접 입력받습니다. 메신저 연락처 입력은 현행 그대로 필수이고 매번 빈 칸입니다. 메신저 칸 옆 앱 열기 버튼은 이 화면에서 직접 숨기므로 「알리페이 채널 분리 관리 PRD v1.0」 4단계 배포 여부와 상관없이 숨겨집니다
- 필수값이 모두 채워지고 휴대폰 번호 인증을 마쳐야 예약 요청 버튼이 켜집니다
- 동의 항목 영역은 웹 예약 폼과 같고 이 기능에서 바꾸지 않습니다
- 예약 변경 화면도 이메일 칸이 없고, 휴대폰 번호 규칙은 예약 입력과 같습니다. 인증 문자 재전송은 웹과 같은 규칙입니다
- 예약 완료 화면은 현행 그대로이고 "We sent the confirmation details to your email"만 알리페이 회원에게 "We sent the confirmation details by text message"로 바꿉니다
- 상담접수 폼의 이름과 휴대폰 번호는 회원 정보 값으로 채우고 이용자가 고칠 수 있습니다. 고친 값은 회원 정보를 덮어쓰지 않습니다
- 예약은 지금의 무결제 예약 그대로이고, 노쇼 등 운영 기준도 같습니다

어드민 알리페이 회원 목록

- 화면 제목 "알리페이 회원". 상세 화면과 엑셀 다운로드는 두지 않습니다
- 칼럼은 회원번호, 가입일, 마지막 로그인, 알리페이 식별자, 유입 채널, 닉네임, 이름, 성별, 생년월일, 국적, 언어, 연락처, 여권명, 예약, 노쇼, 프로필 동의 일자, 마케팅 활용 정보(동의 여부, 동의 일자)입니다
- 필터는 가입 기간, 가입 시작일과 종료일, 탈퇴 여부(기본 미탈퇴), 유입 채널, 마케팅 수신 여부, 검색어입니다. 유입 채널 값은 회원이 가입한 월렛(알리페이 중국 / 알리페이 홍콩)입니다
- 알리페이 식별자는 가리지 않고 전부 보여주고, 검색은 완전 일치입니다. 탈퇴 여부를 전체로 두면 같은 식별자가 여러 행일 수 있습니다
- 예약은 그 회원 이름으로 잡힌 예약만 셉니다. 언어는 회원 정보에 저장된 언어입니다. 화면 권한과 검색 방식은 기존 회원 화면과 같습니다

알림 발송

- 알리페이 회원의 예약 알림은 우리 문자로 보냅니다. 이메일, 알리페이 알림(푸시·문자·메시지함)과 알림 발송 권한(SEND_MESSAGE)은 쓰지 않습니다
- 알림은 예약 확인, 예약 변경, 예약 취소, 예약 거절, 방문 하루 전(전날 한국 시간 오전 10시) 다섯입니다. 변수는 예약번호, 스토어명, 일시, 주소이고, 언어는 회원 정보에 저장된 언어입니다. 보내는 시점은 지금 웹 이메일이 나가는 시점과 같습니다
- 받는 번호는 그 예약에 저장된 번호입니다. 발송 실패는 발송 요청 실패와 통신사 수신 실패를 모두 뜻합니다. 발송이 실패하면 5분 뒤 한 번 다시 보내고, 그래도 실패하면 어드민·호스트 예약 상세에 "문자를 보내지 못했습니다."를 보입니다
- 예약번호는 웹과 같은 규칙과 같은 일련 카운터를 씁니다
- 마케팅 문자는 운영이 직접 보냅니다. 개발 범위는 동의 받기·기록과 어드민 알리페이 회원 목록에서 동의한 회원과 연락처를 확인하는 것까지이고, 발송 기능은 만들지 않습니다. 기존 발송 시간 제한(한국 시간 오후 9시부터 다음 날 오전 8시 사이 금지)과 수신 거부 규칙은 그대로입니다

## 6. 배포

- 진입 관문은 알리페이 앱 이용자를 도메인(alipay-app.kbstations.com)으로 구분하므로 「알리페이 채널 분리 관리 PRD v1.0」의 배포 순서와 상관없이 켤 수 있습니다
- BO-CH-11은 진입 관문을 처음 켜기 전에 배포합니다
- 진입 관문을 처음 켤 때 「알리페이 채널 분리 관리 PRD v1.0」의 회원 연동 뒤 적용 항목을 함께 적용합니다. 리뷰의 유입 채널을 알리페이 회원은 가입한 월렛으로 표시, 이메일 칼럼의 알리페이 회원 건은 하이픈, 어드민 목록에서 회원 정보에 이름이 없을 때 알리페이 식별자 표시, 예약자 설문조사의 이메일은 알리페이 회원 건에서 하이픈입니다
- 진입 관문 스위치가 FO-CH-08·09·11·12·13과 SYS-CH-04·05를 켜고 끕니다. FO-CH-10(자체 로그인 경로 숨김)은 별도 저장 값으로 두고 진입 관문을 처음 켤 때 함께 켜며, 진입 관문을 꺼도 유지합니다
- 진입 관문은 아래 선행 작업을 모두 마친 뒤 스위치로 켭니다. 기한은 모두 진입 관문을 켜기 전입니다
  - 개발: 미니프로그램 코드 수정(web-view 진입 주소, getAuthCode·getSystemInfo·getSiteInfo 결과를 웹페이지로 전달하는 연결 코드), 새 버전 업로드, 홍콩 항목별 권한 지원 확인과 홍콩 요청 권한 확정, customerId와 userInfo.userId 일치 확인(중국·홍콩 테스트), 콘솔 설정 세 가지(기능(Features)에 사용자 인증 기능(App user authorization) 추가, 개발 설정(Development Configuration)에 가맹점 공개 키 등록, 알리페이 중국 API 호출 위임)
  - 기획: 미니프로그램 심사 요청(중국 영업일 2일, 홍콩 최소 영업일 3일, 첫 출시는 1주 이상), 홍콩 테스트 계정 요청(사용 1주 전 신청, 3일 사용), 홍콩 검색 키워드 신청, 개인정보 처리방침·이용약관 개정 게시, 약관·처리방침의 중국어(간체)·중국어(번체)·영어 전문 준비, 고객 화면 새 문구 번역 문구표
  - 운영: 월 문자 비용 추정, 고객센터 대리 처리 절차 공유
- 진입 주소(/zh-TW 등) 변경, 웹페이지 연결 코드, 사용자 인증 기능 반영은 미니프로그램 새 버전 업로드와 심사를 거칩니다
- 스위치는 어드민 화면 없이 서버 구성 값으로 둡니다. 운영자가 요청하면 개발이 배포 없이 바꾸고, 반영은 60초 안입니다. 켜고 끈 시각과 요청자를 기록합니다
- 스위치를 끄면 다음에 웹뷰를 새로 열 때부터 알리페이 채널이 비로그인 상태로 돌아가고, 로그인이 필요한 기능(북마크, 리뷰 작성, 쿠폰)은 숨깁니다. 자체 로그인 경로 숨김은 유지하고 로그인·마이페이지 주소는 홈으로 보냅니다. 예약·상담접수는 지금 알리페이 도메인의 비로그인 동작(이메일 칸 포함)입니다. 만든 회원은 그대로 두고 예약 알림 문자는 그대로 보냅니다. 마케팅 문자는 보내지 않고, 탈퇴와 마케팅 수신 거부 요청은 고객센터가 대신 처리합니다. 다시 켜면 같은 계정을 그 회원으로 식별합니다
- 롤백은 진입 관문 스위치를 끄는 것입니다. 이미 만들어진 회원은 그대로 둡니다
- STG의 알리페이 채널 주소와 미니프로그램 안에서 테스트 서버를 여는 방법은 확정 전이고 개발이 정해 공유합니다

### 1. 요구사항

- 알리페이 회원 정보 연동을 진행합니다.
  - 진입 동의를 관문으로 두고, 프로필을 필수로 받습니다.
  - 착수 조건은 4장과 같습니다.
- 예약 알림은 우리 문자로 보냅니다.
  - 이메일은 쓰지 않습니다.
- 알리페이 결제는 이번 범위에서 뺍니다.
  - 예약은 지금의 무결제 예약 그대로 받습니다.
- 알리페이 홍콩 연동은 진입 경로(/zh-TW) 확인, 월렛 판별과 홍콩 회원 식별, 권한 해제(revoke), 테스트 계정, 검색 키워드 등재까지입니다.
  - 주소 경로 연결과 언어 목록은 「알리페이 채널 분리 관리 PRD v1.0」 9장에서 배포하고, 이 문서는 미니프로그램 진입 주소 변경과 동작 확인만 합니다(7장·8장).
  - 홍콩 결제는 범위 밖입니다.

### 2. 알리페이 앱 안의 제약

- 알리페이 앱 안에서 외부 링크·타 메신저 앱 이동이 막히는 제약과 운영 방침은 「알리페이 채널 분리 관리 PRD v1.0」 3장에 있습니다.
- 알리페이 사용자 정보는 우리가 알리페이 콘솔에 사용자 인증 기능(App user authorization)을 추가하면 쓸 수 있습니다(8장 콘솔 할 일). 알리페이의 별도 승인은 필요 없습니다.
  - 사용자 인증 기능은 미니프로그램 새 버전 업로드와 심사를 거쳐 반영됩니다(7장).
  - 받는 항목은 이름, 닉네임, 성별, 생년월일, 국적 다섯입니다. 휴대폰 번호는 알리페이에서 받지 않고 첫 예약이나 계정 설정에서 직접 입력받아 문자 인증합니다(4장).
  - 요청하는 권한 목록은 4장, 알리페이에 확인할 사항은 8장에 있습니다.

### 3. 용어

| 월렛 | 알리페이 앱의 지역 구분. 월렛(알리페이 중국/알리페이 홍콩) 두 가지이고, 채널로는 둘 다 알리페이 앱 하나입니다. 알리페이 응답에서 월렛을 알려 주는 값을 “월렛 값”이라 합니다. 월렛별 진입 주소는 「알리페이 채널 분리 관리 PRD v1.0」 9장 |

### 4. 회원 정보 연동

SYS-CH-04 / FO-CH-08 ~ FO-CH-13 / BO-CH-11

착수: 알리페이 웹뷰에서 계정 권한 요청(getAuthCode)을 쓸 수 있다는 알리페이 회신을 받았습니다(8장).

- 알리페이는 월렛마다 주는 사용자 정보가 다를 수 있어 알리페이 식별자로 회원을 식별하라고 권했습니다.
  - 식별자는 계정 식별(applyToken) 응답의 customerId를 저장합니다.
  - 사용자 정보 조회 응답의 userInfo.userId와 같은 값인지 중국·홍콩 테스트로 확인합니다(7장).
- 유입 채널(BO-CH-12, HOST-CH-03)은 회원 연동 없이 채널 기록값만 쓰므로 「알리페이 채널 분리 관리 PRD v1.0」 10장에서 1단계에 배포합니다.

- 알리페이 계정 식별자를 받아 별도 로그인 없이 회원을 식별합니다.
  - 회원은 월렛과 알리페이 식별자(customerId)의 조합으로 식별합니다.
    - 이 조합은 탈퇴하지 않은 회원 사이에서만 고유합니다.
    - 진입 때 회원을 찾을 때는 탈퇴 회원을 빼고 찾습니다. 그래서 탈퇴한 뒤 다시 들어오면 새 회원입니다.
  - 월렛(알리페이 중국/알리페이 홍콩)은 알리페이 응답의 월렛 값으로 정해 진입 때 저장합니다.
    - 월렛 값은 getSiteInfo로 받는 customerBelongsTo(ALIPAY_CN, ALIPAY_HK)입니다.
    - 이 값이 없으면 getSystemInfo의 app 값으로 정합니다. alipay는 ALIPAY_CN, alipayHK는 ALIPAY_HK입니다.
    - 둘 다 없으면 진입 경로로 정합니다.
    - /zh로 들어오면 알리페이 중국, /zh-TW로 들어오면 알리페이 홍콩, 그 밖의 경로(/en 등)로 첫 진입하면 알리페이 중국입니다.
    - 진입 경로로 정한 월렛으로 서버 호출이 실패하면 다른 월렛으로 한 번 더 시도하고, 성공한 월렛을 저장합니다.
  - 서버 호출(applyToken, inquiryUserInfo, revoke)에는 이 월렛 값을 customerBelongsTo로 함께 보냅니다. 알리페이가 필수로 받는 값입니다.
  - 화면 언어는 들어온 주소의 언어를 따릅니다.
    - 회원 정보에 저장된 언어는 가입 때 진입 주소의 언어로 시작하고, 회원이 언어를 직접 바꿀 때만 갱신합니다.
    - 알림 문자는 저장된 언어로 보냅니다.
- 알리페이 회원은 어드민에서 기존 회원과 따로 보입니다.
  - 데이터는 기존 회원과 같은 회원 데이터에 두고, 알리페이 회원을 가리는 구분 값을 둡니다.
  - 기존 회원 관리 화면에는 나오지 않고 알리페이 회원 목록(BO-CH-11)에 나옵니다.
  - 기존 회원 가입은 이메일과 비밀번호를 필수로 받는데 알리페이 회원은 둘 다 없습니다.
    - 기존 회원 가입의 필수 조건은 그대로 두고 알리페이 회원에게만 적용하지 않습니다.
  - 알리페이 회원의 회원번호는 기존 회원의 회원번호와 겹치지 않습니다.
    - 회원 수 같은 집계는 두 회원을 합쳐 하나로 셉니다.
  - 예약·채팅·상담·리뷰 화면에 건마다 어느 채널로 들어왔는지 보여주는 “유입 채널”은 「알리페이 채널 분리 관리 PRD v1.0」 10장에 있습니다.

#### 진입 관문

- 알리페이 채널은 진입 동의를 통과해야 이용할 수 있습니다.
  - 둘러보기는 없습니다.
- 진입 순서는 다음과 같습니다.
  - 가. 알리페이에서 계정 식별자를 받습니다(auth_base).
  - 나. 우리 동의 창(FO-CH-09)을 띄웁니다.
    - 필수 셋에 동의하고 “동의하고 시작하기”를 누릅니다.
  - 다. 알리페이 권한 요청(getAuthCode)을 보내면 알리페이가 권한 창을 띄웁니다.
  - 라. 요청한 필수 권한(아래 표)이 모두 허용되면 사용자 정보를 조회합니다.
  - 마. 회원을 만들고 로그인합니다.
    - 회원을 만들 때 웹 회원 가입과 같은 처리를 적용합니다(지금은 가입 혜택이 없습니다).
    - 이메일이 없어 환영 메일은 보내지 않습니다.
- 단계별 알리페이 호출은 아래 표와 같습니다.

| 단계 | 미니프로그램 쪽 호출(결과를 웹페이지로 전달) | 서버 쪽 호출 | 받는 값 | 실패 때 화면 |
|---|---|---|---|---|
| 월렛 판별 | getSiteInfo, getSystemInfo | 없음 | customerBelongsTo(ALIPAY_CN, ALIPAY_HK), app 값(중국 alipay, 홍콩 alipayHK) | 차단하지 않고 진입 경로로 정합니다 |
| 가. 계정 식별 | getAuthCode(요청 범위 auth_base) | applyToken(/v2/authorizations/applyToken, 인증 코드로 이용 허가 토큰 받기) | 이용 허가 토큰, 알리페이 식별자(customerId) | 식별 실패 |
| 다. 권한 요청 | getAuthCode(요청 범위 프로필 권한. 중국 auth_user, 홍콩 항목별 권한) | 없음 | 인증 코드, 허용된 권한(authSuccessScopes), 거부된 권한(authErrorScopes) | 필수 권한 거부. 오류 11(authorization is cancelled)·1001(user cancels)도 필수 권한 거부입니다. 그 밖에 호출 자체가 실패하면 식별 실패 |
| 라. 사용자 정보 조회 | 없음 | applyToken(새 인증 코드로 이용 허가 토큰과 갱신 토큰 받기) 뒤 inquiryUserInfo(/v2/users/inquiryUserInfo, 토큰으로 사용자 정보 조회). 두 호출을 합친 applyTokenAndInquiryUserInfo(/v2/authorizations/applyTokenAndInquiryUserInfo)를 써도 됩니다 | 이름, 닉네임, 성별, 생년월일, 국적, userInfo.userId | 식별 실패 |
| 탈퇴 때 권한 해제(홍콩 월렛만) | 없음 | 권한 해제(revoke). 라.에서 받은 이용 허가 토큰을 씁니다 | 처리 결과 | 화면 변화 없음. 실패해도 탈퇴는 진행합니다 |

- 웹뷰 안의 웹페이지는 getAuthCode·getSystemInfo·getSiteInfo를 직접 부를 수 없습니다(알리페이 web-view 문서).
  - 웹페이지가 요청하면 미니프로그램이 호출하고 결과를 웹페이지로 전달합니다(postMessage/onMessage).
  - 이 연결 코드는 미니프로그램 코드 수정에 들어가고, 새 버전 업로드와 심사를 거칩니다(7장).
- 서버 쪽 호출에는 월렛 값을 customerBelongsTo로 함께 보냅니다(위 월렛 판별).
- 호출 이름은 알리페이 미니프로그램 개발자 문서(Alipay Connect)의 v2 API 기준입니다. 요청 값과 응답 칸의 세부는 같은 문서를 따릅니다. 사용자 정보 조회 API는 콘솔에 사용자 인증 기능(App user authorization)을 추가해야 쓸 수 있습니다.
- 우리 동의 창과 알리페이 권한 창은 합칠 수 없습니다.
  - 알리페이 권한 창은 알리페이가 그리는 화면입니다.
  - 그래서 우리 쪽은 모달 하나로 줄이고 그 뒤에 알리페이 창이 한 번 붙는 형태입니다.
- 진입 차단 화면(FO-CH-08)에 머무는 경우
  - 동의 창에서 “닫기”를 누른 경우
    - 동의 창에는 거부 버튼이 없고 “닫기”만 있습니다.
  - 알리페이 권한 창에서 필수 권한을 하나라도 거부한 경우
    - 권한 요청이 오류 11(authorization is cancelled)이나 1001(user cancels)로 끝난 경우도 같습니다.
  - 식별 실패
- 식별 실패에는 이용자가 권한을 허용했는데 우리 쪽 처리(알리페이에서 받은 권한 확인, 사용자 정보 조회)가 실패한 경우도 들어갑니다.
- 통과하는 경우: 필수 권한을 모두 허용하면 통과합니다. 알리페이 중국은 auth_user가 허용되면 통과입니다.
- 7장 선행 작업(콘솔 설정, 미니프로그램 새 버전 업로드와 심사 포함)을 마친 뒤에 켭니다.
  - 사용자 인증 기능이 없는 상태의 예외 처리는 두지 않습니다.
- 진입 관문은 스위치로 켜고 끕니다(7장).
  - 끄면 다음에 웹뷰를 새로 열 때부터 알리페이 채널은 비로그인 상태이고, 이미 만든 회원은 그대로 둡니다.
  - 로그인이 필요한 기능(북마크, 리뷰 작성, 쿠폰)은 숨깁니다.
  - 꺼도 자체 로그인 경로 숨김(FO-CH-10)은 유지해 로그인 없이 쓰는 상태가 됩니다.
  - 로그인·마이페이지 주소로 들어오면 홈으로 보냅니다.
  - 예약·상담접수는 지금 알리페이 도메인의 비로그인 동작(이메일 칸 포함)으로 돌아갑니다.
  - 이미 만든 회원의 예약 알림 문자는 그대로 보냅니다.
  - 마케팅 문자는 보내지 않습니다.
  - 알리페이 회원의 탈퇴와 마케팅 수신 거부 요청은 고객센터가 대신 처리합니다.
  - 다시 켜면 같은 알리페이 계정은 그 회원으로 식별합니다.

#### 요청하는 권한

월렛별 요청 권한

| 월렛 | 요청하는 권한 | 통과 판정 |
|---|---|---|
| 알리페이 중국 | 묶음 하나(auth_user)로 요청합니다 | auth_user가 허용되면 통과 |
| 알리페이 홍콩 | 항목별로 요청합니다(아래 표의 USER_NAME 등 다섯). 항목별 권한 지원은 홍콩 테스트 계정으로 확인한 뒤 확정합니다(7장) | 요청한 항목이 모두 허용되면 통과 |

받는 항목

| 항목 | 홍콩 권한 이름 | 구분 | 비고 |
|---|---|---|---|
| 이름 | USER_NAME | 필수 | 성·이름 또는 전체 이름 |
| 닉네임 | USER_NICKNAME | 필수 | 리뷰·채팅 표시명 |
| 성별 | USER_GENDER | 필수 | F/M 기준입니다. MALE/FEMALE로 와도 같은 값으로 처리합니다. 여성/남성으로 표시 |
| 생년월일 | USER_BIRTHDAY | 필수 | ISO 날짜로 옵니다 |
| 국적 | USER_NATIONALITY | 필수 | 두 글자 국가코드로 옵니다. 국가 이름으로 표시 |

- 받는 항목은 두 월렛 모두 위 표의 다섯이고, 진입 동의 창의 프로필 제공 문구도 두 월렛이 같습니다.
- 필수 권한은 알리페이 중국은 auth_user 하나, 알리페이 홍콩은 위 표의 다섯입니다.
  - 월렛이 주지 않는 권한은 처음부터 요청하지 않습니다.
  - 진입 차단은 이용자가 권한 창에서 필수 권한을 직접 거부했을 때만입니다. 요청한 항목의 값이 오지 않으면 막지 않고 빈 채로 둡니다.
  - 월렛별로 실제로 오지 않는 항목은 홍콩 테스트 계정으로 확인합니다(7장).
- 받지 않는 것: 아바타, 주소, 연락처(USER_CONTACTINFO), 휴대폰 번호 원본(PLAINTEXT_MOBILE_PHONE), 이메일.
  - 아바타와 주소는 쓰는 곳이 없습니다.
  - 휴대폰 번호는 알리페이에서 받지 않고 첫 예약이나 계정 설정에서 직접 입력받아 문자 인증합니다. 연락처 권한으로 오는 가려진 번호와 이메일은 쓰지 않기 때문입니다.
  - 홍콩 월렛은 원본 번호가 가려지거나 오지 않을 수 있다는 알리페이 회신도 근거입니다.
- 알리페이 로그인 ID 원본 권한은 요청하지 않습니다.
  - 어드민 회원 목록에도 로그인 ID 칼럼을 두지 않습니다.
  - 알리페이 쪽에 이용자 확인을 요청할 때는 알리페이 식별자를 쓰고, 고객센터는 예약번호와 휴대폰 번호로 확인합니다.

#### 프로필 처리

- 이름·닉네임·성별·생년월일·국적을 회원 정보에 채웁니다.
  - 알리페이 계정에 값이 없는 항목은 빈 채로 둡니다.
  - 그중 국적·성별·생년월일은 예약 입력에서 직접 받습니다(이름·닉네임은 예약 입력에 칸이 없습니다).
- 휴대폰 번호는 알리페이에서 받지 않습니다.
  - 첫 예약 때나 계정 설정에서 직접 입력하고 문자 인증을 합니다. 웹 예약과 같은 흐름입니다.
  - 인증한 번호는 회원 정보에 저장되어 두 번째 예약부터 채워지고 인증을 건너뜁니다.
  - 인증 문자 재전송은 웹과 같은 규칙입니다.
- 예약 입력에서 고친 국적·성별·생년월일과 입력한 여권 영문명은 칸 편집을 마치고 그 칸을 벗어나는 순간 회원 정보를 덮어씁니다.
  - 칸을 벗어날 때는 올바른 값만 회원 정보에 저장하고, 비운 칸은 회원 정보를 덮어쓰지 않습니다.
  - 계정 설정에서 고친 값은 저장을 누르면 덮어씁니다.
  - 휴대폰 번호는 예약에서는 예약 요청을 보낼 때, 계정 설정에서는 문자 인증을 마친 때 덮어씁니다.
  - 고친 값은 회원 정보에 저장되어 다음 예약과 마이페이지에도 그 값이 보입니다.
- 이름은 여권 표기가 보장되지 않습니다.
  - 여권 영문명은 예약에서 직접 받습니다.

#### 진입과 복귀, 계정

- 웹뷰를 새로 열 때마다 알리페이 계정을 다시 식별합니다.
  - 새로 열기 = 알리페이 앱에서 우리 진입 주소나 딥링크로 웹뷰가 처음 뜨는 것. 같은 웹뷰 안의 새로고침과 화면 이동, 앱 전환 뒤 복귀는 새로 열기가 아닙니다.
  - 우리 쪽 로그인 상태는 웹뷰가 열려 있는 동안 유지합니다.
  - 그래서 폼을 작성하는 도중에는 다시 식별하지 않습니다.
- 새로 식별한 알리페이 계정이 직전과 다르면 앞 회원 상태를 끊고 새 회원으로 로그인합니다.
- 진입 때 웹 계정으로 로그인한 상태가 남아 있으면 그 로그인은 끊고 알리페이 회원으로 로그인합니다.
- 이미 가입한 회원이 다시 들어오면 알리페이 계정 식별만으로 로그인 상태가 됩니다.
  - 권한 상태를 다시 확인하지 않고 프로필도 다시 받지 않습니다.
  - 이용자가 알리페이에서 권한을 끊어도 받아 둔 회원 정보로 이용합니다.
- 로그인 없이 시작한 채팅방은 새 알리페이 회원에게 넘기지 않고, 매장 쪽 기록은 그대로 둡니다.
- 딥링크로 들어와 식별과 동의를 거치면 원래 가려던 화면으로 돌려보냅니다.
- 월렛마다 식별자가 다르면 각각 별도 회원으로 둡니다.
  - 웹에서 이미 가입한 회원과 같은 사람이어도 계정을 합치지 않습니다.
  - 계정 병합은 이번 범위가 아닙니다.

#### 진입 동의 창

FO-CH-09

- 알리페이에서 식별자를 받은 직후 한 번 띄웁니다.
  - 회원을 만들기 전입니다.
  - 가운데 모달이고 뒤 화면은 비어 있습니다.
- 제목은 “서비스 이용에 동의해 주세요”, 그 아래 한 줄로 “필수 항목에 동의해야 이용할 수 있습니다.”를 둡니다.
- 항목은 넷입니다.
  - 이용 약관 (필수)
  - 개인정보 처리방침 (필수)
  - 알리페이 프로필 제공 (필수). “이름, 닉네임, 성별, 생년월일, 국적을 가져옵니다. 닉네임은 리뷰와 채팅에 작성자 이름으로 표시됩니다.” 실제로 요청하는 권한만 적습니다.
  - 마케팅 정보 수신 (선택). “K-Beauty Station의 혜택·이벤트 정보를 휴대폰 번호로 받습니다.” 마케팅 문자는 이 항목에 동의한 회원에게만 보냅니다.
    - 번호가 없는 회원은 동의만 기록하고 번호가 생긴 뒤부터 보냅니다.
    - 기존 회원과 같은 마케팅 수신동의 정책을 따릅니다.
- 항목 뒤 (필수)/(선택)은 화면에서 항목 이름 옆 필수·선택 표시로 그립니다.
- 마케팅 정보 수신은 어드민 회원 목록의 “마케팅 활용 정보(동의 여부)”, 필터의 “마케팅 수신 여부”와 같은 동의입니다.
  - 어드민 쪽 이름은 라이브 회원 화면의 라벨을 따릅니다.
- 필수 셋에 동의해야 동의 버튼 “동의하고 시작하기”가 활성됩니다.
  - 닫는 버튼은 “닫기”입니다.
- 항목 오른쪽 “보기”를 누르면 같은 모달 안에서 전문이 펼쳐지고 버튼이 “접기”로 바뀝니다.
  - 별도 페이지로 보내지 않습니다.
  - 펼쳐도 체크한 것은 풀리지 않습니다.
- 동의를 누르면 알리페이 권한 창이 뜹니다.
  - 요청 권한은 위 월렛별 요청 권한 표를 따릅니다(중국 auth_user, 홍콩 항목별 다섯).
- 이용 약관·개인정보 처리방침·프로필 제공 동의는 시각과 함께 남깁니다.
  - 회원이면 셋 다 동의입니다.
  - 마케팅 수신은 동의와 거부를 모두 시각과 함께 남깁니다.
  - 동의와 동의 시각은 회원을 만들기 전까지 접속 상태에 임시로 두고, 회원을 만들 때 기록합니다.
  - 회원을 만들기 전에 창을 닫거나 웹뷰를 닫으면 임시로 둔 동의는 버리고 기록하지 않습니다.
- 이미 동의를 마친 회원은 다음 진입부터 이 창을 다시 보지 않습니다.
- 마케팅 정보 수신은 동의한 뒤 계정 설정의 마케팅 정보 수신 토글에서 바꿉니다.
- 약관·처리방침 개정 시 재동의는 웹 회원 정책과 같습니다.
- 프로필은 진입 동의 때 한 번 받고 다시 동기화하지 않습니다.
- 창의 언어는 들어온 주소의 언어를 따릅니다.
  - 약관과 처리방침 전문도 같은 언어입니다.

#### 알리페이 채널 회원 화면

FO-CH-10, FO-CH-11, FO-CH-12

- 자체 로그인 경로를 숨깁니다(FO-CH-10).
  - 헤더, 마이페이지, 예약과 문의 전 로그인 유도, 채팅 로그인 유도, 그 밖에 로그인 화면으로 보내는 모든 자리입니다.
  - 자체 로그인, 회원가입, 소셜 로그인, 비밀번호 찾기 진입을 모두 숨깁니다.
  - 진입 관문이 켜져 있을 때 주소로 직접 들어오면 마이페이지로 보냅니다.
  - 진입 관문이 켜져 있으면 관문을 통과해야 들어오므로 알리페이 채널 안에는 비로그인 상태가 없습니다.
- 마이페이지 상단의 로그인 영역 자리에는 닉네임(비어 있으면 “알리페이 회원”)과 가입일을 두고, 그 아래 안내 한 줄은 FO-CH-11을 따릅니다.
  - 헤더의 로그인 자리는 비웁니다.
- 마이페이지와 계정 설정 (FO-CH-11)
  - 구성은 현행 마이페이지와 계정 설정 그대로이고, 아래는 알리페이 회원에 맞춰 달라지는 자리입니다.
    - 마이페이지는 닉네임(비어 있으면 “알리페이 회원”)과 가입일, 예약 내역, 내 활동(채팅 내역·북마크·내 리뷰·쿠폰 목록), 둘러보기(K-BEAUTY 매거진·전문가 가이드), 고객센터, 계정 정보 변경 버튼으로 이루어집니다.
    - 계정 정보 변경을 누르면 계정 설정으로 갑니다.
      - 프로필은 여권 영문명, 국적·성별, 생년월일, 휴대폰 번호, 연락 메신저와 저장 버튼입니다.
      - 국적·성별·생년월일은 알리페이에서 받은 값이 채워지고, 칸을 고쳐도 저장을 눌러야 회원 정보에 들어갑니다.
      - 여권 영문명은 알리페이에서 받지 않아 비어 있고, 예약에서 입력한 값이 들어오며 여기서 고치면 덮어씁니다.
      - 연락 메신저 칸은 현행 웹 계정 설정과 같습니다.

### 8. 알리페이 확인 사항

알리페이 기술 담당의 서면 회신, 개발자 문서, 알리페이 콘솔 화면으로 확인한 결과입니다. 남은 확인 항목은 없습니다.

#### 회원 정보 연동 (4장)

- 알리페이에서 들어오면 회원부터 만들지 않고 진입 동의 창이 먼저 뜹니다.
  - 항목은 넷이고 이용 약관·개인정보 처리방침·알리페이 프로필 제공이 필수, 마케팅 정보 수신이 선택입니다.
- 진입 동의 창의 알리페이 프로필 제공 설명 끝에 “닉네임은 리뷰와 채팅에 작성자 이름으로 표시됩니다.”가 보입니다.
- 필수 셋을 모두 체크해야 동의 버튼이 켜집니다.
  - 누르면 알리페이 권한 창이 뜹니다.
- 알리페이 권한 창에서 필수 권한을 모두 허용하면 회원이 만들어지고 로그인됩니다.
  - 필수 권한을 하나라도 거부하면 진입 차단 화면이 뜨고 다시 동의하기로 권한 창이 다시 뜹니다.
- 동의 창에서 닫기를 누르면 회원이 만들어지지 않고 진입 차단 화면에 머뭅니다.
  - 둘러볼 수 있는 화면이 없습니다.
- 알리페이 권한 창을 닫아 권한 요청이 오류 11(authorization is cancelled)이나 1001(user cancels)로 끝나면 진입 차단 화면의 필수 권한 거부가 뜹니다.
- 알리페이 중국은 권한 창에 auth_user 하나를 요청하고 허용하면 통과합니다. 알리페이 홍콩은 항목별 권한을 요청하고 모두 허용하면 통과합니다. 동의 창의 프로필 제공 문구는 두 월렛이 같습니다.
- 새 미니프로그램 버전에서 월렛 판별·계정 식별·권한 요청이 동작합니다. 미니프로그램이 getSiteInfo·getSystemInfo·getAuthCode를 호출하고 결과를 웹페이지로 전달합니다.
- getSiteInfo와 getSystemInfo가 모두 월렛 값을 주지 않으면 진입 경로로 월렛이 정해집니다(/zh-TW는 알리페이 홍콩, 그 밖은 알리페이 중국).
- 식별에 실패하거나, 권한을 허용했는데 우리 쪽 처리가 실패하면 진입 차단 화면의 다시 시도가 뜹니다.
- 딥링크로 들어와 식별과 동의를 마치면 원래 가려던 화면이 열립니다.
- 진입 관문이 켜져 있을 때 로그인·회원가입 주소로 직접 들어오면 마이페이지로 갑니다.
- 로그인 없이 시작한 채팅방은 알리페이 회원이 된 뒤 채팅 내역으로 넘어오지 않고, 매장 쪽 기록은 그대로 남습니다.
- 이미 동의를 마친 회원에게는 진입할 때마다 창이 뜨지 않습니다.
  - 알리페이에서 권한을 끊은 회원도 다시 들어오면 계정 식별만으로 로그인되고 권한 창이 뜨지 않습니다.
- 웹뷰를 새로 열면 다시 식별되고, 웹뷰가 열려 있는 동안에는 로그인이 유지됩니다.
- 마이페이지에 닉네임·가입일·예약 내역·내 활동이 보이고 이름은 없습니다.
  - 계정 정보 변경을 누르면 계정 설정에서 여권 영문명·국적·성별·생년월일·휴대폰 번호·연락 메신저를 고치고 저장할 수 있습니다.
  - 이메일·비밀번호 변경·로그아웃 자리가 없습니다.
  - 마케팅 정보 수신 토글을 켜고 끌 때마다 동의·거부가 시각과 함께 기록되고, 토글 아래에 동의일 또는 거부일이 보입니다.
- 예약 폼에 이메일 칸이 없습니다.
  - 국적·성별·생년월일이 회원 정보에서 채워지고 고칠 수 있습니다.
  - 이름 칸은 없습니다.
  - 여권 영문명은 비어 있습니다.
  - 요청사항(선택) 칸은 그대로입니다.
  - 필수값은 지금 웹 예약 폼과 같고 이메일만 빠집니다.
  - 두 번째 예약부터는 저장된 인증 번호가 채워지고 “고치면 문자 인증을 다시 합니다.”가 보입니다.
  - 계정 설정에서 번호를 고치면 문자 인증을 다시 합니다.
  - 여권 영문명을 입력하고 칸을 벗어나면 회원 정보에 저장되어 계정 설정에 보입니다.
  - 메신저 칸 옆 앱 열기 버튼이 보이지 않습니다. 「알리페이 채널 분리 관리 PRD v1.0」 4단계 배포 전에도 같습니다.
- 예약 변경 화면에도 이메일 칸이 없고, 휴대폰 번호는 예약 입력과 같은 규칙입니다.
- 알리페이 회원이 예약 요청을 보내면 예약 완료 화면에 이메일 문장 대신 “We sent the confirmation details by text message”가 보입니다.
- 알리페이 채널의 상담접수 폼에 이메일 칸이 없고 프로필 항목이 채워져 있습니다.
  - 상담접수 폼에서 고친 이름·휴대폰 번호는 회원 정보를 덮어쓰지 않습니다.
- 첫 예약에서는 휴대폰 번호를 직접 입력하고 문자 인증을 합니다. 알리페이에서 채워진 번호는 없습니다.
- 예약에서 고친 국적·성별·생년월일·휴대폰 번호가 회원 정보에 반영됩니다.
- 월렛이 다르면 같은 사람이어도 별도 회원으로 생성되고, 웹 회원과 합쳐지지 않습니다.
  - 다른 알리페이 계정으로 다시 들어오면 앞 회원 상태가 끊기고 새 회원으로 로그인됩니다.
- 방문 일시가 지나지 않은 예약이 있으면 탈퇴가 진행되지 않고 웹 탈퇴 화면의 차단 안내가 보입니다.
- 탈퇴하면 알리페이 연결이 끊기고, 다시 들어오면 새 회원으로 진입 관문을 다시 거칩니다.
  - 홍콩 월렛은 권한도 해제되고, 중국 월렛은 권한 해제 호출 없이 우리 쪽 연결만 끊깁니다.
  - 권한 해제가 실패하거나 토큰이 만료되었어도 탈퇴는 끝납니다.
- 어드민 알리페이 회원 목록에 칼럼 열여덟 개(탈퇴일 제외)가 있고 이메일·주소·프로필 동의 여부 칼럼이 없습니다.
  - 필터에 가입 경로와 프로필 동의가 없습니다.
  - 검색은 식별자 완전 일치, 기본 정렬은 가입일 최신순, 한 페이지 10건으로 기존 회원 화면과 같습니다.
  - 화면을 처음 열면 탈퇴정보 토글은 꺼져 있고 마케팅 활용 정보 토글은 켜져 있습니다.
- 진입 관문 스위치를 끄면 웹뷰를 새로 열 때부터 알리페이 채널이 비로그인 상태로 돌아가고 북마크·리뷰 작성·쿠폰이 보이지 않습니다. 다시 켜면 같은 계정이 기존 회원으로 식별됩니다.

#### 알림 (5장)

- 마케팅 문자 발송 기능은 없고, 어드민 알리페이 회원 목록에서 마케팅 수신에 동의한 회원과 연락처를 확인할 수 있습니다.
- 알리페이 회원 예약번호는 웹 예약과 같은 규칙·같은 일련 카운터로 붙고, 같은 접수일·스토어·언어에서 웹 예약과 번호가 겹치지 않습니다.
- 예약 확인·변경·취소·거절·방문 하루 전 알림은 우리 문자로 옵니다.
  - 문자에는 링크가 없고 예약번호가 있습니다.
- 전날 10시 이후에 접수·확정된 예약과 당일 예약에는 방문 하루 전 알림이 가지 않습니다.
- 문자 발송이 실패하면 5분 뒤 한 번 다시 보내고, 그래도 실패하면 어드민 예약 관리와 호스트 예약 현황의 예약 상세에 “문자를 보내지 못했습니다.”가 보입니다. 뒤의 알림이 성공하면 사라집니다.
- 알리페이 회원에게 이메일이 가지 않습니다.
- 진입 관문을 끈 동안에도 이미 만든 회원의 예약 알림 문자는 그대로 갑니다.

#### 배포 (7장)

- 어드민 알리페이 회원 목록은 진입 관문을 처음 켜기 전에 배포되어 있고, 진입 관문은 7장 선행 작업 표의 “진입 관문을 켜기 전” 항목이 모두 끝난 뒤에 켜집니다.
- 진입 관문 스위치를 켜고 끈 시각과 요청자가 기록됩니다.
