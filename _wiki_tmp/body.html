웹과 알리페이 앱(alipay-app.kbstations.com)을 별도 채널로 운영하는 작업입니다. 콘텐츠마다 어느 채널에 낼지 정하고, 알리페이 회원은 진입 동의를 통과해야 들어옵니다. 결제는 이번 범위가 아닙니다.

1. 무엇을 만드는가

화면 ID 33개에 엣지와 모달 26개가 붙습니다. 어드민 13, 호스트 2, 고객 화면 13, 공통 처리 5입니다. 신규 화면은 어드민 알리페이 회원 목록, 고객 진입 차단 화면, 진입 동의 창 셋입니다. 알림 발송 처리가 새로 붙고, 나머지는 기존 화면 수정과 데이터 처리입니다. 상세는 기능정의서 59행과 Figma의 화면별 desc 패널에 있습니다.

2. 기존 웹 서비스가 함께 바뀝니다

지금 웹 동작이 바뀌는 항목이 다섯입니다. 가장 먼저 봐 주세요.

  • 웹에도 노출 채널 조건이 붙습니다. 알리페이 앱 전용으로 정한 콘텐츠는 웹 목록·검색·상세·사이트맵에서 빠집니다. 기존 콘텐츠는 전부 전체로 시작해 배포 직후 웹에서 빠지는 건은 없습니다

  • 버튼 자리 세는 법. 지금 웹은 상담접수와 문의하기를 한 자리로 세는데 항목별 한 자리로 바뀝니다. 이미 3자리인 기존 데이터는 저장이 막히므로 배포 전에 정리해야 합니다

  • 기획전 구성 항목이 필수가 됩니다. 담은 항목이 0건인 기획전은 저장이 막힙니다

  • 배너의 연결 대상 선택지가 배너 채널에 맞는 것으로 제한됩니다

  • 메신저 버튼을 인앱 채팅으로 바꿔 보여주던 자동 치환을 없앱니다. 알리페이 열 생성 이후에 배포해야 합니다

5. 핵심 규칙

채널 판별

  • alipay-app.kbstations.com 접속이 알리페이 채널, 그 외는 웹 채널. 이미 도메인으로 분리 운영 중이라 새 로직이 아니다. 서버는 요청 Host로 읽는다

  • 판별은 한 곳에서만 한다. 필터·폴백·결과 분리·버튼 노출·참조 정리·진입 관문이 모두 이 값을 쓴다

  • 알리페이 중국과 홍콩은 한 채널. 월렛 구분은 언어 경로가 대신한다. 중국 /zh, 홍콩 /zh-TW

노출 채널

  • 콘텐츠 건마다 값 하나. 전체 / 웹 / 알리페이 앱. 대상은 상품, 스토어, 배너, 기획전, 매거진, 스토어 칼럼. 인플루언서 기획전은 URL 랜딩이라 대상 아님

  • 공개여부·활성화·히든 같은 기존 노출 조건은 그대로 별개다. 노출 채널은 어디에 낼지만 정한다

  • 상품과 칼럼은 스토어를 따른다. 스토어가 전체면 자유, 웹이면 웹 고정, 알리페이 앱이면 알리페이 앱 고정. 저장값은 건드리지 않고 화면만 잠근다

  • 일본어·인도네시아어·몽골어 건은 웹 고정. 외부링크 배너는 웹 고정

  • 호스트 화면에는 설정이 없다. 호스트 상품·칼럼은 스토어 값을 따른다

노출 판정. 웹과 알리페이가 같은 규칙이다

  • ① 노출 채널 유효값이 전체이거나 지금 채널과 같다

  • ② 기존 노출 조건. 지금 웹이 쓰는 그대로

  • ③ 배너만. 연결 대상이 그 채널에 노출. 등록 시 채널에 맞지 않는 대상은 고를 수 없고, 연결 뒤 대상이 바뀐 경우만 자동 숨김

  • ④ 기획전만. 담은 항목 중 그 채널에 노출되는 것이 1건 이상. 채널마다 따로 센다

  • 버튼 조건은 없다. 버튼이 없어도 노출된다

목록 표시

  • 노출 채널 칼럼 하나. 설정값(고정된 건은 유효값). 상품·스토어 목록에는 사유 칼럼이 없다

  • 배너·기획전 목록에만 사유. "웹에 노출 대상 없음" / "알리페이 앱에 노출 대상 없음"

버튼 구성

  • 종류는 상담접수 / 채팅(신설) / 상담접수·채팅 통합 표시 / 외부링크 설정 / 메신저 설정 / 예약(스토어만) 여섯. 상품 예약은 별건

  • 여섯은 각각 독립이다. 켜져 있으면 항목마다 한 자리를 쓴다

  • 자리는 웹 열과 알리페이 열에 각각 둘까지. 셋째를 켜려 하면 화면 위쪽 알림으로 막고 토글은 원위치

  • 알리페이 열에서 외부링크와 메신저는 비활성 고정

  • 노출 채널이 웹이면 알리페이 열을, 알리페이 앱이면 웹 열을 잠근다. 값은 유지

  • 저장을 막는 것은 자리 상한 초과뿐. 버튼이 비었다는 안내나 확인은 없다

고객 화면 처리

  • 숨김은 서버의 조회 레이어 공통 필터 한 곳에서 일괄 적용한다. 웹과 알리페이 양쪽. 화면별로 따로 처리하지 않는다

  • 알리페이 채널에서 버튼이 0개면 하단 CTA 영역을 접는다

  • 허용 목록에 없는 외부 임베드는 알리페이 채널 렌더 단계에서 영역째 숨긴다. 메신저 카드, SNS 임베드, SNS 채널 아이콘, 상품 인스타그램 임베드. 구글 리뷰 위젯은 대상이 아니다

  • 리뷰는 채널을 나누지 않는다. 작성자 표시명은 알리페이 닉네임

회원

  • 진입 동의가 관문이다. 둘러보기는 없다. 우리 모달 하나(이용 약관·개인정보 처리방침·알리페이 프로필 제공 필수, 알림 수신·마케팅 정보 수신 선택) 뒤에 알리페이 권한 창이 한 번 뜬다. 둘 다 통과한 시점에 회원 생성

  • 프로필 거부, 닫기, 식별 실패는 진입 차단 화면. 알림 권한만 거부하면 통과

  • 알리페이 회원은 웹 회원과 별개 집합이다. 계정을 합치지 않는다

  • 받는 항목은 이름, 닉네임, 아바타, 성별, 생년월일, 국적, 주소, 휴대폰 번호(원본 권한 승인 시), 로그인 ID 원본. 이메일은 받지 않는다

  • 원본 휴대폰이 오면 예약 폼 문자 인증을 생략한다. 고치면 다시 인증. 원본 권한이 없으면 지금처럼 입력과 인증. 두 갈래를 모두 만든다

  • 예약에서 고친 값은 회원 정보를 덮어쓴다

  • 예약의 확인·변경·취소는 알리페이 앱에서 우리 채널을 다시 여는 것이 정규 경로다. 그 밖의 경우는 고객센터가 예약번호와 휴대폰 번호로 대신 처리한다

알림

  • 알리페이 알림 발송(/v2/miniprogram/message/send) 1순위. 푸시·문자·메시지함 템플릿 4종(예약 확인·변경·취소·방문 하루 전)

  • 우리 문자는 예비. 알리페이 발송 실패, 알림 권한 거부, SEND_MESSAGE 미승인일 때. 알리페이 발송 성공 시 우리 문자는 보내지 않는다

  • 이메일 발송 없음

6. 마이그레이션과 배포 순서

  • 기존 콘텐츠의 노출 채널을 전부 전체로 일괄 설정. 기존 버튼 ON/OFF는 웹 열 값으로 그대로

  • 알리페이 열은 스토어가 예약설정 사용이면 예약과 상담접수, 미사용이면 상담접수. 개별 설정 상품은 상담접수. 기본 설정 상품은 스토어 값(예약 제외)을 읽는다. 웹 열 값을 알리페이로 옮기지 않는다

  • 배치는 여러 번 실행해도 결과가 같다. 이미 값이 있는 건은 건너뛴다

배포는 이 순서를 지켜야 합니다. 순서가 바뀌면 콘텐츠가 통째로 사라지거나 채팅 버튼이 사라집니다.

  1. 노출 채널 값 설정(전부 전체)

  2. 알리페이 열 생성, 채팅 항목·배너 버튼 내부링크·노출 채널 항목 추가

  3. 기존 콘텐츠의 판정 결과 최초 일괄 계산(스토어 → 상품·칼럼 → 기획전·인플루언서 기획전 → 배너)

  4. 자동 치환 제거 배포

  5. 공통 필터(양방향) 적용

진입 관문은 알리페이 권한 개통 뒤에 켭니다. 위 순서와 별개입니다.

1차 롤백은 공통 필터 차단입니다. 외부 연결 계열은 필터와 분리된 하드 규칙이라 롤백해도 유지됩니다.

7. 개발에 요청하는 것

어드민 필터가 배포 후에 생겨서 배포 전에는 쿼리로만 뽑을 수 있습니다. 아래 네 건을 부탁드립니다.

  • (b) 웹 열 버튼 자리가 3개 이상인 건

  • (c) 구성 항목이 0건인 기획전

  • (d) 연결 대상이 비활성이거나 기간이 지났거나 언어가 다른 배너

  • (e) 같은 유형 값과 언어로 둘 이상인 기획전 유형 레코드

알리페이 담당에게 서면으로 확인받을 항목 다섯은 기획에서 진행합니다. 결과에 따라 갈리는 곳은 문서에 두 갈래로 적어 두었습니다.

  • 원본 휴대폰·원본 로그인 ID 권한(PLAINTEXT_MOBILE_PHONE, PLAINTEXT_USER_LOGIN_ID, USER_CONTACTINFO) 승인 여부

  • 알림 발송 권한(SEND_MESSAGE) 승인 여부

  • 홍콩 지갑의 푸시·문자·메시지함 템플릿 제공 여부

  • 알림 발송 빈도 상한

  • 현재 웹뷰 채널의 미니프로그램 플랫폼 등록 상태와 권한 호출(getAuthCode) 사용 가능 여부

8. 이번 범위가 아닌 것

  • 결제 연동, 월렛 확대, 채널별 통계 화면 분리, 목록 일괄 변경, 계정 병합, 상품 단위 예약

  • 다만 노출·클릭·채팅·상담·예약 기록에 어느 채널에서 들어온 것인지 값을 남기는 것은 이번에 넣습니다. 화면은 나중에 만들어도 되지만 값을 남기지 않으면 소급할 수 없습니다

  • 기획전 유형 관리의 중복 차단은 기존 화면에 검증 하나만 추가하는 것이라 동작 시안을 만들지 않았습니다

  • 회원 구분 표기의 위치와 형태는 각 화면 실측 자료를 받아 확정합니다

9. 첨부

PRD v3.1과 기능정의서 v3.1입니다.
