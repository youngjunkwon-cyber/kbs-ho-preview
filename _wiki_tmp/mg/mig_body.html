알리페이 채널 분리 기능을 배포할 때, 이미 등록된 상품·스토어·배너 등의 설정을 어떻게 맞출지 정리한 계획입니다. 대상 건수는 개발을 시작할 때 다시 셉니다. 상품 예약이 배포되면 건수가 크게 바뀌기 때문입니다.

 

■ 기존 데이터에 넣는 값

- 콘텐츠를 보여줄 곳(노출 채널): 모두 "전체"(웹과 알리페이 앱 둘 다)

- 웹 하단 버튼: 지금 켜 둔 그대로

- 알리페이 앱 하단 버튼: 예약을 쓰는 스토어는 예약과 상담접수, 예약을 안 쓰는 스토어와 개별 설정 상품은 상담접수만 켭니다. 상담접수 대신 채팅을 켤지는 아래 "정할 것" 1번에서 정합니다

- 예약·채팅 등이 어디서 들어왔는지(유입 채널): 지난 건은 채우지 않고 "-"로 보입니다

 

■ 진행 순서

- 시작할 때: 개발팀이 아래 정리 목록을 뽑습니다. 상품 예약 배포 뒤 바뀐 것도 확인합니다(상품에 예약 버튼이 생겨 ①번이 늘 수 있음)

- 배포 전: 운영팀이 ①·②·③번을 정리합니다

- 어드민·호스트 배포 당일: 개발팀이 알리페이 앱 하단 버튼 값을 한꺼번에 채웁니다. 문제가 생기면 채우기 전 값으로 되돌립니다

- 고객 화면 적용 뒤: 운영팀이 개별 설정 상품의 알리페이 예약 버튼을 상품마다 켭니다

- 버튼 값 채우기는 꼭 알리페이 앱 고객 화면 적용보다 먼저 해야 합니다. 순서가 바뀌면 알리페이 앱에서 버튼이 모두 사라집니다

 

■ 정리 목록

- ① 버튼 세는 방식이 바뀌면 3개가 되는 상품·스토어: 버튼을 2개 이하로 줄이기(배포 전)

- ② 담긴 상품이나 스토어가 없는 기획전: 담거나 비활성으로 바꾸기(배포 전)

- ③ 같은 종류·언어로 두 개 이상 있는 기획전 유형: 하나로 합치기(배포 전)

 

■ 정할 것

1. 알리페이 앱 기본 버튼을 상담접수로 할지, 채팅으로 할지. 버튼은 최대 2개라 예약을 쓰는 스토어는 "예약 + 상담접수" 또는 "예약 + 채팅" 중 하나입니다

2. 날짜와 담당자

3. ①번 목록에서 남길 버튼 기준

4. 버튼 값을 채운 건수가 예상과 다를 때 처리
