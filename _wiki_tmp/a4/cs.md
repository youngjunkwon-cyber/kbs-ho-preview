# 알리페이 채널 분리 관리 개발 전달 (v1.0)

웹과 알리페이 앱(alipay-app.kbstations.com)을 별도 채널로 운영하는 작업입니다. 콘텐츠마다 어느 채널에 낼지 정하고, 알리페이 앱 안에서는 이용자를 앱 밖으로 내보내는 버튼과 링크를 없앱니다. 규칙 전문(PRD v1.0)은 9장에 그대로 있어 이 문서만 읽으면 됩니다.

## 1. 무엇을 만드는가

화면 ID는 25개입니다. 어드민 12, 호스트 3, 고객 화면 7, 공통 처리 3입니다. 새 화면은 없고 기존 화면 수정과 데이터 처리입니다.

- 상품, 스토어, 배너, 기획전, 매거진에 노출 채널(전체 / 웹 / 알리페이 앱)을 둡니다. 스토어 칼럼은 값을 두지 않고 소속 스토어의 값을 따릅니다
- 상품, 스토어, 배너의 하단 버튼을 웹용과 알리페이용으로 따로 켭니다. 채팅을 단독 버튼으로 추가합니다
- 알리페이 채널에서는 외부링크·메신저 버튼, 메신저 카드, SNS 임베드, SNS 채널 아이콘을 숨기고, 매거진·스토어 칼럼 본문의 외부 링크는 글자로 바꿉니다
- 알리페이 중국은 /zh(중국어 간체), 알리페이 홍콩은 /zh-TW(중국어 번체)로 들어옵니다. 알리페이 도메인의 언어 선택 목록은 중국어(간체), 영어, 중국어(번체) 셋입니다
- 어드민·호스트의 예약·채팅·상담·리뷰 화면, 스토어 문의 통계, 예약자 설문조사, 호스트 대시보드에서 건마다 들어온 채널(웹 / 알리페이 중국 / 알리페이 홍콩)을 "유입 채널"로 보고 거를 수 있게 합니다
- 알리페이 회원 정보 연동, 예약 알림 문자, 알리페이 홍콩 연동은 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」에서 다룹니다. 그 작업은 이 문서의 1단계 배포 뒤에 진행합니다

## 2. 지금 동작이 바뀌는 항목

가장 먼저 봐 주세요. 웹 동작이 바뀌는 것과, 알리페이 도메인에서 지금 보이던 동작이 바뀌는 것입니다.

- 웹에도 노출 채널 조건이 붙습니다. 알리페이 앱 전용 콘텐츠는 웹 목록·검색·상세·사이트맵에서 빠지고, 주소로 열면 404입니다. 기존 콘텐츠는 전부 전체로 시작합니다
- 매거진·스토어 칼럼 에디터에 링크 도구로 넣은 우리 도메인 절대 주소는 저장할 때 상대 경로로 바뀝니다
- 하단 버튼 세는 법이 항목마다 한 자리로 바뀝니다. 지금 상담접수와 문의하기를 한 자리로 세던 것이 두 자리가 됩니다. 채널마다 두 자리를 넘는 기존 건(집계 1)은 1단계 배포 전에 운영자가 정리하고, 정리 완료가 1단계 배포 조건입니다
- 기획전 구성 항목이 필수가 됩니다. 활성 상태로 저장할 때 담은 항목이 0건이면 저장할 수 없고, 비활성으로 저장할 때는 막지 않습니다
- 배너의 연결 대상은 배너 채널에 노출되는 것만 고를 수 있습니다
- 스토어 칼럼 에디터는 웹을 포함해 외부 링크와 외부 임베드를 넣을 수 없습니다. 옛 칼럼을 고쳐 저장하면 남은 외부 링크·임베드가 지워집니다. 지우기 전 원문을 보관하고, 운영자가 어드민 칼럼 상세의 "원문 복원" 버튼으로 되돌립니다. 매거진은 웹에서 지금처럼 허용합니다
- 랜딩페이지 배너의 하단 버튼은 연결 대상이 웹에 노출되지 않으면 웹에서도 버튼만 숨깁니다
- 기획전, 홈 큐레이션 섹션, 인플루언서 기획전, 매거진 본문 카드에서 웹에 노출되지 않는 항목이 빠집니다
- 알리페이 도메인에서 메신저 버튼을 인앱 채팅으로 바꿔 보여주던 자동 치환을 없앱니다. 치환으로 보이던 채팅 버튼이 사라지는 것은 의도한 결과입니다. 알리페이에 채팅 버튼을 두려면 알리페이 열에서 채팅을 켭니다
- 알리페이 도메인의 언어 선택 목록이 여섯에서 셋(중국어 간체, 영어, 중국어 번체)으로 줄어듭니다

## 3. 읽는 순서

1. 이 문서 1~8장. 무엇을 만드는지, 바뀌는 동작, 핵심 규칙, 배포
2. 9장 PRD 전문. 판정 규칙, 화면 문구, 마이그레이션과 배포의 전문
3. 9장 PRD의 부록 A. QA 체크리스트

문서끼리 다르게 읽히면 9장 PRD를 따르고 기획에 알려 주세요.

## 5. 핵심 규칙

채널 판별

- alipay-app.kbstations.com 접속이 알리페이 채널이고, 그 외는 웹 채널입니다. 이미 도메인으로 나눠 운영 중이라 새 판별 로직이 아닙니다
- 공통 필터, 직접 진입 폴백, 결과 분리, 버튼 노출, 참조 정리가 모두 같은 판별 결과를 따릅니다
- 알리페이 중국과 알리페이 홍콩은 같은 알리페이 앱 채널입니다

노출 채널

- 콘텐츠 건마다 값이 하나이고, 값은 전체 / 웹 / 알리페이 앱입니다. 기존 콘텐츠와 새 콘텐츠 모두 전체로 시작합니다
- 노출 채널은 어디에 낼지만 정합니다. 공개여부, 활성화, 히든, 노출 기간, 게시 상태 같은 기존 조건은 그대로 따로 적용합니다
- 인플루언서 기획전은 대상이 아닙니다. 어느 채널에서 열면 그 채널에 노출되지 않는 담은 상품 카드를 빼고, 남는 상품이 0건이면 그 채널에서 404입니다. 홈 큐레이션 섹션은 설정 없이 담은 항목을 따라갑니다
- 상품과 스토어 칼럼은 소속 스토어의 노출 채널을 따릅니다. 화면·목록·노출 판정은 운영자가 고른 저장값이 아니라 스토어 종속, 대상 외 언어, 지원언어, 외부링크 배너를 반영한 유효값을 씁니다
- 일본어·인도네시아어·몽골어 건과 링크종류가 외부링크인 배너는 웹으로 고정됩니다. 지원언어에 중국어(간체)·중국어(번체)·영어가 하나도 없는 스토어도 웹으로 고정됩니다
- 일본어·인도네시아어·몽골어는 웹에 노출되는 스토어만 지원언어에 켤 수 있습니다. 노출 채널이 알리페이 앱인 스토어는 이 언어들을 켤 수 없고, 이 언어가 하나라도 켜진 스토어는 노출 채널을 알리페이 앱으로 바꿀 수 없습니다. 그래서 대상 외 언어 건이 어디에도 안 나가는 상태가 생기지 않습니다
- 세부 규칙(스토어 종속, 설정 단위와 언어, 저장값 보존, 에디터의 외부 링크·임베드)은 9장 PRD 5장에 있습니다

노출 판정. 웹과 알리페이가 같은 규칙입니다. 판정 조건 ①~④는 배포 단계(1단계~5단계)와 별개입니다

- ① 노출 채널 유효값이 전체이거나 지금 채널과 같습니다
- ② 지금 웹이 쓰는 기존 노출 조건 그대로이고, 상품과 스토어 칼럼은 소속 스토어가 그 채널에 노출될 때만 통과합니다
- ③ 배너만 적용합니다. 내부링크로 가리키는 대상이 그 채널에 노출되어야 합니다. 등록할 때 채널에 맞지 않는 대상은 고를 수 없게 막고, 연결한 뒤 대상 쪽이 바뀐 경우만 자동으로 숨깁니다. 랜딩페이지 배너의 하단 버튼 대상은 배너 노출과 무관하고, 대상이 그 채널에 없으면 버튼만 숨깁니다
- ④ 기획전만 적용합니다. 담은 항목 중 그 채널에 노출되는 것이 한 건 이상이어야 하고, 채널마다 따로 셉니다
- 새로 등록했거나 배포 직후라 연결 대상·담은 항목의 노출 여부가 아직 반영되지 않은 배너·기획전은 ③④를 통과로 보고 숨기지 않습니다
- 버튼은 판정 조건이 아닙니다. 버튼이 하나도 없어도 노출되고 하단 버튼 영역만 접힙니다
- 숨긴 콘텐츠는 어떤 경로로도 볼 수 없어야 합니다. 상품, 스토어, 배너, 기획전, 인플루언서 기획전, 매거진, 스토어 칼럼의 모든 노출면과 사이트맵에 같은 판정을 적용합니다
- 그 채널에 노출되지 않는 콘텐츠 주소로 들어오면 기존 404 페이지를 404 상태 코드로 보여줍니다. ② 때문에 안 보이는 경우(비공개 스토어 등)는 지금 정책 그대로입니다
- 저장하면 목록과 고객 화면에 60초 안에 반영됩니다. 참조 대상이 바뀌어 결과가 달라지는 경우도 같습니다
- 리뷰는 채널을 나누지 않습니다. 리뷰 수와 평점도 지금처럼 하나로 셉니다

버튼

- 상품·스토어 버튼 표의 항목마다 웹 ON/OFF 옆에 알리페이 ON/OFF를 하나 더 둡니다
- 버튼 자리는 채널마다 둘까지이고, 상담접수, 채팅, 상담접수·채팅 통합 표시(기존 문의하기), 외부링크, 메신저, 예약은 켜져 있으면 항목마다 한 자리를 씁니다
- 외부링크와 메신저는 알리페이 열에서 켤 수 없습니다
- 노출 채널이 웹이면 알리페이 열을, 알리페이 앱이면 웹 열을 잠급니다. 값은 지우지 않고 흐리게 보이며, 전체로 되돌리면 열린 열은 꺼진 상태로 시작합니다. 스토어의 노출 채널이나 지원언어를 바꿔 알리페이 열 잠금이 풀리면, 스토어를 저장하는 순간 그 스토어와 개별 설정 상품의 풀린 알리페이 열을 모두 끈 값으로 저장합니다
- 상품이 기본 설정이면 두 열 모두 스토어 값을 그대로 따르고 편집은 잠깁니다. 개별 설정으로 바꾸면 두 열 모두 스토어 현재 값을 복사해 시작합니다
- 예약은 스토어와 상품 모두에 있고 다른 버튼과 같은 하나의 버튼입니다. 예약 설정을 켜야 켤 수 있습니다. 예약 설정을 끄면 값은 지우지 않고 흐리게 잠기고 고객 화면에 나가지 않습니다. 다시 켜면 스토어와 상품의 예약 버튼 모두(웹·알리페이 열 모두) 꺼진 상태로 시작하고 운영자가 다시 켭니다. 다른 버튼 값은 그대로입니다
- 버튼 설정에서 저장을 막는 것은 버튼 자리 상한을 넘겼을 때뿐입니다
- 채팅 버튼은 새 기능이 아니라 지금의 인앱 채팅을 단독으로 켜는 항목입니다. 지금 문의하기 안의 채팅과 같은 방을 엽니다. 상품 화면이면 상품 채팅방, 스토어 화면이면 스토어 채팅방입니다. 웹 열도 OFF로 시작합니다
- 신규 스토어의 알리페이 열은 상담접수로 시작합니다. 상품·스토어는 웹 열에서 켠 것을 알리페이 열로 복사하지 않습니다
- 배너 하단 버튼은 웹 표시여부를 복사해 시작하되, 버튼 링크 종류가 외부링크면 알리페이 열은 비활성화로 시작합니다. 배너 버튼 링크 종류에 내부링크를 더하고, 직접입력은 /로 시작하는 우리 사이트 경로만 받습니다

외부 요소. 알리페이 채널에서 렌더할 때 일괄로 거릅니다. 운영자 설정은 없습니다

- 메신저 카드, SNS 임베드, SNS 채널 아이콘은 영역째 숨기고 여백 없이 접습니다
- 매거진·스토어 칼럼 본문의 외부 링크는 글자로 바꾸고, 허용 목록에 없는 외부 임베드는 숨깁니다. 저장된 본문은 그대로입니다. 허용 목록은 확정 전이라 비어 있습니다
- 전화·메일 링크는 글자로 바꿉니다
- 예약 폼과 상담접수 폼의 메신저 아이디 입력에서 앱 열기 버튼을 숨깁니다
- 구글 리뷰 위젯은 이번 범위가 아니고 현행 그대로입니다

어드민·호스트 화면

- 목록의 노출 채널 칼럼은 하나이고 값은 유효값입니다. 사유 칼럼은 배너·기획전 목록에만 있습니다
- 호스트 화면에는 노출 채널 설정과 버튼 설정이 없습니다. 한쪽 채널에 나가지 않는 상품·칼럼에는 안내만 보입니다(5단계부터)
- 화면 문구와 저장 규칙은 9장 PRD 7장에 있습니다

유입 채널

- 노출·클릭·조회수·버튼 클릭수·채팅·상담·예약 기록에 채널 기록값(웹 / 알리페이 중국 / 알리페이 홍콩)을 남기고, 화면에서는 이 값을 합치지 않고 "유입 채널"로 보여줍니다. 통계용이고 과금 기준은 바꾸지 않습니다
- 배포 전에 생긴 건과 매장·운영자가 대신 등록한 수기 예약은 "-"이고, 유입 채널 필터에서 채널 하나를 고르면 빠지고 "전체"에서만 보입니다. 예약 상세, 호스트 예약 카드, 대시보드 예약 현황 카드에는 배지를 두지 않습니다
- 알리페이 중국과 알리페이 홍콩은 1단계부터 첫 진입 주소로 정합니다(/zh-TW는 알리페이 홍콩, 그 밖은 알리페이 중국). 이용하는 동안 유지하고 언어를 바꿔도 그대로입니다. 회원 연동 배포 뒤에는 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」의 월렛 값을 먼저 씁니다. 비회원의 언어 설정은 브라우저(쿠키)에 저장합니다
- 채팅의 유입 채널은 채팅방이 처음 생길 때의 값이고 이후 바뀌지 않습니다
- 리뷰는 건에 채널 기록값이 없어 작성 회원의 채널로 보여줍니다. 알리페이 회원 구분은 회원 연동 배포 뒤 적용하므로, 그 전에는 알리페이 도메인에서 쓴 리뷰도 웹이고 이 기능 배포 전 리뷰도 웹입니다
- 예약 관리 목록의 필터 순서는 언어 → 유입 채널 → 예약 구분 → 등록 주체입니다. 예약 구분 필터와 스토어 문의 통계의 플랫폼 예약 칸은 상품 예약 기능 그대로이고, 플랫폼 예약 건의 유입 채널은 그 예약의 채널 기록값입니다
- 유입 채널은 목록에 이미 있는 유입경로(스토어·상품 등 어디서 시작했는지)와 다른 값입니다
- 호스트 대시보드 통계 칸은 합계만 보이고 채널별 숫자와 유입 채널 필터는 두지 않습니다. 대시보드 칸 규칙은 상품 예약 기능 그대로입니다
- 어드민과 호스트가 같은 이름과 같은 값을 씁니다

주소 경로

- 알리페이 중국은 alipay-app.kbstations.com/zh, 알리페이 홍콩은 alipay-app.kbstations.com/zh-TW로 들어오고, 들어온 주소가 언어를 정합니다. 앱을 알아내 언어를 자동으로 바꾸는 처리는 만들지 않습니다
- 알리페이 채널에서 /ja, /id, /mn 경로로 들어오면 저장된 언어(없으면 월렛의 진입 언어) 홈으로 보냅니다
- 상세를 보다가 언어를 바꾸면 그 언어의 같은 종류 목록으로 이동합니다. 지금 웹과 같은 동작입니다

## 6. 배포

- 1단계부터 5단계까지 차례로 배포합니다
  - 1단계: BO-CH-01~10·12·13, HOST-CH-01~03, SYS-CH-01. 노출 채널 값은 전부 전체로 시작하고, 채널 기록값 저장도 여기서 시작합니다
  - 2단계: SYS-CH-03 배치(버튼 알리페이 열 채우기). 1단계 배포 직후 같은 날 실행합니다
  - 3단계: SYS-CH-02(판정)와 배너·기획전 목록의 사유 칼럼. 고객 화면에는 아직 적용하지 않습니다
  - 4단계: FO-CH-01, FO-CH-05, FO-CH-07, 외부링크 배너의 알리페이 앱 숨김(공통 필터와 별개로 늘 적용). 반드시 2단계 뒤에 배포합니다. 알리페이 열이 채워지기 전에 알리페이 열로 그리면 알리페이 앱에서 하단 버튼이 전부 사라집니다. 4단계 전에는 버튼 링크 종류가 내부링크인 배너 하단 버튼을 고객 화면에 그리지 않습니다
  - 5단계: FO-CH-02·03·04·06과 사이트맵. 공통 필터를 웹과 알리페이 양쪽에 적용합니다
- 1단계 배포 조건은 집계 1(버튼 자리 초과), 집계 2(구성 항목 0건 기획전), 집계 4(중복 기획전 유형 레코드) 정리 완료입니다. 선행 집계 1~5는 배치 전에 개발이 뽑아 운영에 공유합니다
- 2단계 배치 규칙
  - 스토어: 예약 설정을 쓰면 알리페이 열에 예약과 상담접수, 쓰지 않으면 상담접수를 켭니다
  - 개별 설정 상품: 상담접수를 켜고, 예약 줄은 알리페이 열만 OFF로 둡니다. 웹 열은 건드리지 않습니다
  - 기본 설정 상품: 배치 대상이 아닙니다. 늘 스토어의 현재 값으로 보입니다
  - 채팅, 통합 표시, 외부링크, 메신저의 알리페이 열은 전부 OFF입니다
  - 잠긴 알리페이 열은 건너뜁니다
  - 운영자가 알리페이 열을 직접 바꿔 저장한 건은 덮지 않습니다. 이를 가르기 위해 1단계부터 건마다 기록합니다. 운영자가 알리페이 열 칸을 직접 눌러 값이 달라진 채로 저장했을 때만 기록하고, 개별 설정 전환으로 복사된 값과 예약 설정을 다시 켜서 꺼진 값은 기록하지 않습니다
- 단계 사이의 화면 동작(저장 완료 안내, 사유 칼럼, 호스트 채널 안내가 언제부터 보이는지)은 9장 PRD 13장에 있습니다
- 공통 필터 스위치: 운영자가 요청하면 개발이 배포 없이 켜고 끕니다. 반영은 60초 안이고, 켜고 끈 시각과 요청자를 기록합니다. 끄면 판정 조건 ①③④와 채널 종속이 풀립니다. 외부 연결 계열 넷(외부링크 배너 숨김, 외부링크·메신저 버튼 비표시, 메신저 카드·SNS 요소 숨김, 본문 외부 링크·임베드 변환)은 스위치와 별개로 늘 적용합니다
- 롤백: 1차 대응은 공통 필터 스위치 끄기입니다. 2단계 배치는 되돌릴 수 있어야 하고, 4단계 이후에 되돌릴 때는 4단계를 먼저 되돌립니다. 4단계 안에서 외부 요소 숨김과 본문 변환은 알리페이 열 렌더·자동 치환 제거와 따로 되돌릴 수 있게 나눠 배포합니다
- 알리페이 회원 화면, 진입 관문 스위치, 어드민 알리페이 회원 목록(BO-CH-11)의 배포는 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」을 따르고, 이 문서 1단계 배포 뒤에 진행합니다

### 목적

- 웹과 알리페이 앱을 따로 운영합니다.
  - 콘텐츠마다 웹, 알리페이 앱, 둘 다 중 어디에 보일지 정할 수 있게 합니다.
  - 콘텐츠마다 노출 채널 값(전체·웹·알리페이 앱)을 붙여 채널별로 거르는 방식입니다. 데이터를 따로 저장하지 않습니다.
- 알리페이 앱 안에서는 이용자를 앱 밖으로 내보내는 버튼과 링크를 없앱니다.
  - 알리페이 앱이 앱 밖 이동을 막고 있기 때문입니다.
- 운영 화면에서 건마다 들어온 채널(웹 / 알리페이 중국 / 알리페이 홍콩)을 볼 수 있게 합니다.

### 1. 요구사항

- 웹과 알리페이 앱을 별도 채널로 운영합니다.
  - 콘텐츠마다 어느 채널에 낼지를 정합니다.
  - 상품, 스토어, 배너, 기획전, 매거진에 노출 채널을 둡니다.
    - 값은 전체, 웹, 알리페이 앱 셋입니다.
    - 스토어 칼럼은 값을 따로 두지 않고 소속 스토어의 값을 따릅니다.
  - 웹에서도 알리페이 앱 전용 콘텐츠는 보이지 않습니다.
    - 두 채널이 같은 규칙으로 걸러집니다.
- 상품, 스토어, 배너의 하단 버튼은 웹용과 알리페이용을 따로 켤 수 있게 합니다.
  - 버튼은 노출 조건이 아닙니다.
  - 버튼이 없어도 콘텐츠는 노출됩니다.
- 알리페이 중국과 홍콩은 들어오는 주소 경로를 각 언어로 연결합니다.
  - 알리페이 중국은 중국어(간체) 경로, 알리페이 홍콩은 중국어(번체) 경로. 언어 선택 목록에는 영어까지 셋을 남깁니다.
- 어드민·호스트의 예약·채팅·상담·리뷰 화면과 스토어 문의 통계, 예약자 설문조사, 호스트 대시보드에서 건마다 들어온 채널(웹 / 알리페이 중국 / 알리페이 홍콩)을 “유입 채널”로 보고 거를 수 있게 합니다.
  - 호스트 대시보드는 예약 카드에 보여주기만 하고 거르지 않습니다(10장).
- 알리페이 회원 정보 연동과 예약 알림은 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」에서 다룹니다.

#### 웹이 함께 바뀌는 것

- 웹에도 노출 채널 조건이 붙습니다.
  - 알리페이 앱 전용 콘텐츠는 웹 목록·검색·상세·사이트맵에서 빠지고, 주소로 열면 404가 뜹니다(8장).
- 매거진·스토어 칼럼 에디터에 링크 도구로 넣은 우리 도메인 절대 주소는 저장할 때 상대 경로로 바뀝니다(5장).
- 하단 버튼 세는 법이 항목마다 한 자리로 바뀝니다.
  - 지금 상담접수와 문의하기를 한 자리로 세던 것이 두 자리가 됩니다.
  - 상한을 넘는 건은 배포 전에 운영자가 정리합니다(6장·13장).
- 기획전 구성 항목이 필수가 됩니다.
  - 활성 상태로 저장할 때 담은 항목이 0건이면 저장할 수 없습니다.
  - 비활성으로 저장할 때는 막지 않습니다(7장).
- 배너의 연결 대상은 배너 채널에 노출되는 것만 고를 수 있습니다(6장).
- 스토어 칼럼 에디터는 웹을 포함해 외부 링크와 외부 임베드를 넣을 수 없습니다.
  - 옛 칼럼을 고쳐 저장하면 남은 외부 링크·임베드가 지워집니다.
  - 매거진은 웹에서 지금처럼 허용합니다(5장).
- 랜딩페이지 배너의 하단 버튼은 연결 대상이 웹에 노출되지 않으면 웹에서도 버튼만 숨깁니다(6장).
- 기획전, 홈 큐레이션 섹션, 인플루언서 기획전, 매거진 본문 카드에서 웹에 노출되지 않는 항목이 빠집니다(8장).

### 3. 알리페이 앱 안의 제약

아래 제약이 채널별 버튼 구성을 나누는 근거입니다.

- 용어는 4장에 있습니다.

- 외부 링크로 이동하는 것이 막힙니다.
  - 알리페이 보안 정책상 차단됩니다.
- 타 메신저 앱으로 연결하는 것도 막힙니다.
  - 위챗을 포함한 모든 메신저가 같습니다.
- 인앱 채팅은 우리 자체 기능이라 제약 없이 동작합니다.
- 운영 방침: 알리페이 안에서는 이용자를 밖으로 내보내는 요소를 두지 않습니다.
  - 상품과 스토어의 외부링크 버튼과 메신저 버튼은 알리페이에서 켜지 않습니다.
  - 외부 주소로 연결되는 배너는 알리페이에 노출하지 않습니다.
    - 노출 채널이 웹으로 고정됩니다.
- 진출 방식은 현행 웹뷰 구조를 그대로 유지합니다.
  - 별도 미니앱을 새로 만들지 않습니다.
  - 알리페이 기술 담당과 합의한 내용입니다.
- 알리페이 사용자 정보 연동과 그에 필요한 확인 사항은 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」 2장·8장에 있습니다.

| 콘텐츠 | 노출 채널의 대상이 되는 단위. 상품, 스토어, 배너, 기획전, 매거진, 스토어 칼럼 여섯 종이고 이 중 스토어 칼럼은 값을 따로 두지 않습니다. 인플루언서 기획전은 URL로 밖에서 쓰는 랜딩이라 대상이 아닙니다 |
| 스토어 칼럼 | 호스트(원장)가 쓰는 글. 원장 칼럼이라고도 부릅니다. 매거진은 운영자가 쓰는 글입니다 |
| 칼럼 | 본문에서 홀로 쓴 “칼럼”은 목록 표의 세로 칸(노출 채널 칼럼, 칼럼설정)입니다. 글은 “스토어 칼럼”으로 씁니다. 상품과 나란히 쓴 “상품·칼럼”과 어드민 화면 문구 안의 “칼럼”은 어드민 메뉴명 그대로 스토어 칼럼(글)을 뜻합니다 |
| 버튼 | 콘텐츠 하단에 다는 행동 요소. 상품과 스토어는 상담접수, 채팅, 상담접수·채팅 통합 표시(라이브 이름 문의하기. 이 문서에서는 줄여서 통합 표시), 외부링크, 메신저, 예약을 각각 켜고 끄며, 배너는 내부이미지랜딩페이지의 하단 버튼 하나입니다. 어드민 화면의 “외부링크 설정”, “메신저 설정” 행이 외부링크, 메신저 버튼입니다 |
| 버튼 구성 | 한 콘텐츠에서 채널별로 켜 둔 버튼 묶음. 웹 버튼 구성과 알리페이 버튼 구성이 따로 있습니다. 노출과 무관합니다 |
| 버튼 자리 | 하단 버튼 하나가 차지하는 칸. 켜 둔 버튼 하나가 한 자리입니다. 채널마다 둘까지 |
| 외부 요소 | 버튼 구성 밖에서 외부와 연결되는 것. 메신저 카드, SNS 임베드, SNS 채널 아이콘, 본문 임베드·외부 링크, 전화·메일 링크. 알리페이 채널에서 일괄로 숨기거나 글자로 바꿉니다 |
| 외부 연결 계열 | 스위치와 무관하게 늘 적용되는 넷: 외부링크 배너의 알리페이 앱 숨김, 외부링크·메신저 버튼의 알리페이 앱 비표시, 메신저 카드·SNS 임베드·SNS 채널 아이콘 숨김, 본문 외부 링크·임베드의 알리페이 앱 변환. 판정 조건 ①~④와는 다른 것입니다 |
| 구성 항목 | 기획전에 담은 상품 또는 스토어. “담은 항목”과 같은 말입니다 |
| 연결 대상 | 배너가 내부링크로 가리키는 대상. 내부링크 종류는 직접입력, 병원(=스토어), 기획전(=그 언어의 기획전 유형), 인플루언서(=인플루언서 기획전) 넷. 랜딩페이지 배너의 하단 버튼이 내부링크로 가리키는 대상도 연결 대상이라 부릅니다. 본문에서 연결 대상은 배너(본체·하단 버튼)에만 씁니다. 기획전 목록의 사유 값 “연결 대상이 {웹 / 알리페이 앱}에 없음”에서만 기획전이 담은 항목(④)을 가리킵니다 |
| 랜딩페이지 배너 | 링크종류가 내부이미지랜딩페이지인 배너. 하단 버튼이 있는 유일한 배너입니다 |
| 참조 정리 | 기획전처럼 다른 콘텐츠를 묶어 보여주는 화면에서, 그 채널에 노출되지 않는 항목을 목록에서 빼는 것. 두 채널 같습니다 |
| 렌더 | 고객 화면을 그려 보여주는 단계. “렌더 때 숨긴다”는 저장된 데이터는 두고 보여줄 때만 뺀다는 뜻입니다 |
| 폴백 | 1순위 처리가 안 될 때 대신 쓰는 처리. 노출되지 않는 주소의 404 |
| 공통 필터 | 기존 노출 조건(②)에 ①③④와 채널 종속을 더해 웹과 알리페이 앱의 모든 노출면에 똑같이 적용해, 그 채널에 노출되지 않는 콘텐츠를 숨기는 처리(FO-CH-02). 스위치로 켜고 끄며(13장), 끄면 ①③④와 채널 종속만 빠집니다 |
| 토스트 안내 | 어드민 화면 위쪽에 4초 동안 떴다가 저절로 사라지는 한 줄 안내. 버튼이 없고 눌러서 닫지 않습니다 |
| 알림 창 | 제목, 본문, 확인 버튼 하나로 된 작은 창. 저장을 막은 이유나 저장 결과를 알리고 확인을 누르면 닫힙니다 |
| 기본 설정 / 개별 설정 | 상품 버튼 설정의 “스토어 설정 적용” 값. 기본 설정이면 상품의 웹 열과 알리페이 열이 예약 줄까지 스토어 값을 그대로 따르고, 개별 설정이면 상품이 따로 정합니다 |
| 모달(확인 모달) | 화면 위에 겹쳐 뜨는 창. 취소와 실행 버튼 둘로 운영자 선택을 받거나(확인 모달) 등록·수정 폼을 담습니다. 화면 ID의 -mdl은 알림 창에도 붙입니다. 어느 종류인지는 각 문구에 적습니다. 모달·알림 창의 본문은 문장마다 줄을 바꿔 보여줍니다. 문구에서 버튼 뒤의 (주)는 강조 버튼이라는 뜻이고 화면 라벨에는 붙이지 않습니다 |
| 스위치 | 배포 없이 켜고 끌 수 있는 기능 단위. 이 문서에서는 공통 필터 스위치 하나입니다(13장). 어드민 화면 없이 서버 구성 값으로 두고 운영자 요청으로 개발이 바꿉니다. 진입 관문 스위치는 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」 7장 |
| 집계 1~5 | 배포 전에 개발이 뽑아 운영에 넘기는 정리 대상 목록 다섯(13장) |
| 매장 | 호스트 화면 문구에서 스토어를 부르는 말 |

### 5. 노출 채널

BO-CH-01 / 03 / 05 / 07 / 08 / 13, SYS-CH-01 / 02

전제: 콘텐츠가 실제로 보이는지는 노출 채널 값과 기존 노출 조건이 함께 정합니다.

- 노출 채널은 어디에 낼지만 정합니다.
- 공개여부, 활성화, 히든, 노출 기간, 게시 상태 같은 기존 조건은 그대로 별개로 적용됩니다.
- 화면 문구는 7장에 모아 두었습니다.

- 대상: 상품, 스토어, 배너, 기획전, 매거진, 스토어 칼럼.
  - 인플루언서 기획전은 대상이 아닙니다.
    - URL을 밖에서 공유해 쓰는 랜딩 페이지라 어느 도메인에서든 주소로 열립니다.
    - 배너의 연결 대상으로 고를 때는 담은 상품으로 판정합니다(6장).
    - 어느 채널에서 인플루언서 기획전 페이지를 열면 담은 상품 중 그 채널에 노출되지 않는 상품 카드는 뺍니다(8장 참조 정리).
    - 그 채널에 노출되는 담은 상품이 0건이면 그 채널에서 그 주소는 404입니다.
  - 홈 큐레이션 섹션은 콘텐츠가 아니라 지면입니다.
    - 설정을 두지 않고 담은 항목을 따라갑니다(8장).
- 설정 위치: 각 콘텐츠의 등록과 수정 화면. 상품은 관리자설정 탭 노출 설정 안, 스토어는 기본정보 섹션 카테고리 바로 아래(지원언어 위), 매거진은 게시 언어 탭의 노출 정보 영역이며 탭마다 값이 독립입니다(탭 = 건).

| 값 | 의미 | 비고 |
|---|---|---|
| 전체 | 웹과 알리페이 앱 모두 노출 | 디폴트. 기존 콘텐츠와 새 콘텐츠 전부 |
| 웹 | 웹에만 노출 | 알리페이 앱에서 숨김 |
| 알리페이 앱 | 알리페이 앱에만 노출 | 웹 목록·검색·상세·사이트맵에서 숨김 |

#### 스토어 종속

- 상품과 스토어 칼럼은 자기 스토어의 노출 채널을 따릅니다.
  - 스토어가 전체면 상품은 셋 중 자유롭게 고르고 스토어 칼럼은 전체입니다.
  - 스토어가 웹이면 상품·칼럼은 웹으로 고정됩니다.
    - 알리페이 앱이면 알리페이 앱으로 고정됩니다.
    - 상품은 라디오를 잠그고 그 아래 한 줄로 알립니다.
    - 칼럼에는 설정 자리가 없습니다.
  - 고정되어도 상품의 저장값은 건드리지 않습니다.
    - 스토어를 전체로 되돌리면 상품은 저장값대로, 칼럼은 전체로 돌아옵니다.
  - 스토어가 웹으로 바뀌면 그 스토어의 상품·칼럼이 전부 알리페이 앱에서 빠집니다.
    - 반대로 상품이 전부 빠져도 스토어는 자동으로 숨기지 않습니다.
- 새로 등록하는 상품의 저장값은 전체로 시작합니다.
  - 스토어 칼럼은 저장값이 없습니다.
  - 화면과 목록에는 스토어 종속을 반영한 유효값이 보입니다.
  - 어드민과 호스트가 같습니다.
  - 호스트 화면에는 노출 채널 설정이 없습니다.
  - 알리페이 앱 전용 상품은 호스트와 협의해 운영자가 어드민에서 정합니다.
  - 지원언어에 중국어(간체)·중국어(번체)·영어가 하나도 없는 스토어는 웹으로 고정되고 스토어 자신의 노출 채널 라디오가 잠깁니다.
    - 스토어 라디오에는 잠금 사유 안내가 없습니다(상시 안내 줄은 그대로).
    - 스토어 버튼 표의 알리페이 열에는 안내 한 줄이 붙습니다.
    - 지원언어에서 뺀 언어의 상품은 현행대로 노출되지 않고, 남은 상품·칼럼은 대상 외 언어 건이라 따로 안내하지 않습니다.
    - 지원언어 저장은 현행처럼 확인 창 없이 바로 저장됩니다.
    - 지원언어는 1개 이상 골라야 저장됩니다(현행). 대상 언어를 모두 빼도 다른 언어가 하나 남아 있으면 저장됩니다.
  - 일본어·인도네시아어·몽골어(대상 외 언어)는 웹에 노출되는 스토어만 지원언어에 켤 수 있습니다.
    - 노출 채널이 알리페이 앱인 스토어는 지원언어에서 대상 외 언어를 켤 수 없습니다. 라디오에서 알리페이 앱이 선택된 동안 지원언어의 일본어·인도네시아어·몽골어 칸은 비활성이라 켤 수 없습니다. 안내 문구는 두지 않습니다.
    - 대상 외 언어가 하나라도 켜진 스토어는 노출 채널을 알리페이 앱으로 바꿀 수 없습니다(웹을 끌 수 없습니다. 아래 줄).
  - 일본어·인도네시아어·몽골어 상품이나 그 언어를 켠 스토어 칼럼이 있는 스토어, 지원언어에 그 언어가 있는 스토어는 알리페이 앱 전용으로 바꿀 수 없습니다.
    - 그 언어의 스토어 페이지는 웹에만 있어서, 알리페이 앱 전용이 되면 어디에도 보이지 않기 때문입니다.
    - 고르는 순간 알림 창으로 막고, 알림 창을 닫으면 라디오는 누르기 직전 값으로 돌아갑니다.
    - 건수는 삭제된 건만 빼고 셉니다.
  - 알리페이 앱 전용 스토어의 지원언어에는 대상 언어만 있으므로, 대상 언어를 모두 빼면 지원언어가 0개가 되어 현행 규칙(1개 이상)대로 저장되지 않습니다.
  - 노출 채널 유효값이 알리페이 앱인 칼럼(알리페이 앱 전용 스토어의 칼럼)은 보여줄 언어에서 일본어·인도네시아어·몽골어를 켤 수 없습니다.
    - 일본어·인도네시아어·몽골어만 켜진 칼럼은 웹으로 고정됩니다.
  - 알리페이 앱 전용 스토어에는 호스트도 어드민도 일본어·인도네시아어·몽골어 상품을 등록할 수 없습니다.
    - 그래서 대상 외 언어 건이 어디에도 안 나가는 상태는 생기지 않습니다.

#### 설정 단위와 언어

- 설정은 콘텐츠 한 건 단위입니다.
  - 언어를 따로 고르는 설정은 없습니다.
  - 상품, 배너, 기획전, 매거진은 등록할 때 언어를 하나 정해 올라갑니다.
    - 건이 곧 언어라 간체 건과 번체 건이 따로 있고 설정도 각각입니다.
    - 매거진은 게시 언어 탭 하나가 한 건입니다.
  - 스토어는 한 곳이 언어와 무관한 한 건입니다.
    - 설정 하나가 모든 언어에 적용됩니다.
    - 라디오 아래에 상시 안내 한 줄을 둡니다.
  - 스토어 칼럼은 값을 따로 두지 않습니다.
    - 스토어 값을 따르고, 일본어·인도네시아어·몽골어만 켜진 글은 웹입니다.
- 알리페이가 지원하는 언어는 9장의 언어 목록을 따릅니다.
  - 지금은 중국어(간체), 중국어(번체), 영어 셋입니다.
  - 일본어, 인도네시아어, 몽골어 건은 알리페이 앱에 나갈 수 없습니다.
    - 노출 채널을 고르지 않고 웹으로 고정됩니다.
    - 라디오와 알리페이 쪽 버튼 열이 비활성이고 안내 문구는 두지 않습니다.
    - 잠긴 알리페이 열은 버튼 상한 검사에서 빼고 표 아래 자리 수에 알리페이 앱 0개로 적습니다.
    - 목록에서 그 언어를 고르면 노출 채널 칼럼에 웹이 보이고 필터는 노출 채널 (전체)로 돌아가 잠깁니다.
  - 배너와 기획전은 언어를 바꿀 수 있습니다.
    - 대상 외 언어로 바꾸면 그 순간 웹으로 고정되고, 다시 대상 언어로 바꾸면 저장값이 돌아옵니다.
    - 언어를 바꿀 때마다 그 언어의 규칙이 다시 돕니다.
  - 언어와 경로 대응: 중국어(간체)=zh, 영어=en, 중국어(번체)=zh-TW, 일본어=ja, 인도네시아어=id, 몽골어=mn.
- 링크종류가 외부링크인 배너는 알리페이 앱에서 열 수 없어 웹으로 고정됩니다.
  - 라디오를 잠그고 아래 한 줄로 알립니다.
  - 내부링크로 바꾸면 저장값이 돌아옵니다.

| 콘텐츠 | 노출 채널 | 버튼 구성 |
|---|---|---|
| 상품 | 건별 1개. 스토어 값에 종속 | 건별 1개. 기본 설정 시 스토어 값 적용 |
| 스토어 | 스토어별 1개. 전 언어 공통 | 스토어별 1개. 전 언어 공통 |
| 배너 | 건별 1개. 외부링크 배너는 웹 고정 | 랜딩페이지 배너에 한해 하단 버튼 1개. 알리페이 표시여부 별도 |
| 기획전 | 건별 1개 | 해당 없음 |
| 매거진 | 건별 1개 | 해당 없음 |
| 스토어 칼럼 | 없음. 스토어 값에 종속 | 해당 없음 |

#### 판정 규칙

아래 판정 조건 ①~④를 모두 만족하는 콘텐츠 건만 그 채널에 노출됩니다.

- 웹 채널과 알리페이 채널이 같은 규칙입니다.
- 표에서 해당 없음인 조건은 통과로 봅니다.
- 조건 번호는 13장의 배포 단계(1단계~5단계)와 별개입니다.

| 콘텐츠 | ① 노출 채널 | ② 기존 노출 조건 | ③ 연결 대상 | ④ 담은 항목 |
|---|---|---|---|---|
| 상품 | 유효값(스토어 종속) | 승인·활성·히든. 소속 스토어가 그 채널에 노출 | 해당 없음 | 해당 없음 |
| 스토어 | ○ | 공개여부·언어별 노출 | 해당 없음 | 해당 없음 |
| 배너 | ○ (외부링크는 웹) | 광고표기여부·광고진행일정 | ○ | 해당 없음 |
| 기획전 | ○ | 활성화·노출 기간 | 해당 없음 | ○ |
| 매거진 | ○ | 게시 상태 | 해당 없음 | 해당 없음 |
| 스토어 칼럼 | 유효값(스토어 종속) | 게시중·언어 노출. 소속 스토어가 그 채널에 노출 | 해당 없음 | 해당 없음 |

- ① 그 건의 노출 채널 유효값(4장)이 전체이거나 지금 채널과 같습니다.
- ② 지금 웹이 쓰는 노출 조건 그대로입니다.
  - 여기에 스토어 종속이 더해집니다.
  - 상품과 스토어 칼럼은 소속 스토어가 그 채널에 노출될 때(스토어의 ①②를 통과할 때)만 통과합니다.
  - 공통 필터 스위치를 끄면 ①③④와 함께 스토어 종속도 풀립니다.
  - 스토어 종속은 노출 채널 값에서 나오는 조건이기 때문입니다.
  - 풀리는 것은 채널 종속뿐이고, 소속 스토어 조건(스토어의 ②)과 ②의 나머지 기존 노출 조건은 그대로입니다(13장).
- ③ 배너만. 내부링크로 가리키는 대상(병원·기획전·인플루언서·패턴에 맞는 직접입력)이 그 채널에 노출되어야 합니다.
  - 등록할 때 채널에 맞지 않는 대상은 애초에 고를 수 없게 막고, 연결한 뒤 대상 쪽이 바뀌는 경우만 자동으로 숨깁니다.
  - 랜딩페이지 배너의 하단 버튼이 가리키는 대상은 배너 노출과 무관합니다.
  - 그 대상이 채널에 없으면 그 채널에서 버튼만 숨깁니다.
  - 구성 방법은 6장. 랜딩페이지 배너 본체는 대상이 없어 ③을 통과로 봅니다.
- ④ 기획전만. 담은 항목 중 그 채널에 노출되는 것이 한 건 이상 남아 있습니다.
  - 채널마다 따로 셉니다.
  - 심사 반려·비활성·히든처럼 기존 조건에서 이미 빠진 항목은 세지 않습니다.
- 새로 등록했거나 배포 직후라 연결 대상·담은 항목의 노출 여부가 아직 반영되지 않은 배너·기획전은 ③④를 통과로 보고 숨기지 않습니다.
- 버튼은 판정 조건이 아닙니다.
  - 버튼이 하나도 없어도 노출되고 하단 버튼 영역만 접힙니다.
- 기획전의 구성 항목은 기획전 유형이 정합니다.
  - 유형 값은 병원, 추천상품, 특가, TOP10 네 가지입니다.
    - 병원은 스토어를 담고 나머지 셋은 상품을 담습니다.
  - 담는 종류가 달라지는 유형으로 바꿀 때 이미 담아 둔 항목이 있으면 먼저 확인을 띄웁니다(문구는 7장).
  - 구성 항목 표에 노출 채널 칼럼을 넣습니다.
    - 값은 각 항목의 유효값이고 이 화면에서 편집하지 않습니다.

#### 저장값 보존

- ③④ 때문에 노출되지 못하는 경우에도 콘텐츠의 노출 채널 저장값은 건드리지 않습니다.
  - 조건이 풀리면 보존해 둔 값대로 다시 노출됩니다.
- 스토어 종속으로 고정된 상품도 저장값을 그대로 둡니다.
  - 스토어를 되돌리면 원래 값대로 돌아옵니다.
  - 칼럼은 저장값이 없습니다.
- ③④로 숨겨진 배너와 기획전은 목록의 사유 칼럼에 이유가 표시됩니다.
  - 상품·스토어 목록에는 사유 칼럼이 없습니다.
  - 값은 7장에 있습니다.

#### 본문 에디터의 외부 링크·임베드

- 본문 에디터를 쓰는 화면은 매거진과 스토어 칼럼 둘뿐입니다.
  - 상품과 기획전에는 본문 에디터가 없고, 스토어 소개도 본문 에디터가 아닙니다.
- 매거진은 운영자가 쓰는 글이라 웹에서는 외부 링크와 외부 임베드를 지금처럼 허용합니다.
  - 알리페이 채널에서 보여줄 때는 외부 링크를 글자로 바꾸고 외부 임베드를 숨깁니다(6장 외부 요소).
  - 저장된 본문은 바꾸지 않습니다.
  - 노출 채널 유효값에 알리페이 앱이 포함된 매거진(유효값이 전체 또는 알리페이 앱)을 저장할 때 본문에 외부 링크나 허용 목록에 없는 외부 임베드가 있으면, 알림 창(BO-CH-07-mdl)으로 알리페이 앱에서 어떻게 보이는지 알립니다.
  - 매거진의 내부 연결 정식 경로는 상품 추가·스토어 추가 버튼입니다.
    - 이미 있는 기능이고 이번 범위에서 손대지 않습니다.
    - 이 버튼으로 넣은 카드는 내부 참조입니다.
    - 카드가 가리키는 대상이 어느 채널에 노출되지 않으면 그 채널에서 렌더할 때 카드만 빠집니다(8장).
    - 스토어 칼럼에는 카드 기능이 없습니다.
- 스토어 칼럼은 호스트가 쓰는 글이라 웹을 포함해 외부 링크와 외부 임베드(iframe·script·object)를 넣을 수 없게 막습니다.
  - 허용 목록 없이 전부 막습니다.
  - 막는 것은 링크 도구로 직접 입력하거나 붙여넣기로 들어오는 외부 주소입니다.
    - 외부 주소인지는 호스트 완전 일치로 가립니다.
    - 허용하는 주소는 http·https 주소와 상대 경로이고 ftp·mailto·tel 같은 다른 스킴은 외부입니다.
    - 스킴 없이 적은 주소(example.com/promo)는 첫 구간을 호스트로 읽어 내부 호스트 셋이 아니면 외부로 봅니다.
    - 호스트 뒤의 포트·?·#는 호스트 일치에 영향이 없습니다.
    - 내부는 www.k-beautystation.com, k-beautystation.com, alipay-app.kbstations.com 셋뿐이고 어드민·호스트 도메인은 외부로 봅니다.
    - javascript:·data:·프로토콜 상대 주소와 유사 호스트는 외부로 봅니다.
    - 배너 내부링크 직접입력은 이 기준을 쓰지 않고 /로 시작하는 우리 사이트 경로만 받습니다(6장).
  - 붙여넣기로 들어온 외부 링크·임베드는 저장할 때 제거되고 글자만 남습니다.
    - 제거하기 전 원문을 보관합니다.
    - 되돌리기는 운영자가 어드민 칼럼 상세(BO-CH-13)의 “원문 복원” 버튼으로 합니다.
    - 복원은 가장 최근에 지우기 직전 본문으로 되돌립니다.
    - 복원한 본문의 외부 링크는 웹에서 그대로 보이고 알리페이 채널에서는 글자로 바뀝니다.
    - 호스트가 다시 저장하면 다시 지워지고 원문 보관도 새로 합니다.
    - 호스트에게 저장 후 지운 개수를 “저장했어요” 창으로 알립니다(7장 HOST).
    - 운영자가 어드민 칼럼 상세(BO-CH-13)에서 저장할 때는 본문을 검사하지 않습니다.
  - 차단 이전에 쓴 칼럼에 남은 외부 링크·임베드는 알리페이 채널에서 보여줄 때 글자로 바꾸거나 숨깁니다(6장).
    - 기존 칼럼은 13장의 마이그레이션 때 목록으로 뽑아 정리합니다.
    - 호스트가 옛 칼럼을 다른 항목만 고쳐 저장해도 본문 전체를 검사해 남은 외부 주소·임베드를 지우고 저장 후 알립니다.
    - 매거진에는 이 규칙이 없습니다.
- 두 에디터 모두 링크 도구로 직접 입력한 내부 주소(내부 호스트 셋의 절대 URL 포함)는 상대 경로로 바꿔 저장합니다.

### 6. 버튼 설정

BO-CH-10 / FO-CH-05

#### 채널마다 버튼을 따로 켭니다

- 상품과 스토어의 하단 버튼 설정은 지금처럼 버튼마다 ON/OFF입니다.
  - 이 구조는 바꾸지 않습니다.
  - 배너는 아래 배너 절에서 따로 다룹니다.
- 여기에 알리페이용 ON/OFF를 나란히 하나 더 둡니다.
  - 웹에서 켠 것과 알리페이에서 켠 것이 다를 수 있습니다.
  - 웹에서 켠 묶음이 웹 버튼 구성, 알리페이에서 켠 묶음이 알리페이 버튼 구성입니다.
- 버튼 자리는 채널마다 둘까지입니다.
  - 웹 둘과 알리페이 둘이 동시에 가능합니다.
  - 상담접수, 채팅, 상담접수·채팅 통합 표시, 외부링크, 메신저, 예약은 각각 독립된 버튼 종류이고 켜져 있으면 항목마다 한 자리를 씁니다.
  - 서로 묶이거나 대신 세어지는 항목은 없습니다.
  - 통합 표시는 기존 문의하기 버튼 그대로입니다.
  - 웹 열도 같은 세는 법을 씁니다.
  - 지금 웹에서 상담접수와 문의하기를 한 자리로 세던 방식은 이 배포로 항목별 한 자리로 바뀝니다.
- 버튼은 노출 조건이 아닙니다.
  - 알리페이 열이 비어 있어도 콘텐츠는 노출되고 하단 버튼 영역만 접힙니다.
  - 버튼이 비었다는 안내나 저장 확인은 두지 않습니다.
- 노출 채널이 웹이면 알리페이 열을, 알리페이 앱이면 웹 열을 비활성으로 잠급니다.
  - 값은 지우지 않고, 잠긴 칸은 저장된 값을 흐리게 보여줍니다. 고객 화면에는 나가지 않습니다.
  - 전체로 되돌리면 열리고, 열린 열은 꺼진 상태로 시작합니다. 잠기기 전 값으로 돌아오지 않습니다.
    - 그래서 잠금이 풀려 버튼 자리가 넘치는 일은 없습니다.
    - 스토어의 노출 채널이나 지원언어를 바꿔 알리페이 열 잠금이 풀리면, 스토어를 저장하는 순간 그 스토어와 그 스토어의 개별 설정 상품의 풀린 알리페이 열을 모두 끈 값으로 저장합니다.
  - 표 아래 한 줄로 알립니다.
  - 지원언어 때문에 웹으로 고정된 스토어의 알리페이 열도 같습니다.
- 상품은 지금처럼 스토어 설정 적용을 개별 설정과 기본 설정 중에서 고릅니다.
  - 기본 설정이면 웹 열과 알리페이 열 모두 스토어 값을 그대로 따릅니다.
  - 기본 설정인 상품은 늘 스토어의 현재 버튼 값으로 보이고 편집은 잠깁니다.
  - 개별 설정으로 바꾸면 두 열 모두 스토어 현재 값을 복사해 시작합니다.
    - 그 뒤에는 자유롭게 편집합니다.
  - 스토어의 버튼 설정을 바꾸면 기본 설정인 상품 전부에 바로 적용됩니다.
    - 기본 설정 상품은 스토어와 같은 버튼이라 채널마다 2자리를 넘지 않습니다. 개별 설정에서 기본 설정으로 바꿀 때도 같습니다.
- 매거진, 스토어 칼럼, 기획전에는 하단 버튼이 없습니다.
- 버튼 설정에서 저장을 막는 것은 버튼 자리 상한을 넘겼을 때뿐입니다(7장).

#### 버튼 종류와 알리페이 사용 가능 여부

| 버튼 | 상품 | 스토어 | 알리페이 | 비고 |
|---|---|---|---|---|
| 상담접수 | 있음 | 있음 | 가능 | 자체 기능 |
| 채팅 | 신설 | 신설 | 가능 | 인앱 채팅. 이번에 단독 항목으로 추가 |
| 상담접수·채팅 통합 표시 | 있음 | 있음 | 가능 | 기존 문의하기 버튼 그대로. 독립된 버튼이라 켜면 한 자리. 신규 콘텐츠는 두 열 모두 꺼진 채 시작하고 기존 웹 열 값은 그대로 |
| 외부링크 | 있음 | 있음 | 잠김(켤 수 없음) | 외부로 이동 |
| 메신저 | 있음 | 있음 | 잠김(켤 수 없음) | 외부 앱으로 이동 |
| 예약 | 있음 | 있음 | 가능 | 예약설정 섹션에서 예약을 켜야 켤 수 있습니다 |

- 예약은 스토어와 상품 모두에 있고, 다른 버튼과 같은 하나의 버튼입니다.
  - 웹 열과 알리페이 열을 따로 두고, 자리 세는 법과 잠금 규칙은 다른 버튼과 같습니다.
  - 예약 설정을 끄면 값은 지우지 않고 흐리게 잠기고 고객 화면에 나가지 않습니다. 다시 켜면 두 예약 버튼 모두(웹·알리페이 열 모두) 꺼진 상태로 시작하고 운영자가 다시 켭니다. 다른 버튼 값은 그대로입니다.
- 알리페이에서 동작하지 않는 외부링크와 메신저는 알리페이 열에서 비활성으로 두고 행 오른쪽에 미지원 안내를 붙입니다.
- 마이그레이션에서 예약 설정을 쓰는 스토어는 알리페이 열에 예약과 상담접수를, 쓰지 않는 스토어는 상담접수를 켭니다(13장).
  - 예약 설정을 나중에 켠 스토어는 운영자가 예약 버튼을 켭니다.
  - 자동으로 켜지 않습니다.

#### 배너

- 배너의 링크종류는 외부링크, 내부링크, 내부이미지랜딩페이지 셋입니다.
  - 이 구조는 바꾸지 않습니다.
- 링크종류가 외부링크인 배너는 노출 채널이 웹으로 고정됩니다(5장).
  - 설정을 두지 않고 라디오를 잠급니다.
- 하단 버튼은 랜딩페이지 배너에만 하나 있습니다.
  - 버튼 표시여부, 버튼 텍스트, 버튼 링크 종류, 버튼 링크로 구성됩니다.
  - 버튼 링크 종류에 내부링크를 추가합니다.
    - 선택 방식은 배너 자체의 내부링크와 같습니다.
    - 하단 버튼의 대상 선택지는 배너와 같은 언어만 나오고 노출 채널로는 거르지 않으며, 저장도 막지 않습니다(직접입력이 /로 시작하는 경로가 아닌 것은 예외로 막습니다).
    - 대상이 채널에 없거나 직접입력 대상을 찾지 못하면 그 채널에서 버튼만 숨깁니다.
    - 판정 기준은 배너 자체의 대상 판정과 같습니다.
    - 기존의 링크없음, 외부링크는 그대로 둡니다.
    - 링크없음 버튼은 대상이 없으므로 대상 조건 없이 그 채널의 표시여부만 따릅니다.
  - 버튼 표시여부에 알리페이 열을 둡니다.
    - 웹 활성화/비활성화 옆에 알리페이 활성화/비활성화가 나란히 있습니다.
  - 버튼 링크 종류가 외부링크면 알리페이 열은 비활성으로 잠급니다.
    - 배너는 알리페이 앱에 노출되고 버튼만 안 나갑니다.
    - 잠긴 동안 표시는 비활성화이고 저장값은 유지합니다.
    - 내부링크나 링크없음으로 바꾸면 저장값대로 돌아옵니다.
  - 하단 버튼의 내부링크 대상이 어느 채널에 노출되지 않으면 그 채널에서 버튼만 숨깁니다.
    - 배너는 그대로 노출됩니다.
    - 웹도 같습니다.
    - 수정 화면에 안내를 두고 목록 사유는 생기지 않습니다.
  - 알리페이 열을 운영자가 직접 비활성화해도 배너는 노출됩니다.
    - 하단 버튼 없는 랜딩페이지가 열립니다.
    - 안내는 두지 않습니다.
- 내부링크 종류는 직접입력, 병원, 기획전, 인플루언서 넷입니다.
  - 셀렉트 종류에 상품은 없습니다.
  - 상품은 직접입력 주소(/products/{id})로 연결합니다.
- 연결 대상은 등록할 때 배너 채널에 맞는 것만 고를 수 있습니다.
  - 병원·기획전·인플루언서 셀렉트에는 배너와 같은 언어이면서 배너의 노출 채널에 나가는 대상만 나옵니다.
    - 기준은 저장값이 아니라 판정입니다.
    - 배너가 나가는 채널마다 그 채널에 노출되는 대상만 나오고, 배너가 전체면 두 채널 모두에 노출되는 대상만 나옵니다.
    - 이미 골라 둔 대상은 조건이 안 맞아도 목록에 남습니다.
  - 직접입력은 주소가 가리키는 대상의 노출 채널을 옆에 표시합니다.
    - 대상의 판정이 배너 채널에 맞지 않으면 저장을 막습니다.
  - 배너의 노출 채널이나 언어를 바꿔서 이미 고른 대상이 안 맞게 되어도 같은 문구로 저장을 막습니다.
    - 사후 변경으로 이미 어긋나 있던 배너라도, 이번 수정에서 대상·노출 채널·언어 중 하나를 바꿨고 바꾼 뒤에도 어긋나면 막습니다.
- 연결한 뒤 대상 쪽이 바뀌어 채널에서 빠지면 배너도 그 채널에서 자동으로 숨깁니다.
  - 등록 시 막을 수 없는 사후 변경만 이 규칙이 받습니다.
  - 대상의 노출 채널·언어·활성·기간·삭제가 바뀌는 경우입니다.
    - 수정 화면에 안내 박스를 두고 목록에 사유를 표시합니다(문구와 값은 7장).
  - 배너의 저장값은 건드리지 않습니다.
    - 대상이 돌아오면 배너도 별도 조작 없이 돌아옵니다.
  - 병원(=스토어)은 스토어의 판정을 따릅니다.
  - 기획전으로 고르는 것은 기획전 한 건이 아니라 그 언어의 유형 레코드입니다.
    - 유형 값 네 가지가 언어별로 하나씩 있고 배너는 그 레코드를 가리킵니다.
    - 같은 유형 값과 언어의 레코드는 하나만 둡니다.
    - 유형 관리에서 같은 조합을 더 만들 수 없게 막고, 이미 둘 이상인 것은 13장 집계 4로 정리합니다.
    - 유형에 붙은 기획전 중 하나라도 그 채널에 노출되면 연결 대상으로 통과합니다.
  - 대상이 기존 노출 조건에서 이미 빠져 있으면 연결 대상으로 치지 않습니다.
    - 노출 기간 안은 시작일 ≤ 오늘 ≤ 종료일입니다.
    - 오늘은 서버의 한국 시간 날짜입니다.
    - 스토어는 기간이 없고 공개여부와 삭제 여부만 봅니다.
    - 삭제된 대상은 존재하지 않는 것으로 봅니다.
  - 배너와 대상의 언어가 다르면 연결 대상으로 치지 않습니다.
    - 스토어는 언어를 나누지 않아 이 검사에서 제외합니다.
    - 다만 배너 언어의 언어별 노출이 꺼진 스토어는 연결 대상으로 치지 않습니다.
  - 인플루언서는 인플루언서 기획전을 가리킵니다.
    - 노출 채널이 없으므로 담은 상품으로 봅니다.
    - 배너와 같은 언어이고, 활성 상태이며, 노출 기간 안이고, 담은 상품 중 배너 채널에 노출되는 것이 1건 이상일 때 통과합니다.
    - 패스워드는 성과 페이지 접근용이라 판정에 관계없습니다.
    - 담은 상품의 언어는 보지 않습니다.
  - 직접입력으로 넣은 주소는 우리 경로 패턴(/products/{id}, /stores/{id}, /collections/{id}, /influencers/{id})으로 읽어(/stores/{id}는 종류를 병원으로 표시) 대상을 특정하고 그 대상의 판정을 따릅니다.
    - /collections/{id}는 기획전 한 건을 가리킵니다.
    - 신규 등록이거나 이번 수정에서 주소를 바꿨는데 대상을 찾을 수 없으면 저장을 막습니다.
    - 저장 뒤 대상이 삭제된 경우는 사후 변경으로 처리합니다.
    - 앞에 붙은 언어 경로(/en, /zh 등)와 물음표·샵 뒤의 값은 무시합니다.
    - 패턴에 맞지 않는 주소(카테고리·검색·홈 등 목록 페이지)는 대상을 특정할 수 없어 판정하지 않고 그대로 노출합니다.
    - 입력칸 옆 표시는 7장.
  - 내부링크 직접입력에는 우리 사이트 경로(/로 시작하는 주소)만 씁니다.
    - /로 시작하지 않는 주소(https:// 주소 전체, 도메인, mailto: 등)와 //로 시작하는 주소는 외부 사이트로 읽지 않고 입력칸 옆에 “/로 시작하는 경로만 입력할 수 있습니다”를 보이며 저장을 막습니다.
    - 외부 사이트는 링크종류의 외부링크로 연결합니다.
    - 하단 버튼의 직접입력도 같습니다.

#### 버튼 구성에 따른 결과

| 대상 | 웹 | 알리페이 | 알리페이에서 |
|---|---|---|---|
| 스토어 | 예약, 상담접수 | 예약, 상담접수 | 스토어와 두 버튼이 노출됩니다 |
| 스토어 | 예약 | 예약 | 스토어와 예약 버튼이 노출됩니다 |
| 상품 | 메신저 | 없음 | 상품은 노출되고 버튼 영역이 접힙니다 |
| 상품 | 메신저 | 채팅 | 상품과 채팅 버튼이 노출됩니다 |
| 상품 | 외부링크, 상담접수 | 상담접수 | 상품이 노출되고 외부링크는 웹에만 남습니다 |
| 상품(기본 설정) | 스토어: 예약만 | 스토어: 예약만 | 스토어 값을 따르므로 상품과 예약 버튼이 노출됩니다 |
| 배너 | 링크종류 외부링크 | 해당 없음 | 웹 고정. 배너가 노출되지 않습니다 |
| 배너 | 랜딩페이지, 버튼 외부링크 | 버튼 표시여부 비활성화로 잠김 | 배너는 노출되고 버튼이 없습니다 |
| 배너 | 내부링크, 대상 병원이 알리페이 앱에 없음 | 해당 없음 | 등록 시 고를 수 없습니다. 사후 변경이면 배너가 숨겨집니다 |
| 배너 | 랜딩페이지, 버튼 내부링크 (대상이 알리페이 앱에 노출) | 버튼 활성화 | 배너와 버튼이 노출됩니다 |
| 배너 | 랜딩페이지, 버튼 내부링크 (대상이 알리페이 앱에 없음) | 버튼 활성화 | 배너는 노출되고 버튼은 없습니다 |

#### 채팅 항목 신설

- 인앱 채팅은 지금도 살아 있는 기능입니다.
  - 다만 상담접수·채팅 통합 표시(라이브 이름 문의하기, 어드민 라벨 “문의하기(상담+채팅)로 통합 노출”) 안에 묶여 있거나, 알리페이 도메인에서 메신저 버튼을 대신 보여주는 형태로만 나옵니다.
  - 단독으로 켤 수 없습니다.
- 채팅을 단독 ON/OFF 항목으로 추가합니다.
  - 새 채팅 기능을 만들지 않습니다.
  - 채팅 버튼은 지금 문의하기 안의 채팅과 같은 방을 엽니다.
    - 상품 화면이면 상품 채팅방, 스토어 화면이면 스토어 채팅방입니다.
  - 버튼 라벨은 기존 인앱 채팅 진입 문구를 언어별로 그대로 씁니다.
- 웹에서도 켤 수 있습니다.
  - 알리페이 전용이 아닙니다.
- 채팅의 웹 열은 기존 콘텐츠와 새 콘텐츠 모두 OFF로 시작합니다.

#### 메신저 자동 치환 제거

- 2장에 적은 메신저 버튼의 인앱 채팅 자동 치환을 없앱니다.
- 치환으로 보이던 채팅 버튼이 알리페이 앱에서 사라지는 것은 의도한 결과입니다.
  - 알리페이에 채팅 버튼을 두고 싶으면 알리페이 열에서 채팅을 켭니다.
- 기존에 메신저가 켜진 콘텐츠는 마이그레이션(SYS-CH-03)으로 처리합니다.

#### 신규 콘텐츠의 초기값

- 신규 스토어의 알리페이 열은 상담접수로 시작합니다.
  - 예약은 예약 설정을 켠 뒤 운영자가 켭니다.
- 신규 상품은 스토어 설정 적용이 기본 설정으로 시작해 스토어 값으로 보입니다.
  - 개별 설정으로 바꾸면 그 시점의 스토어 값을 두 열 모두 복사합니다.
- 상품·스토어는 웹 열에서 켠 것을 알리페이 열로 복사하지 않습니다.
  - 배너의 하단 버튼만 아래 규칙으로 복사합니다.
- 배너의 하단 버튼은 웹 표시여부를 복사해 시작하되, 버튼 링크 종류가 외부링크면 알리페이 열은 비활성화로 시작합니다.

#### 외부 요소

- 버튼 구성 밖에서 외부로 연결되는 요소가 있습니다.
  - 버튼으로 넣는 대상이 아니며 알리페이 채널에서 렌더할 때 일괄로 걸러냅니다.
  - 상품의 인스타그램 임베디드 노출 여부가 ON이어도 알리페이에서는 숨깁니다.

| 요소 | 알리페이 | 비고 |
|---|---|---|
| 메신저 카드 | 영역째 숨김 | 왓츠앱·위챗·라인 등 |
| SNS 임베드 | 영역째 숨김 | 인스타그램 게시물 등. 스토어와 상품 둘 다 |
| SNS 채널 아이콘 | 영역째 숨김 | 인스타그램·틱톡 |
| 본문 임베드·외부 링크 | 렌더 때 변환 | 매거진·스토어 칼럼 본문. 외부 링크는 글자로 바꾸고 허용 목록에 없는 외부 임베드는 영역째 숨깁니다. 저장된 본문은 그대로입니다 |
| 전화·메일 링크 | 글자로 바꿈 | 스토어 대표번호·사업자 이메일 같은 전화·메일 링크(tel·mailto). 번호와 주소는 글자로 그대로 보입니다 |

- 메신저 카드, SNS 임베드, SNS 채널 아이콘은 허용 목록과 무관하게 알리페이 채널에서 늘 숨깁니다.
- 허용 목록은 매거진·스토어 칼럼 본문 안의 임베드에만 적용합니다.
  - 본문 안의 iframe·script·외부 임베드는 허용 목록에 없으면 전부 숨깁니다.
  - 허용 목록은 어드민 화면 없이 서버 구성 값으로 두고 운영자가 확정해 개발에 요청하며, 확정 전에는 비어 있어 본문 임베드는 모두 숨깁니다.
  - 이 허용 목록은 알리페이 채널에서 보여줄 때만 씁니다.
  - 스토어 칼럼 에디터의 입력 차단에는 허용 목록이 없습니다(5장).
- 구글 리뷰 위젯은 이 규칙의 대상이 아닙니다.
  - 이번 범위에서 다루지 않고 현행 그대로 둡니다.
- 영역 제목까지 함께 숨기고, 숨긴 자리는 여백으로 두지 않고 레이아웃을 접습니다.

#### 예약 폼과 상담접수 폼의 메신저 연락처 입력

- 예약 폼에서 메신저 아이디를 받을 때 제공하는 앱 열기 기능은 알리페이에서 동작하지 않습니다.
  - 앱 열기 버튼을 숨기고 아이디는 고객이 직접 입력합니다.
  - 왓츠앱, 라인, 위챗, 카카오 네 메신저 모두 같습니다.
- 상담접수 폼에 메신저 아이디 입력의 앱 열기 버튼이 있으면 예약 폼과 같이 숨깁니다.
- 메신저 도메인은 알리페이 화이트리스트에 신청하지 않습니다.

### 7. BO(어드민)와 HOST 영향

BO-CH-01 ~ BO-CH-10 / BO-CH-13 / HOST-CH-01 / HOST-CH-02. 이 화면들의 화면 문구는 이 장 한 곳에 둡니다.

- 알리페이 회원 목록(BO-CH-11)과 알리페이 회원 화면의 문구는 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」 4장에 있습니다. 언어 선택 목록 문구는 9장에 있습니다.

#### BO

- 콘텐츠 등록과 수정 화면에 노출 채널 라디오(전체 / 웹 / 알리페이 앱)를 추가합니다.
  - 상품, 스토어, 배너, 기획전, 매거진 각각. 스토어 칼럼에는 라디오를 두지 않습니다.
- 버튼 설정 영역의 항목마다 알리페이 ON/OFF를 하나 더 둡니다.
  - 상품과 스토어에 적용합니다.
  - 규칙은 6장에 있습니다.
  - 셋째 자리를 만들려 하면 모달이 아니라 토스트 안내로 막고 누른 라디오는 누르기 직전 값으로 돌아갑니다.
  - 노출 채널, 대상 외 언어, 지원언어 때문에 잠긴 열은 상한 검사에서 빼고 표 아래 자리 수에 0개로 적으며 버튼 이름을 붙이지 않습니다.
    - 그 열의 버튼은 어디에도 나가지 않기 때문입니다.
    - 잠금이 풀린 열은 꺼진 상태로 시작합니다. 0개에서 다시 셉니다.
    - 예약 설정 때문에 잠긴 예약 줄도 상한 검사와 표 아래 자리 수에서 뺍니다. 예약 설정을 끄면 값은 지우지 않고 흐리게 잠기고 고객 화면에 나가지 않습니다. 다시 켜면 두 예약 버튼 모두(웹·알리페이 열 모두) 꺼진 상태로 시작하고 운영자가 다시 켭니다. 다른 버튼 값은 그대로입니다.
  - 예약설정에서 예약을 다시 사용으로 바꾸는 것은 막지 않습니다.
    - 스토어와 상품의 예약 버튼이 꺼진 상태로 시작하므로 자리가 넘치지 않습니다.
  - 스토어 설정 적용 라디오 아래 안내 한 줄은 개별 설정·기본 설정 어느 쪽이든 보입니다.
    - 기본 설정일 때는 버튼 표 아래에 잠금 안내를 더 둡니다.
- 화면 안내는 운영자가 바로 읽고 판단할 수 있는 말로 씁니다.
  - 열, 판정, 렌더, 배치, 레코드 같은 내부 용어를 화면 문구에 쓰지 않습니다.
  - 사유는 목록 칼럼 이름으로만 씁니다.
  - 채널은 웹과 알리페이 앱으로 쓰고, 결과는 “노출됩니다”, “보이지 않습니다”처럼 고객에게 보이는지로 씁니다.
- 화면 안내는 한 사실에 한 줄만 둡니다.
  - 잠긴 컨트롤이 있으면 그 컨트롤 바로 아래 한 줄에 사유와 결과를 함께 적고, 같은 사실을 말하는 안내 박스는 따로 두지 않습니다.
- 문구 속 {웹 / 알리페이 앱}은 해당 채널 이름으로 바꿔 씁니다.
  - 두 채널 모두에 해당하면 “웹과 알리페이 앱”으로 씁니다.
  - 목록 사유도 두 채널 모두면 “연결 대상이 웹과 알리페이 앱에 없음” 한 줄입니다.
  - 배너 연결 대상 저장 차단 안내는 두 채널 모두면 “웹과 알리페이 앱”으로 한 문장입니다.
  - 기획전 담은 항목 안내 박스, 저장 확인 창은 아래 각 문구에 적은 대로 채널마다 따로 씁니다.
- 문구 속 {알리페이 앱 / 웹}은 반대 채널입니다.
  - 같은 문구의 {웹 / 알리페이 앱} 자리에 웹이 들어가면 알리페이 앱을, 알리페이 앱이 들어가면 웹을 씁니다.
  - 예: 웹으로 저장하는 확인 창은 제목 “웹으로 저장할까요?”, 본문 첫 줄 “알리페이 앱 미노출 대상”입니다.
- 문구 속 {버튼 이름}이 여럿이면 버튼 설정 표의 행 순서대로 “ / ”로 잇습니다.

#### 상시 안내

- 스토어 노출 채널 라디오 아래: “지원언어와 무관하게 이 설정 하나가 모든 언어에 적용됩니다. 웹이나 알리페이 앱으로 정하면 이 스토어의 상품과 칼럼도 그 채널에만 노출됩니다.”
- 문구 속 {버튼 이름}은 상담접수 / 채팅 / 문의하기 / 외부링크 / 메신저 / 예약 중에서 쓰고, 순서는 버튼 설정 표의 행 순서입니다.
  - 아래 자리 수·알림 창 모두 같습니다.
- 버튼 표 아래 자리 수: “웹 N개 ({버튼 이름} / {버튼 이름}), 알리페이 앱 M개 ({버튼 이름})입니다. 각각 2개까지 켤 수 있습니다.” 버튼 이름은 버튼 설정 표의 행 순서로 “ / ”로 잇습니다.
  - 0개인 채널은 괄호 없이 “0개”로 적습니다.
  - 잠긴 열은 켠 버튼이 있어도 0개로 적습니다.
  - 예: “웹 2개 (상담접수 / 예약), 알리페이 앱 0개입니다. 각각 2개까지 켤 수 있습니다.”
- 버튼 표의 행 오른쪽 안내
  - 통합 표시: “기존 문의하기 버튼입니다. 다른 항목처럼 독립된 버튼이라 켜면 1개로 셉니다.”
  - 예약 사용이 꺼진 예약 행(스토어와 상품): “예약설정에서 예약을 사용하면 켤 수 있습니다.”
  - 외부링크·메신저 행: “알리페이 앱 미지원 항목입니다.”
  - 메신저 언어별 입력 영역: “메신저 설정을 켜면 언어별로 1개씩 등록할 수 있습니다.”
- 예약설정 섹션의 예약 사용 항목 아래 한 줄
  - 예약 사용일 때: “예약을 사용해야 버튼 및 메신저 설정에서 예약 버튼을 켤 수 있습니다.”
  - 미사용으로 바꾸면 그 자리에: “예약 미사용 상태입니다. 예약 버튼은 웹·알리페이 앱 모두 꺼집니다. 다시 사용하면 예약 버튼은 꺼진 상태로 시작합니다.”
  - 이때 스토어 예약 버튼과 상품의 예약 버튼은 모두 값을 그대로 둔 채 잠기고, 고객 화면에는 나가지 않습니다.
    - 잠긴 칸은 저장된 값을 흐리게 보여줍니다.
  - 예약 설정을 끄면 값은 지우지 않고 흐리게 잠기고 고객 화면에 나가지 않습니다. 다시 켜면 두 예약 버튼 모두(웹·알리페이 열 모두) 꺼진 상태로 시작하고 운영자가 다시 켭니다. 다른 버튼 값은 그대로입니다.
  - 안내의 “꺼진 상태로 시작”은 스토어 예약 버튼과 상품 예약 버튼을 말합니다.
- 스토어 설정 적용 라디오 아래(항상): “기본 설정은 스토어 버튼 구성을 그대로 적용합니다.”
- 알리페이 앱 전용 스토어의 상품 언어 셀렉트 아래: “이 스토어는 알리페이 앱 전용이라 중국어(간체), 중국어(번체), 영어만 등록할 수 있습니다.”
- 배너 직접입력 칸 옆 표시
  - 패턴에 맞고 대상이 있으면 “노출 채널 {대상 유효값}, {종류} {이름}”으로 씁니다.
  - 배너 채널 중 대상이 빠진 채널이 있으면 “. {웹 / 알리페이 앱}에 노출되지 않습니다.”를 붙입니다.
    - 두 채널 모두면 “웹과 알리페이 앱”으로 씁니다.
  - 대상이 기존 노출 조건(상품은 승인·활성·히든, 스토어는 공개여부, 기획전은 활성화·노출 기간 등. SYS-CH-02 ②) 때문에 두 채널 모두에서 빠졌으면 “노출되지 않음, {종류} {이름}”만 쓰고 뒤의 채널 문장은 붙이지 않습니다.
  - 우리 경로 패턴에 맞지 않는 주소는 “직접입력 (목록 페이지)”로 씁니다.
  - 비어 있으면 “직접입력 (주소 없음)”으로 씁니다.
  - 주소가 가리키는 대상을 찾을 수 없으면 “입력한 주소의 대상을 찾을 수 없습니다. 주소를 확인해 주세요.”로 씁니다.
  - 하단 버튼의 직접입력 대상을 찾을 수 없으면 저장은 막지 않고 “{웹 / 알리페이 앱}에서는 하단 버튼이 보이지 않습니다.” 안내를 둡니다.
    - 두 채널이면 “웹과 알리페이 앱”으로 씁니다.
- 저장이 끝나면 “저장했습니다”와 “목록과 고객 화면에 1분 안에 반영됩니다.”를 보입니다.

#### 잠긴 컨트롤 아래 한 줄로 알리는 경우

- 스토어 종속으로 고정된 상품의 노출 채널 라디오: “스토어의 노출 채널이 {웹 / 알리페이 앱}이라 이 상품도 같은 채널에만 노출됩니다. 스토어 > 정보관리의 기본정보에서 바꿀 수 있습니다.”
- 채널 때문에 잠긴 버튼 열
  - 노출 채널이 웹인 콘텐츠의 알리페이 열과, 지원언어에 대상 언어가 없는 스토어의 알리페이 열: “웹에만 노출되는 상태에서는 알리페이 앱 버튼을 수정할 수 없습니다. 다시 열리면 꺼진 상태로 시작합니다.”
  - 알리페이 앱인 콘텐츠의 웹 열: “알리페이 앱에만 노출되는 상태에서는 웹 버튼을 수정할 수 없습니다. 다시 열리면 꺼진 상태로 시작합니다.”
  - 배너 하단 버튼 열은 잠금이 풀리면 저장된 값으로 돌아오므로 원래 문구를 씁니다: “웹에만 노출되는 상태에서는 알리페이 앱 버튼을 수정할 수 없습니다. 설정값은 유지됩니다.” / “알리페이 앱에만 노출되는 상태에서는 웹 버튼을 수정할 수 없습니다. 설정값은 유지됩니다.”
- 배너 링크종류가 외부링크: “외부링크 배너는 웹에만 노출됩니다. 이 설정은 수정할 수 없습니다.”
- 하단 버튼 링크 종류가 외부링크: “하단 버튼이 외부링크입니다. 알리페이 앱에서는 이 버튼이 보이지 않습니다.”
- 기본 설정으로 잠긴 상품의 버튼 표: “기본 설정 적용 중입니다. 개별 설정을 선택하면 수정할 수 있습니다.”
  - 예약 줄도 함께 잠깁니다(6장).
- 대상 외 언어 건은 잠금만 있고 문구가 없습니다.
  - 지원언어에 대상 언어가 없는 스토어 자신의 노출 채널 라디오도 문구가 없습니다.

#### 안내 박스로 알리는 경우

- 스토어의 노출 채널을 웹이나 알리페이 앱으로 고르면 라디오 아래 “웹으로 지정하면 상품 N건과 칼럼 M건이 알리페이 앱에 노출되지 않습니다.”
  - 둘 중 하나만 있으면 그 항목만 씁니다.
  - 건수는 그 채널에서 보이다가 안 보이게 되는 건만 셉니다.
  - 알리페이 앱이면 웹과 알리페이 앱을 바꿔 씁니다.
  - 저장값과 다른 값을 고른 동안만 보입니다.

FO-CH-01 ~ FO-CH-06

  - 숨긴 콘텐츠는 화면에서 가리기만 하는 것이 아니라 어떤 경로로도 볼 수 없어야 합니다.

  - 스토어 칼럼: 목록 / 상세 / 스토어 페이지 섹션 / 홈 섹션
  - 사이트맵: 웹 채널 판정을 통과한 건만 넣습니다.
    - 기존 생성 주기대로 갱신하고 60초 반영 기준의 대상은 아닙니다.
    - 알리페이 도메인은 지금처럼 색인하지 않습니다.
- 버튼 숨김도 같은 채널 판별 결과를 따릅니다.
  - 화면마다 판별이 달라서는 안 됩니다.
- 판정은 콘텐츠 건 단위입니다.
  - 간체 요청에는 간체 건들이 조회되므로 그 건들의 설정으로 판정됩니다.
- 직접 진입 폴백: 어느 채널에서든 그 채널에 노출되지 않는 콘텐츠 주소로 진입하면 기존 404 페이지를 그대로 띄웁니다.
  - 404 상태 코드로 응답합니다.
  - 이 404는 판정 조건 ①③④ 때문에 노출되지 않는 주소에 쓰고, ②(비공개 스토어 등) 때문이면 지금 정책(비공개 스토어는 200과 noindex)을 그대로 따릅니다.
  - 새 화면을 만들지 않습니다.
  - 인플루언서 기획전은 그 채널에 노출되는 담은 상품이 0건이면 404입니다.
  - 채널 분기의 목적은 이런 진입 자체가 생기지 않게 하는 것이고, 404는 뚫린 경우의 마지막 처리입니다.
- 스토어가 그 채널에 노출되지 않으면(스토어의 판정 조건 ①② 중 하나라도 걸리면) 그 스토어의 상품·칼럼도 그 채널에 없습니다.
  - 상품이 전부 빠져도 스토어는 자동으로 숨기지 않습니다.
- 상세 페이지는 열 때마다 판정을 다시 합니다.
  - 목록에 남아 있던 항목이라도 상세에서 막힙니다.
- 웹에서 보인 목록이 알리페이 앱에 그대로 나오면 안 되고, 알리페이 앱에서 보인 목록이 웹에 그대로 나와도 안 됩니다.
  - 같은 채널이라도 언어가 다르면 보이는 목록이 다릅니다.
- 고객 화면과 어드민 목록의 사유는 같은 판정 결과를 보여야 합니다.
- 리뷰는 채널을 나누지 않습니다.
  - 웹 회원이 쓴 리뷰와 알리페이 회원이 쓴 리뷰가 두 채널 모두에서 보이고, 리뷰 수와 평점도 지금처럼 하나로 셉니다.
  - 작성자 표시명 규칙은 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」 4장에 있습니다.
- 결과가 바뀌어야 하는 경우
  - (1) 콘텐츠의 노출 채널 값·언어, 스토어 칼럼의 보여줄 언어, 배너의 링크종류·연결 대상, 기획전의 담은 항목 변경
  - (2) 스토어의 노출 채널·지원언어·언어별 노출·공개여부 변경 → 그 스토어의 상품·칼럼과 그 스토어를 가리키는 배너
  - (3) 상품·스토어 판정 변경 → 그것을 담은 기획전·인플루언서 기획전 → 그것을 가리키는 배너
  - (4) 기획전의 유형 레코드 변경 → 옛 유형과 새 유형을 가리키는 배너 모두
  - (5) 유형 레코드의 생성·삭제·언어 변경 → 그 유형을 가리키는 배너
  - (6) 대상의 활성화 여부·노출 기간·공개여부·삭제 변경 → 그것을 가리키는 배너와 담은 기획전
  - (7) 날짜 경과
  - 버튼 구성 변경은 노출 결과를 바꾸지 않습니다.
  - 저장하면 목록과 고객 화면에 1분 안에 반영됩니다.
    - 합격 기준은 저장 후 60초 안입니다.
    - 참조 대상이 바뀌어 결과가 달라지는 경우도 같습니다.
    - 구현 방식은 개발이 정합니다.

판정 적용에서 한 노출면이라도 누락되면 그 노출면에 숨길 콘텐츠가 나옵니다.

  - 리뷰 관리는 리뷰 카드의 “상품 리뷰”·“스토어 리뷰” 태그 바로 뒤에 유입 채널 배지(“웹”, “알리페이 중국”, “알리페이 홍콩” 중 하나)를 더하고, 필터 줄의 리뷰 타입 필터 뒤에 유입 채널 필터를 더합니다.
    - 위쪽 요약 네 칸(전체 리뷰, 상품 리뷰, 스토어 리뷰, 평균 평점)도 이 필터를 따릅니다.
    - 값은 어드민과 같이 작성 회원의 채널(웹 회원은 웹, 알리페이 회원은 가입한 월렛(알리페이 중국/알리페이 홍콩))입니다.
  - 대시보드의 통계 영역(스토어 방문, 상품 방문, 메신저 문의, 채팅 문의, 예약 확정, 방문 완료 여섯 칸)은 합계만 보여주고 채널별 숫자는 보이지 않습니다.
    - 유입 채널 필터도 두지 않습니다.
    - 대시보드 칸 규칙은 상품 예약 기능 그대로이고, 이 문서는 채널별 숫자를 두지 않는 것만 정합니다.
    - 메신저 문의 상세 표에도 칼럼을 더하지 않습니다.
  - 대시보드 예약 현황 카드에는 오른쪽 위 “예약” 배지 바로 왼쪽에 유입 채널 배지(“웹”, “알리페이 중국”, “알리페이 홍콩” 중 하나)를 더합니다.
    - 배지는 중립 회색 윤곽선이고, 마우스를 올리면 “유입 채널”이라고 알려 줍니다.
    - 예약 현황 오른쪽 처리 필요 패널도 같은 카드를 쓰므로 같습니다.
    - 처리 필요 패널은 유입 채널 필터를 따르지 않고 늘 전부 보입니다.
  - 목록 화면에는 유입 채널별 건수 칸을 따로 두지 않습니다.
    - 필터를 고르면 목록 제목의 건수가 그 결과로 바뀝니다.
    - 처리 필요 패널은 바꾸지 않습니다.
    - 초기화 버튼이 있는 화면은 초기화 때 유입 채널 필터도 전체로 돌아갑니다.
  - 알리페이 식별자는 호스트에 보이지 않습니다.

### 11. 설정 값 정의

SYS-CH-01

콘텐츠마다 노출 채널 값을 하나 가집니다.

- 등록·수정 화면의 라디오와 목록 칼럼은 이 값을 보여줍니다.
- 판정 결과는 운영자가 편집하는 값이 아닙니다.

#### 콘텐츠

- 저장값의 디폴트는 전체입니다.
  - 새로 등록하는 콘텐츠는 상품을 포함해 전부 전체로 시작합니다.
  - 스토어 칼럼은 저장값이 없습니다.
  - 대상 언어가 아닌 건도 저장값은 디폴트로 두고 유효값만 웹입니다.
- 설정 단위는 5장의 표를 따릅니다.
  - 콘텐츠 건마다 하나이고 언어를 따로 나누지 않습니다.
  - 스토어 칼럼은 값을 따로 두지 않고 소속 스토어의 값을 따릅니다.
- 유효값은 저장값에 스토어 종속, 대상 외 언어, 지원언어에 대상 언어가 없는 스토어의 웹 고정, 외부링크 배너의 웹 고정을 반영한 값입니다.
  - 화면과 목록과 판정이 모두 유효값을 씁니다.
  - 저장값은 건드리지 않습니다.
- 공개여부, 활성화, 히든, 게시 상태 같은 기존 노출 조건은 별개 값으로 그대로입니다.

#### 버튼

- 버튼 종류: 상담접수, 채팅, 상담접수·채팅 통합 표시, 외부링크, 메신저, 예약. 상품과 스토어에 씁니다.
  - 채팅은 이번에 신설하고 웹 열·알리페이 열 모두 OFF로 시작합니다.
  - 예약은 스토어와 상품에 있고, 예약 설정이 켜져 있을 때 켤 수 있습니다.
  - 배너의 하단 버튼은 랜딩페이지 배너에만 하나 있습니다.
    - 버튼 링크 종류에 내부링크를 추가하고 연결 대상을 고르게 합니다.
    - 종류는 직접입력, 병원, 기획전, 인플루언서입니다.
- 상품과 스토어는 버튼마다, 배너는 하단 버튼 하나에 웹 값과 알리페이 값을 각각 가집니다.
  - 언어를 나누지 않습니다.
  - 메신저 종류·URL·QR만 지금처럼 언어별입니다.
  - 상품의 스토어 설정 적용(개별 설정 / 기본 설정)은 지금 구조 그대로입니다.
    - 기본 설정이면 웹 값과 알리페이 값 모두 스토어 값을 따릅니다.
  - 채널마다 버튼 자리 상한은 두 개입니다.
    - 모든 버튼 종류가 각각 한 자리입니다.
- 버튼 값은 노출에 관여하지 않습니다.

#### 외부 요소와 채널 기록

- 외부 요소는 버튼이 아닙니다.
  - 운영자가 켜고 끄는 설정을 두지 않습니다.
  - 알리페이 채널에서는 일괄로 걸러냅니다.
- 노출·클릭·조회수·버튼 클릭수·채팅·상담·예약 기록에 어느 채널에서 들어왔는지 값을 남깁니다.
  - 값은 채널 기록값: 웹 / 알리페이 중국 / 알리페이 홍콩 셋입니다.
    - 매장·운영자가 대신 등록한 수기 예약은 고객이 들어온 채널이 없어 유입 채널 값을 두지 않고 “-”로 보입니다. 유입 채널 필터에서 채널 하나를 고르면 빠지고 “전체”에서만 보입니다. 수기 예약은 상품 예약 기능의 예약 목록 필터 “등록 주체”와 예약 상세 칸 “등록 방식”(둘 다 고객 / 매장)으로 구분합니다.
    - 유입 채널 기록을 시작하기 전(1단계 배포 전)에 쌓인 기록도 값이 없어 “-”로 보입니다.
  - 알리페이 중국과 알리페이 홍콩은 1단계부터 첫 진입 주소로 정합니다.
    - /zh-TW로 들어오면 알리페이 홍콩, 그 밖의 주소로 들어오면 알리페이 중국입니다.
    - 이용하는 동안 그대로 유지하고, 언어를 바꿔도 바뀌지 않습니다.
    - 회원 연동 배포 뒤에는 「알리페이 회원정보 연동 및 알리페이 홍콩 연동 PRD v1.0」 4장의 월렛 값을 먼저 씁니다.
    - 비회원의 언어 설정은 브라우저(쿠키)에 저장합니다.
  - 채팅의 값은 채팅방이 처음 생길 때의 값이고, 이후 바뀌지 않습니다.
  - 통계용이고 과금 기준은 바꾸지 않습니다.
  - 화면에서도 이 셋을 합치지 않고 그대로 유입 채널로 보여줍니다(10장).
  - 새 통계 화면은 이번 범위가 아닙니다.
  - 예약·채팅·상담 목록과 스토어 문의 통계, 예약자 설문조사, 호스트 대시보드에서는 이 값을 유입 채널로 보여줍니다.
  - 리뷰는 건에 이 값이 없어 작성 회원의 채널로 보여줍니다(10장).

### 12. 권한

  - 상품을 수정할 수 있는 운영자는 그 상품의 노출 채널과 버튼 구성도 바꿀 수 있습니다.
- 스토어를 알리페이 앱 전용으로 바꾸는 것도 스토어를 수정할 수 있는 운영자면 누구나 할 수 있습니다.

  - 버튼은 어드민에서만 다룹니다.
  - 스토어 칼럼은 노출 채널 설정이 없고 소속 스토어의 값을 따릅니다.

### 13. 배포 준비와 마이그레이션

SYS-CH-03

#### 개발 외 선행 작업

내부 전용. 담당은 역할로, 기한은 배포 단계로 적습니다.

| 작업 | 담당 | 기한 |
|---|---|---|
| Flow 위키에 개발 전달 본문 게시 | 기획 | 개발 착수 전 |
| 집계 1~5를 받아 정리 작업 공수 확정. 건수는 확정 전 | 운영 | 집계를 받은 직후 |
| 집계 1·2·4 정리 | 운영 | 1단계 배포 전 |
| 외부 링크·임베드가 남은 옛 스토어 칼럼 정리 | 운영 | 기한 없음. 정리 전에도 알리페이 채널에서는 변환해 보여줍니다 |

#### 마이그레이션

- 기존 콘텐츠의 노출 채널 저장값은 전부 전체로 일괄 설정합니다.
  - 상품, 스토어, 배너, 기획전, 매거진 모두입니다.
  - 스토어 칼럼은 저장값이 없어 대상이 아닙니다.
  - 집계 2 기획전은 배포 전에 정리를 마치므로, 배포 직후 웹에서 빠지는 건은 집계 3 중 배너 자체의 연결 대상이 걸린 배너뿐입니다.
- 배치는 다시 실행해도 결과가 같아야 합니다.
  - 운영자가 알리페이 열을 직접 바꿔 저장한 건은 알리페이 열의 모든 항목이 OFF여도 그대로 둡니다.
  - 알리페이 열을 건드리지 않고 다른 항목만 저장한 건은 2단계 규칙으로 채웁니다.
  - 이를 가르기 위해 운영자가 알리페이 열을 직접 바꿔 저장했는지를 건마다 기록합니다. 값이 없는 것과 OFF로 저장한 것을 이 기록으로 구분합니다.
    - 운영자가 알리페이 열 칸을 직접 눌러 값이 달라진 채로 저장했을 때만 기록합니다. 개별 설정으로 바꿀 때 복사된 값과 예약 설정을 다시 켜서 꺼진 값은 기록하지 않습니다.
  - 배치를 다시 돌려도 운영자가 저장한 알리페이 열을 덮지 않습니다.
- 배치는 실행 전 바꿀 값을 보관하고(되돌리기에 씁니다), 실행 전에 배치 대상 건수(알리페이 열을 채울 스토어 수와 개별 설정 상품 수)를 세어 두고, 실행 뒤 바뀐 건수와 대조해 운영에 공유합니다.
  - 중간에 실패하면 그 배치를 실행 전 상태로 되돌린 뒤 다시 실행합니다.
- 기존 버튼 ON/OFF는 웹 열 값으로 그대로 둡니다.
  - 웹 열 값을 알리페이 열로 옮기지 않습니다.
- 선행 집계: 배치 전에 아래 다섯 목록을 개발이 뽑아 운영에 공유합니다.
  - 산출물은 건별 ID·이름·언어·해당 조건을 담은 스프레드시트 한 장입니다.
  - 어드민 필터가 배포 후에 생기므로 배포 전에는 개발이 직접 뽑아 줍니다.
  - 건수는 확정 전입니다.
  - 집계 1. 웹 열 버튼 자리가 3개 이상인 상품·스토어. 켜 둔 항목 수가 곧 자리 수입니다.
    - 지금 웹은 상담접수와 문의하기를 한 자리로 세지만 새 규칙에서는 두 자리라, 이 둘에 예약·메신저·외부링크가 더 켜진 건이 여기에 걸립니다.
    - 배치가 값을 건드리지 않고 목록으로 넘깁니다.
    - 운영자가 1단계 배포 전에 두 개로 줄여 정리를 마칩니다.
    - 정리 완료가 1단계 배포 조건입니다.
  - 집계 2. 활성 상태이면서 구성 항목이 0건인 기획전과 웹에서 노출 가능 항목이 0건인 기획전(정리 대상). 알리페이 앱에서만 노출 가능 항목이 0건인 기획전은 참고용으로 따로 뽑고 정리를 기다리지 않습니다.
    - 구성 항목을 필수로 바꾸기 때문에, 0건인 기획전은 노출 채널만 바꾸려 해도 저장이 막힙니다.
    - 운영자가 1단계 배포 전에 항목을 담거나 기획전을 비활성으로 바꿔 정리를 마칩니다.
    - 비활성으로 저장할 때는 0건 검사에서 빠지므로 막히지 않습니다.
    - 정리가 끝난 상태가 배포 전제입니다.
  - 집계 3. 최초 판정에서 연결 대상이 그 채널에 노출되지 않는 배너. 대상이 비활성이거나 노출 기간이 지났거나 언어가 다르거나 삭제·비공개이거나 배너 언어의 언어별 노출이 꺼진 스토어이거나 노출 상품이 없는 인플루언서 기획전인 경우입니다.
    - 배포와 동시에 그 채널에서 노출되지 않게 바뀝니다.
    - 하단 버튼의 대상이면 배너는 그대로 두고 버튼만 숨깁니다.
    - 배너 자체가 이미 기간이 지났으면 세지 않습니다.
    - 정리를 기다리지 않고 배포합니다.
  - 집계 4. 같은 유형 값과 언어로 둘 이상인 기획전 유형 레코드. 운영자가 1단계 배포 전에 하나로 합치고, 붙어 있던 기획전과 그것을 가리키는 배너를 남는 레코드로 옮겨 정리를 마칩니다.
  - 집계 5. 지원언어에 중국어(간체)·중국어(번체)·영어가 하나도 없는 스토어. 배포와 동시에 그 스토어와 상품·칼럼이 알리페이 앱에서 빠집니다.
    - 정리를 기다리지 않고 배포합니다.
- 알리페이 열을 다음 규칙으로 채웁니다.
  - 스토어: 예약 설정이 사용이면 예약과 상담접수를 켭니다.
    - 미사용이면 상담접수를 켭니다.
    - 알리페이 앱은 예약 중심 채널이고, 상담접수는 우리 자체 기능이라 어디서든 동작합니다.
  - 개별 설정 상품: 상담접수를 켭니다.
  - 기본 설정 상품: 배치 대상이 아닙니다.

#### 버튼 구성 (6장)

- 마이그레이션 배치는 개발과 운영 책임자만 실행할 수 있습니다.

#### 마이그레이션과 배포 (13장)

- 1단계 배포 뒤 운영자가 알리페이 열을 직접 바꿔 저장한 건에는 그 기록이 남고, 2단계 배치는 그 건의 알리페이 열을 바꾸지 않습니다.
- 배치가 끝나면 바뀐 건수가 실행 전에 세어 둔 배치 대상 건수와 맞는지 대조한 결과가 운영에 공유됩니다. 중간에 실패하면 실행 전 상태로 되돌아간 뒤 다시 실행됩니다.
- 기존 콘텐츠 전체의 노출 채널이 전체입니다.
  - 배포 직후 웹 목록과 검색에 집계 3 중 배너 자체의 연결 대상이 걸린 배너를 뺀 전 콘텐츠가 그대로 나옵니다.
- 기존 버튼 ON/OFF가 웹 열 값으로 그대로 남아 있고 알리페이 열로 옮겨지지 않았습니다.
- 예약 설정을 쓰는 스토어는 알리페이 열에 예약과 상담접수가, 쓰지 않는 스토어는 상담접수가 켜져 있습니다.
  - 개별 설정 상품은 상담접수가 켜져 있습니다.
  - 개별 설정 상품은 예약 줄의 알리페이 열이 꺼져 있고(1단계 뒤 운영자가 알리페이 열을 직접 바꿔 저장한 건은 그 값 그대로), 웹 열은 배치 전 값 그대로입니다.
- 메신저가 켜져 있던 상품·스토어의 알리페이 열에 채팅이 켜져 있지 않습니다.
- 외부링크 배너는 알리페이에서 숨겨지고 웹에는 그대로 보입니다.
  - 외부링크 버튼만 있던 랜딩페이지 배너는 알리페이에 노출되되 버튼이 없습니다.
- 배치 전 선행 집계 목록 다섯 개(집계 1~5)가 뽑혀 있고, 집계 3 배너와 집계 5 스토어를 뺀 나머지는 운영자가 1단계 배포 전에 정리를 마친 상태입니다.
- 공통 필터 스위치를 꺼도 외부링크 배너와 외부링크·메신저 버튼은 알리페이에 나타나지 않습니다.
- 4단계(고객 화면 알리페이 열 렌더와 자동 치환 제거)는 2단계(버튼 열 마이그레이션) 뒤에 배포됩니다.

#### 웹 회귀

- 웹 목록·검색·상세에 기존 콘텐츠가 그대로 나옵니다(집계 3 중 배너 자체의 연결 대상이 걸린 배너 제외).
- 웹 하단 버튼이 항목마다 한 자리로 세어지고 상한 둘이 지켜집니다.
- 웹에서 기획전 구성 항목 0건 저장이 막힙니다.
  - 비활성으로 저장할 때는 막히지 않습니다.
- 웹 배너의 연결 대상 선택지가 배너 채널에 맞는 것으로 제한됩니다.
- 웹에서도 스토어 칼럼 에디터에 외부 링크·임베드를 넣을 수 없습니다.
  - 매거진은 넣을 수 있습니다.
- 랜딩페이지 배너의 하단 버튼은 대상이 웹에 노출되지 않으면 웹에서 숨겨집니다.
- 웹의 홈 큐레이션 섹션과 매거진 본문 카드에서 웹에 노출되지 않는 상품·스토어가 빠집니다.
- 웹에서 알리페이 앱 전용 주소를 열면 404가 뜹니다.
- 사이트맵에 웹 판정을 통과하지 못한 건이 없습니다.

#### 공통

  - 웹 채널도 이번 배포로 동작이 바뀝니다.
